# ADR-0005：Agent 启动链不依赖独立 Context 仓库

状态：`Approved`

日期：2026-08-26

## 背景

项目最初使用产品仓库与私有 Agent Context 仓库并列的工作区结构。产品事实虽然始终以产品仓库
为准，但每次启动仍需读取共享规则和当前 Agent 的私有恢复文件。随着产品进入 v0.2，这条链已经
出现维护漂移：私有恢复摘要可能落后于产品仓库状态，并增加多工具、多设备和权限隔离的维护成本。

项目仍需要 Codex、Cursor 与 Claude 共享协作规则、独立评审协议和用户批准边界，但这些内容是
项目级事实，应当与代码和文档一起版本化，而不是依赖第二个 Context 仓库。

## 决策

- 产品 Git 仓库同时承载产品事实与项目级协作规则，是唯一权威事实来源。
- `AGENTS.md` 与 `CLAUDE.md` 各自作为薄原生入口，直接链接同一个文档索引、当前状态和协作
  规则；入口不再跳转到任何独立 Context 仓库或 Agent 私有目录。
- Agent 私有的短期状态优先使用工具宿主的原生 session/memory，不在产品仓库建立按 Agent
  划分的 Context 目录，也不作为正式交接依赖。
- 旧 `JDAgentAgentContext` 仓库暂时原样保留，但退出默认启动、恢复和协作链。只有项目所有者
  明确要求审计、迁移或归档时，Agent 才能读取或修改它。
- 按项目所有者的本地使用习惯，外层 `JDAgent/` 继续作为启动根。这是相对于直接从产品 Git 根
  启动的明确例外：外层只保留到产品原生入口的薄路由，不保存或复制产品事实。
- 外层 `tmp/`、`.vscode/` 和已批准的开发期 Key 路径保持现状；本决策不修改产品运行时、配置
  优先级或秘密合同。

## 备选方案

### 继续维护双仓启动链

可以保留每个 Agent 的可迁移精选记忆，但需要持续同步共享规则、权限边界和恢复摘要，并会让
过时私有状态影响新会话。项目当前没有足够收益证明这项长期维护成本。

### 把全部私有 Context 合并进产品仓库

读取链最短，但会把私有记忆、草稿和工具方法混入产品事实，增加泄漏、确认偏误和事实重复风险，
因此只迁移经过确认的项目级协作规则。

### 把产品仓库搬到外层工作区根

最符合单仓直接启动拓扑，但需要移动现有产品文件和 Git 边界，并影响本地工具路径。项目所有者
明确选择保留当前外层启动根，因此本次不执行。

## 后果

- 从外层启动和从产品 Git 根直接启动都会到达同一文档索引和权威事实。
- 私有恢复摘要不再自动影响项目判断；需要长期保留的结论必须进入产品仓库的对应事实文档。
- 项目级协作和评审协议由 `docs/development/agent-collaboration.md` 统一维护。
- 旧 Context 仓库及其 remote、branch 和历史仍存在，但不再是产品依赖，也不随本决策自动归档
  或删除。
- 外层路由文件不在产品 Git 历史内，需要在本地保持薄路由；产品仓库自身仍可独立恢复和协作。

## 复审条件

- 项目所有者决定归档、删除或导出旧 Context 仓库。
- 外层工作区路由在多设备恢复中产生不可接受的漂移，需要把产品仓库移动到启动根。
- 某个工具缺少可用的宿主原生私有状态机制，并出现经过验证的跨会话恢复需求。
- 项目进入多人或远程协作，需要把本地启动约束提升为可自动分发的配置。
