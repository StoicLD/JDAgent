# ADR-0007：原始历史、上下文投影与记忆版本分离

状态：`Proposed`

日期：2026-10-21。产品行为已由用户确认，本文对持久化和恢复机制的细化待工程评审。
修订：2026-10-22，R1；用户授权修订文档，未授权产品实现或批准新增工程细节。

## 背景

v0.5 需要在长任务中多次压缩，同时跨会话检索与维护长期记忆。如果把摘要写回历史、把向量索引
当唯一事实，或让停用等同于删除，恢复与审计会失去依据。

## 决策

- Session 事件继续追加保存，原文或完整结果由其引用的不可变对象持有；压缩只改变模型投影。
- 压缩候选先验证预算与引用，再持久提交检查点，最后替换内存投影；未提交候选不影响恢复。
- Memory 独立持有版本、来源、作用域、状态和停用约束；索引可重建，不能决定事实是否有效。
- 请求清单记录逻辑输入与依赖版本；Knowledge 仍遵循原来源生命周期，不通过快照绕过删除合同。
- Context 协调服务隐藏选择、计数、压缩和检查点，Loop 只提供安全边界；复用既有 ModelPort 和
  工具执行合同，不将维护模型的输出当成工具执行事实。
- 保留独立 recovery Session，以父会话安全截止点、checkpoint 和事件引用组合上下文；不复制
  全量消息，不继承权限，不使用截止点之后的摘要。未知副作用单独保护，历史索引不重复计父正文。
- 一个 Session 由一个进程持有 OS 独占锁；后台发布以来源版本和带 epoch 的租约校验为条件。
  请求 manifest 存为对象、日志存引用，在锁内缓存已校验尾部序号，保持 durable-before-use。
- Memory 的用户操作意图由应用层确定并绑定对象、作用域、版本与内容；自动整理由独立策略授权。
  两者均受 DENY 限制，模型引用用户文字不能自行产生授权，Memory 不取得目录或全局指令优先级。
- 生成请求内的 KB 正文仅引用原所有者；从回答派生的 Memory 继承知识来源依赖，失效后停止自动
  使用，既有 assistant 历史仍按原合同保留。

## 备选方案

直接裁剪最早历史实现简单，但不能保留约束或缩小当前 Turn。持续覆盖一份摘要存储少，但容易
积累语义损失且无法定位丢失来源。由统一知识库同时拥有历史与 Memory 看似复用更多，实际会
混淆原始事实、修正状态和来源删除语义。

## 后果

可以重建当时可用的逻辑请求、恢复已提交投影，并保留停用记忆的来源；代价是维护对象引用、
版本与提交协议，且摘要语义仍须 Eval。旧 Session 不兼容是单独的一次性版本决定，不是本 ADR
允许日常删除原文。具体合同见[架构](../architecture/v0.5-context-memory.md)。

## 复审条件

重复压缩无法满足约束保留验收、对象归档增长不可接受，或多进程并发证明现有提交边界不足时，
依据故障与性能证据复审；不能仅因采用另一个框架而替换事实所有者。
