## Problem Statement

用户希望通过配置，让 JDAgent 使用不同标准 MCP Server 的工具、资源和提示模板，而不为每个外部服务编写一套产品接入。
工具数量增加后，全部定义随每次模型请求发送会消耗上下文；每轮重新发现、检索和加载又会产生重复开销。
外部操作还可能返回大结果、长时间没有最终响应，或先返回任务句柄，需要有明确的等待、取消、重试与查回行为。

当前 ToolRegistry 与 ContextBuilder 主要面向预先组装的工具定义；原生 Runner 和 LangGraph 均按批内顺序执行工具。
现有会话存储、权限、上下文预算与恢复机制可以作为接入基础，但尚无 MCP 协议适配、工具检索、动态加载、结果分段读回或 Tasks 合同。
普通成功工具结果目前还可能进入自动记忆抽取，需要在引入 MCP 时明确其来源边界。

v0.7 的核心结果是：用户配置并启用 Server 后，Agent 能按需使用 Tools、Resources 和 Prompts，
在有界缓存、上下文与执行预算内完成普通调用或顺序等待的 Tasks，并保留可检查的执行事实。

## Solution

采用官方 Python SDK，加上 JDAgent 自建的宿主适配。SDK 负责协议处理，宿主适配负责传输接入与接收限额，并优先复用 SDK 的传输实现。JDAgent 负责配置、能力目录、BM25、
工具加载、权限衔接、结果投影、执行事实和用户交互。两种 Runner 共用同一接入链，SDK 类型不成为领域或会话合同。

Tools 由模型通过 search_tools 按需检索、加载，再经现有 ToolRuntime 执行；Resources 由 Agent 按任务发现并读取；
Prompts 同时支持用户直接触发，以及 BM25 召回后由模型判断是否采用。模板与返回内容保留外部来源。

当前 Session 复用客户端、能力目录及已加载工具，两层缓存均设硬容量上限。完整结果与模型预览分离：
模型先读取有界预览，必要时分段读回原文。缓存可以重建，已被会话引用的结果属于持久证据，不按缓存淘汰规则删除。

业务工具继续顺序执行。普通长调用等待最终结果；新版 Tasks 取得句柄后在当前调用内串行查询，
直到最终结果、失败、等待预算耗尽或用户取消。中断后允许查回任务，不自动继续原 Agent 流程或重新提交工作。

MCP 与知识库 RAG 完全分离。MCP 内容可保存于会话历史并被历史读回，默认排除自动长期记忆抽取；
用户明确的记忆请求仍由独立记忆模块处理。

## User Stories

下列 US 编号是稳定的需求追踪标识；采用“作为……我希望……以便……”的用户故事格式。

1. **US-01** 作为用户，我希望通过配置接入标准 MCP Server，以便不为每个服务修改 JDAgent 代码。
2. **US-02** 作为用户，我希望用户级配置定义 Server、项目级只引用并缩小范围，以便不同工作区使用明确的接入集合。
3. **US-03** 作为用户，我希望配置只引用凭据，并支持环境变量和固定 Bearer Token，以便账号信息不进入项目文档与普通日志。
4. **US-04** 作为用户，我希望同时使用 stdio 和 Streamable HTTP，以便接入本地进程及远程服务。
5. **US-05** 作为用户，我希望知道具体支持的协议版本和扩展，以便分辨兼容性限制与连接故障。
6. **US-06** 作为用户，我希望只提供 Resources 或 Prompts 的 Server 也能正常接入，以便不把“没有 Tools”误报为连接失败。
7. **US-07** 作为用户，我希望首次使用 MCP 时才准备连接与目录，以便只使用内置能力时不启动外部服务。
8. **US-08** 作为用户，我希望同一 Session 的后续操作复用已准备的客户端，以便减少重复启动和协商。
9. **US-09** 作为用户，我希望切换或退出时关闭客户端、恢复时重新连接，以便连接归属与对话生命周期一致。
10. **US-10** 作为用户，我希望一个 Server 不可用时其他能力仍可使用，以便局部故障不拖垮整个 CLI。
11. **US-11** 作为用户，我希望不同 Server 的同名工具能够准确区分，以便调用不会被路由到错误服务。
12. **US-12** 作为用户，我希望目录分页及尚未完成的搜索范围被准确处理，以便不会漏掉后续页或把未加载当成不存在。
13. **US-13** 作为用户，我希望不合法或不兼容的工具被局部隔离，以便同一 Server 的其他能力继续可用。
14. **US-14** 作为用户，我希望模型通过 BM25 检索工具名称与描述，以便按需找到能力而不发送全部定义。
15. **US-15** 作为用户，我希望搜索支持 Server 过滤、明确的无结果和查询改写，以便能够定位工具而不依赖向量服务。
16. **US-16** 作为用户，我希望检索后加载完整参数定义，以便模型能在后续请求中正确构造调用。
17. **US-17** 作为用户，我希望未启用或未提供给本次模型请求的工具不能执行，以便模型猜测名称不能绕过可用范围。
18. **US-18** 作为用户，我希望常用工具跨 Turn 保留，以便连续任务不用每轮重新搜索。
19. **US-19** 作为用户，我希望目录和索引容量有界、被淘汰后可重新加载，以便工具规模增长时仍能准确说明覆盖范围。
20. **US-20** 作为用户，我希望已加载工具按容量与最近使用情况淘汰，以便完整 Schema 不持续挤占模型上下文。
21. **US-21** 作为用户，我希望执行依据与模型看到的工具定义一致，以便刷新或淘汰不会在调用中途改变参数含义。
22. **US-22** 作为用户，我希望在空闲时显式刷新目录或重新连接，以便更新能力时不会破坏当前执行条件。
23. **US-23** 作为用户，我希望发现资源及资源模板，以便使用没有枚举为固定文件的上下文来源。
24. **US-24** 作为用户，我希望 Agent 按任务读取选定资源 URI，以便获得必要上下文而不预加载全部资源。
25. **US-25** 作为用户，我希望 MCP 与 RAG 保持完全分离，以便外部资源不会进入知识库摄取、索引或检索流程。
26. **US-26** 作为用户，我希望直接点名或通过命令触发 Prompt，以便使用明确指定的模板而不先打开选择菜单。
27. **US-27** 作为用户，我希望 Agent 能用 BM25 召回并自动选用相关 Prompt，以便自然语言任务也能利用模板。
28. **US-28** 作为用户，我希望关键词命中只产生候选，以便不相关的模板不会被无条件执行。
29. **US-29** 作为用户，我希望模板参数来自任务信息、缺失时按普通对话澄清，并保留模板来源，以便外部模板不冒充用户或系统指令。
30. **US-30** 作为用户，我希望正确接收文本与 JSON 结构化结果，以便既能阅读解释也能使用结构化数据。
31. **US-31** 作为用户，我希望资源链接保留来源并按需读取，以便远端 URI 不被误当成本机路径。
32. **US-32** 作为用户，我希望未处理的图片、音频或其他内容被明确标记，以便部分结果不冒充完整证据。
33. **US-33** 作为用户，我希望输入及结构化输出按相应 Schema 校验，以便错误参数或结果不会被悄悄改写后使用。
34. **US-34** 作为用户，我希望单次结果预览受 12,000 个估算 token 及剩余上下文预算限制，以便大结果不挤满窗口。
35. **US-35** 作为用户，我希望按引用分段读取已完整保存的结果，以便超过软限制后仍能取得原文。
36. **US-36** 作为用户，我希望单个 RPC 响应在接收阶段执行 1 MiB 硬限制，以便过大数据不会先全部进入内存再被拒绝。
37. **US-37** 作为用户，我希望每个 Session 的 MCP 完整结果存储有可配置配额，以便容量不足时在新操作前得到明确反馈。
38. **US-38** 作为用户，我希望历史结果不被缓存淘汰自动删除，以便原文引用可以持续核验。
39. **US-39** 作为用户，我希望连接准备默认在 15 秒内得到结果，以便不可用服务不会无限阻塞接入。
40. **US-40** 作为用户，我希望工具执行等待预算可按工具或 Server 覆盖，以便长操作不被统一的短超时误中断。
41. **US-41** 作为用户，我希望看见已用时间和可用进度，并区分无进度与执行失败，以便正确理解长操作状态。
42. **US-42** 作为用户，我希望能够取消长操作并得到明确的清理状态，以便不把本地停止等待误认为远端已停止。
43. **US-43** 作为用户，我希望符合条件的服务端超时总共最多尝试 3 次，以便有界恢复暂时性故障。
44. **US-44** 作为用户，我希望客户端等待超时、断线或执行结果未确认时不自动重放，以便不会产生未经确认的重复工作。
45. **US-45** 作为维护者，我希望一次逻辑调用内的各次尝试可追踪，以便定位重试原因和真实请求次数。
46. **US-46** 作为用户，我希望检索、读取、获取模板和结果读回都计入工具预算，以便 MCP 不形成隐藏的无限调用路径。
47. **US-47** 作为用户，我希望 v0.7 保持一个前台 Turn 和业务工具顺序执行，以便不提前引入多任务编排。
48. **US-48** 作为用户，我希望使用新版 Tasks 并在当前调用中查询最终结果，以便支持协议提供的长任务形式。
49. **US-49** 作为用户，我希望取得 Task 句柄时仍显示工作未完成，以便提交成功不被当作任务完成。
50. **US-50** 作为用户，我希望任务结束状态与工具业务结果分别判断，以便 completed 内的工具错误不被当作成功。
51. **US-51** 作为用户，我希望任务提出不支持的输入请求时明确结束处理，以便不会无限轮询。
52. **US-52** 作为用户，我希望取消请求与最终取消状态分别记录，以便知道远端是否确认停止。
53. **US-53** 作为用户，我希望恢复 Session 后能查询原任务、读取结果或再次取消，以便查明中断后的执行事实而不自动续跑。
54. **US-54** 作为用户，我希望任务过期、不存在、身份变化或本地进程重启导致的不可恢复被明确说明，以便不会误以为任务必然仍在。
55. **US-55** 作为用户，我希望取得任务句柄后只重试原任务查询，以便查询失败不会创建替代任务。
56. **US-56** 作为用户，我希望在 CLI 查看连接、版本、能力和不可用原因，以便自行诊断接入状态。
57. **US-57** 作为用户，我希望运行中只开放状态查看与取消，改变执行条件的动作留到空闲时，以便操作不会与当前调用冲突。
58. **US-58** 作为用户，我希望 Headless 使用同一接入规则，并对缺少凭据或不支持的交互明确返回，以便脚本不会无限等待输入。
59. **US-59** 作为用户，我希望 MCP 内容保留于历史但默认不参与自动长期记忆抽取，以便外部内容不会被默认固化。
60. **US-60** 作为用户，我希望仅开放显式配置且确认过的只读工具，以便 v0.7 不依赖未实现的自动风险判断。
61. **US-61** 作为维护者，我希望原生 Runner 与 LangGraph 共用 MCP 接入并保留现有模型边界，以便更换引擎不会改变工具行为。
62. **US-62** 作为用户，我希望执行记录包含必要来源、状态及完整性信息而不泄漏凭据，以便能够排错和核验。
63. **US-63** 作为维护者，我希望有受控故障场景及独立 Server 的互操作证据，以便验收不止于一次成功连接。
64. **US-64** 作为学习者，我希望能依据调用链与事实记录解释缓存、长调用、Tasks 和重试，以便掌握设计取舍而不把使用 SDK 当作学习完成。

## Implementation Decisions

本节记录已确认的职责和行为，不冻结新增类名、目录布局或未验证的 SDK 调用写法。具体编码合同的待细化项见 Further Notes。

### D01 协议、传输与 SDK 边界

| 范围 | v0.7 支持 |
| --- | --- |
| 核心协议 | 2026-07-28、2025-11-25 |
| 传输 | stdio、Streamable HTTP；HTTP 同时处理普通 JSON 和请求内 SSE 响应 |
| Server 能力 | Tools、Resources、Prompts；能力缺失、空目录与连接失败分别表达 |
| Tasks | 2026-07-28 扩展；旧版核心支持不意味着支持其 2025 实验 Tasks |
| 认证 | stdio 明确配置的环境变量、公开 HTTP、固定 Bearer Token |

官方 Python SDK 封装在 MCP 适配内。Core、ModelPort、ToolRuntime 的公共结果和 Session 不暴露 SDK 对象或异常。
适配层可以包装 SDK 支持的字节流或传输接入点，在整条消息解析前执行接收硬限；这不改变 SDK 的协议职责。
超限消息必须整体拒绝，不能截断后当作正常 JSON-RPC 消息解析。具体包装可行性仍待锁版实验，不把这项职责划分写成已验证的 SDK 能力。
若两种传输中任一种无法满足 AC-11，暂停对应实现并提交证据与设计修订，不能自动降为解析后的长度检查。
当前官方 SDK 对 Tasks 提供公开扩展接入点，但未提供现成的新 Tasks 实现；需在锁定版本上验证再实现适配，不能宣称安装 SDK 即可获得 Tasks。
协议版本不受支持时明确报告；不静默改用未承诺的旧 HTTP+SSE 或实验扩展。

### D02 与现有运行时的衔接

Runner 保留模型调用顺序和业务限额，ToolRuntime 保留参数、权限、执行与结果规范化职责；ContextService 负责模型输入预算和投影。
MCP 接入负责连接、能力目录、BM25、动态定义、协议结果及 Task 状态的转换，通过现有组合根交给两种 Runner 使用。
不让 SDK、默认 ToolNode 或另一套 Agent 主循环直接接管执行。保持一个前台 Turn、批内业务工具逐项执行。
终端输入与取消仍可响应；这不构成并行工具调度或第二个业务 Turn。

### D03 配置、身份与只读范围

用户级配置定义稳定 Server ID、传输、启动参数或 URL、工作目录、凭据引用、启用范围及等待配置。
项目配置只能引用已定义 Server 并进一步缩小范围，不能替换启动命令、账号或扩大用户级允许集合。
凭据不进入仓库、普通事件正文、模型上下文或 Trace；stdio 不自动继承全部宿主环境。
用户级配置同样只保存凭据引用，不内嵌 Bearer Token。最小接入以环境变量引用解析 Token 和明确配置的 stdio 环境值；
解析值只进入对应连接，不进入配置回显、异常或身份缓存键。身份使用不含秘密的引用标识与连接代次，换凭据后须显式重连。
凭据文件和系统秘密存储不是本轮新增的必需后端，后续扩展仍遵守引用合同。

首版启用手工确认的查询、搜索、读取和计算工具，服务端支持时使用只读凭据。未启用工具在检索与执行入口均不可用。
readOnlyHint 等注解作为信息，不替代宿主配置和现有权限决定。MCP 原始参数中的 path、cwd、revision 不自动获得本地文件权限或本地文件依赖语义。
MCP 工具、资源 URI 和 Prompt 内容携带服务来源，不能因为字段同名而触发本地路径规则或改写系统指令。
来源由宿主注册信息确定，不能信任参数中自报的来源字段。MCP 调用跳过本地目录指令发现和工作区路径解释，包含 path、directory、cwd 及 args 的路径扫描。
仍执行 Schema 校验、启用范围检查和适用于 MCP 的参数预检；内置工具保留原有目录发现与权限处理。

### D04 客户端生命周期与故障隔离

首次使用 MCP 时准备当前工作区启用 Server 的客户端和能力目录。一个活跃 Session 内，每个 Server 复用客户端，stdio 进程随客户端存活。
切换对话或退出时关闭客户端，恢复对话时重新连接；不跨 Session 或工作区共享客户端和缓存。
缓存身份包含 Server 配置、工作区与认证身份的有效版本。配置身份变化、显式重连或刷新使对应旧定义失效。
一个 Server 连接或目录准备失败时标为不可用并说明原因，其他 Server 和内置工具保持可用。
不自动恢复普通工具的 Server 业务状态，也不通过自动重连重放已发出的业务操作。

### D05 目录、名称、Schema 与完整性

按 Server 声明的能力分别获取 Tools、Resources、资源模板和 Prompts，处理分页并对页数、条目和数据量设界限。
工具全局身份由稳定 Server ID 与原始工具名共同确定；对模型名称的编码保留可逆路由信息并处理冲突，不依赖 Server 自报名称唯一。
原始参数及结果语义必须保留。输入 Schema 不合法或无法准确投影到当前模型时，局部隔离该工具并报告原因，不能删除约束来伪装兼容。
只有整份响应不可解析等无法可靠区分条目的情况，才使相应目录获取失败。
目录未加载、分页未完成、某 Server 不可用与确实没有匹配结果分别表达；搜索结果不得把覆盖不完整写成全局无结果。

### D06 BM25 与动态加载

模型通过始终可用的工具检索入口 search_tools 检索获准工具的名称与描述；支持 Server 过滤、有界返回、分页及查询改写。
使用 BM25 关键词检索，不引入 Embedding、向量数据库或额外重排模型。Prompt 候选召回复用关键词检索原则，但保留独立能力类型。
关键词匹配不等于语义检索，中文任务与英文工具信息的固定样例必须覆盖查询改写及未召回情况。

检索选中的完整定义加入后续 ModelRequest。已有可用定义允许跨 Turn 复用，不强制每轮重新检索。
执行必须同时满足配置启用、当前可用及该调用所属 ModelRequest 已实际提供定义；仅猜对已注册工具名称不构成执行资格。
每次 ModelRequest 保存定义身份和版本快照，执行以同一份定义核验。加载或淘汰只影响后续请求，不改变当前批次已引用的定义。
快照绑定请求、Server／认证配置代次、工具路由及 Schema 摘要；执行端接收该快照中的定义，不能只按名称从最新目录重新解释参数。
当前批次引用的定义保持固定且计入容量预算；容量不足时拒绝或减少新加载，不能淘汰正在使用的定义来伪造满足硬限。
持久记录保留请求与定义身份用于核验；恢复 Session 不据此重新执行旧批次。

### D07 两层有界缓存

| 层次 | 内容与约束 | 淘汰与重建 |
| --- | --- | --- |
| 能力目录及 BM25 索引 | 元数据字节数、能力条目和索引开销均有容量边界 | 按 Server 整体释放近期未使用的目录及索引；保留未加载标记，需要时重载 |
| 已加载工具集合 | 工具数量与完整定义的 token 预算同时有界，并服从总上下文预算 | 在模型请求之间按最近实际使用情况淘汰；当前请求及待执行批次引用的定义保持固定 |

单个 Server 的目录本身超过容量时明确报告，不能反复淘汰其他目录却始终装不下，也不能静默截断后标成完整。
缓存重载失败必须反映搜索覆盖缺口。显式刷新、重连或配置身份变化时，对应目录、索引与已加载定义一并失效。
首版不后台订阅或定时刷新目录；改变执行条件的动作只在空闲时执行。
硬容量要求已批准，具体默认值与计量细节须以固定样例校准并进入工程设计，不在本文补造用户已批准的数字。

### D08 Resources 与 Prompts

Agent 可按任务列出资源、发现模板并读取选定 URI；用户也可明确指定资源。不预加载全部资源，不把 URI 自行解释为宿主文件路径。
Resources 只提供当前任务需要的外部上下文，与知识库 RAG 完全分离。

Prompt 两种入口共用发现与获取逻辑：直接命令或明确点名；BM25 召回候选后由模型判断相关性并自动选用。
不要求先打开菜单或专门填参界面。参数从任务信息获取，确实缺少必要信息时通过普通对话澄清。
关键词命中不会无条件执行模板。取得的模板消息保留来源和模板结构，作为当前任务材料使用，不替换系统规则，不伪造为用户亲自输入或模型已经完成的回答。
模板参数澄清与 Server 发起的 elicitation 是不同机制；后者不在本版支持范围内。
用户亲自输入的触发语句可保存为用户消息，展开后的外部模板正文必须另存为带来源的材料，不能写成用户消息。
直接触发 Prompt 不伪造模型曾发起工具调用；其应用记录与模型发起调用的配对记录分别表达。

### D09 结果格式、原文与模型预览

支持文本、JSON 结构化内容、文本嵌入资源及资源链接。合法 structuredContent 可以是对象、数组或其他 JSON 值，不能只接受字典。
资源链接先保留为带来源的引用，是否读取由后续动作决定。图片、音频和二进制等未支持内容明确标记；混合结果可提供已支持部分，但必须显示不完整性。
只有不支持内容、没有可用结果时明确报告能力不足，不能返回空字符串并宣称成功。

完整接收结果、Schema 校验结果、可用内容、模型预览和完整性标记分别表达。结构化校验依据完整数据，不把截断 JSON 当作完整结构化输出。
完整结果在配额内持久保存，模型只接收有界投影及读回引用；分段读回同样受单次展示预算约束并能核验来源与完整性。
历史读回或会话恢复也必须保持此原文／投影边界，不能通过旧事件投影重新把全部大结果塞入模型请求。
普通上下文、压缩输入和恢复投影只消费有界预览及引用，不能因加载了原文对象而重新发送全文。
用户触发语句与外部模板分别保留来源；摘要不得把外部材料提升为受保护的用户约束。

### D10 已确认的时间、容量与调用限额

| 项目 | 默认值或规则 |
| --- | --- |
| 连接准备 | 15 秒；覆盖形成可用 MCP 通信的准备阶段，不作为业务工具执行期限 |
| 工具执行总等待预算 | 10 分钟；工具配置优先于 Server 配置，再优先于默认值，长操作可配置更长时间 |
| 重试时间 | 首次执行、重试、退避和 Tasks 等待共用逻辑操作总预算，不因重试重置 |
| 本地取消清理等待 | 初始 5 秒；到期记录清理或远端停止未确认，不声称已经撤销操作 |
| 单次模型结果预览 | 12,000 个估算 token，并服从本次请求剩余输入预算 |
| RPC 接收硬限 | 单个 MCP RPC 响应 1 MiB；流式按累计、解压后的接收数据计量，stdio 按消息界限处理 |
| Session 完整结果配额 | 初始 100 MiB，可配置；发送新操作前检查并预留额度，容量不足时拒绝新增需要保存结果的操作 |
| 执行尝试 | 符合条件时总共最多 3 次，即首次加最多 2 次重试 |
| 业务工具与模型次数 | 沿用每 Turn 默认 32 次工具调用、16 次模型调用，允许配置调整 |

软限制只限制本次模型看到的内容；硬限制限制能接收的数据。硬限必须在接收阶段生效，不能只在 SDK 完整解析后检查长度。
硬限触发时停止接收并记录结果未完整取得；必要时关闭已无法可靠继续解析的对应连接。其他 Server 仍可用，不自动重试超大响应。
Tasks 的每次查询是独立 RPC，各受接收硬限；多次轮询仍受最小轮询间隔及整个逻辑调用的总等待预算约束。
存储配额不按缓存策略自动删除已引用原文。正文、元数据、预留释放和重复对象的计量合同需在工程细化中固定并测试。
进度通知用于展示，不无限延长总预算；没有进度不能证明工具已挂死。底层 SDK 及传输等待必须与宿主预算协调，避免更短的隐含默认值先终止长操作。
这条要求也覆盖 ToolRuntime：MCP 使用自管超时入口，由适配层管理逻辑调用截止时间，不受内置工具默认 10 秒外层等待提前截断。
本地取消收尾使用独立的 5 秒上限，不能落入无限等待子任务的通用清理路径；该收尾可在执行总预算结束后发生。
到期仍无法确认清理时隔离相应客户端、保留资源归属和未确认记录，并使前台返回；不因此恢复业务执行或宣称远端已停止。

### D11 超时、重试与执行事实

连接准备失败、Server 明确报告的业务超时、客户端等待预算耗尽、断线、用户取消和结果解析失败分别记录。
自动重试只用于能可靠识别的服务端超时，且工具配置已确认允许安全重复；注解、isError 布尔值、文本中的 timeout 或 HTTP 504 本身都不足以自动放行。
客户端未收到结果、用户取消、预算耗尽或执行事实未确认时不自动重放业务操作。
相同 Turn 内的相同工具、参数与有效身份，不因更换模型 call_id 重新获得耗尽的自动重试额度。
重试逐步退避，受总等待预算限制；每次发送、超时来源和结果可追踪，但仍属于一次逻辑工具调用。

继续使用 ToolOutcome 区分 completed、effect、observed_failure、cancelled 和停止要求。
结果未确认与副作用未知不是同一个事实；只能依据实际证据及已确认的操作语义填写 effect，不能把等待超时写成已回滚或未执行。
未知副作用、持久化失败及必须停止的情况继续遵守现有 Turn 与 Session 恢复合同。
发送状态、结果确认状态、副作用和自动重试资格分别记录。已确认只读语义可以保留 effect=none，结果未知时仍须停止当前执行并阻止自动重放，不能靠一律赋值 unknown 实现停止。
宿主在可能发送请求之前持久记录调用身份和发送意图；落盘失败则不发送。崩溃后只有意图而无最终证据时，按“可能已发送、结果未确认”处理，不猜测未执行。
重放限制依据逻辑调用及有效身份检查，不依赖模型是否遵守错误文字，也不因更换 call_id 绕过。

### D12 顺序 Tasks 与恢复

仅协商 io.modelcontextprotocol/tasks 的新版扩展。Server 可以将 tools/call 返回为 Task；适配需要识别该结果，再通过 tasks/get 查询。
不把普通调用放入异步协程就声称实现了 MCP Tasks；不在本版将 Resources 或 Prompts 扩展成 Tasks。
取得句柄只是任务已创建；当前业务调用继续串行等待，不把提交回执当作已完成结果，不让模型提前继续下一步。

识别 working、input_required、completed、failed、cancelled。completed 仍须检查最终 CallToolResult.isError；任务状态与业务成功分别判断。
input_required 等不支持的交互必须明确结束处理并按取消策略收尾，不能当作 working 无限轮询，也不虚假声明支持 elicitation 或 sampling。
遵守 Server 建议的轮询间隔并设最小间隔。正常轮询不是重新执行工具；单次查询失败满足条件时总共最多尝试 3 次，始终查询同一个 Task。
已经取得句柄后，不因查询失败重新提交原工具；任务本身明确失败也不自动创建替代任务。

保存任务与原 Server、认证身份、Session 和逻辑调用的关联，模型和普通日志使用受控本地引用，不把敏感远端句柄当作普通展示文本。
用户取消、正常退出或等待预算耗尽时请求取消，并区分已请求、已确认与未确认；取消响应不自动证明工作已停止。
恢复 Session 后允许显式查询原任务、读取已完成结果或再次取消，不自动继续原 Agent 流程，不重新提交工作。
TTL 是 Server 保存任务的期限，不等同于执行预算。任务过期、不存在、身份不匹配或 stdio 进程关闭后任务消失时明确报告。
不保证 Server 业务状态在进程退出后存活，不引入后台守护进程、自动续跑或持久图 checkpointer 来兑现超出本规格的恢复承诺。
恢复分别处理尚未发送、可能已发送但无句柄、已登记 Task 和已完成结果。只有确定未发送的调用可以补为 NOT_EXECUTED；
无句柄时明确无法保证查回，有句柄时先持久登记，再继续轮询。不得把已开始的只读 MCP 调用按本地安全中断规则补成未执行。
MCP 结果未确认本身不要求切换到新 Session；任务管理仍能访问原 Session 的受控引用。若同时存在本地写副作用未知，保留既有隔离规则，
通过独立任务管理入口按原身份查询，不为方便恢复 Task 而放宽普通 Agent 继续执行的条件。

### D13 计数、持久化与数据边界

模型发起的工具检索、资源发现与读取、Prompt 检索与获取、结果分段读回及外部工具调用均计一次业务工具调用。
工具内部协议分页、轮询和重试不重复计业务调用，但必须受页数、容量、频率及等待预算约束，并记录必要协议尝试事实。
MCP 内部重试次数与既有 observed_failure 恢复计数是不同概念；不能通过修改旧计数器替代协议重试管理。

Session 继续保存请求、权限、执行和结果事实，Trace 是受控投影。原文与预览分离、Task 记录和来源信息需要接入现有事实链，不能建立互相矛盾的第二套完成记录。
MCP 数据不接入 RAG 的摄取、索引、知识检索或自动导入流程，也不要求运行 Milvus 才能使用 BM25。
自动长期记忆抽取排除 MCP 来源内容；会话保存、压缩和历史读回保留来源。用户明确的记忆请求由既有独立机制判断与执行。
排除在把候选事件交给记忆模型之前完成，使用来源及派生关系，不依赖工具名黑名单。
结果读回和摘要继承外部来源；无法分离来源的混合候选不进入自动抽取。用户原始陈述仍按原机制处理，不能因此把整段会话全部排除。
SDK 类型、凭据、完整环境变量及未经筛选的外部日志不进入公共事件或普通 Trace。
新增记录的序列化和读取能力必须一起设计。保留可读取的旧会话；遇到不支持或损坏的单个会话时，列表显示其状态并继续列出其他会话。
可以隔离不可读会话，但不能忽略未知执行事件后继续该会话的 Agent 流程。Schema 版本与编码细节待工程细化，不擅自清理或迁移旧数据。

### D14 CLI 与 Headless

CLI 提供 Server 状态、协议版本、能力列表、不可用原因、显式目录刷新、Prompt 直接触发及已登记 Task 的查询、结果读取与取消。
运行中允许查看不会改变执行条件的本地状态和取消当前操作；目录刷新、配置切换等在空闲时进行。
保留只读 /context-window；MCP 状态查看只读本地快照，显式远端 Task 查询在空闲时执行。
运行中 /compact 提示稍后重发，不在当前 Turn 排队执行；正常退出沿取消和有界清理路径处理。
审批回答与命令由单一终端读取入口分流，不能暂停整个命令队列来保护提示。取消始终可达，状态输出须重绘或延迟显示，避免被误当审批回答。
不增加管理 GUI 或安装市场。精确命令语法在工程设计中固定，交互与 Headless 复用应用用例和 MCP 接入。
Headless 缺少凭据或需要不支持的输入时明确返回，不阻塞等待登录或填参。取消、结果不完整和失败状态在机器可读输出中保持可辨认。

## Testing Decisions

### 主测试边界

用户在 Q37、Q38 已确认从真实使用闭环、故障与集成行为验收。本规格将其落到现有最高公共边界：
主要通过 CLI／InteractiveApplication／Headless 进入 TurnCoordinator 和真实 Runner，观察模型请求、执行结果、事件、退出状态与 Server 实际收到的请求。
使用 FakeModelPort、Scripted Terminal、Capture Presenter 及受控 MCP Server 替换外部依赖，不另建第二套 Agent 或仅供测试的业务接口。

同一组核心场景驱动原生 Runner 与 LangGraph。协议级接收硬限、异常分帧、版本和 Task 结果分派需要更窄的 MCP 适配合同测试，
其结果仍应体现为公开的错误、状态或资源清理行为。不能只 mock SDK 的 call_tool 返回值，就宣称 stdio、HTTP 或 Tasks 互通已通过。

好测试观察外部行为与不变量，不断言私有类数量、缓存容器结构、内部调用顺序或文档里的实现草图。
固定数据包含工具与模板名称／描述、Server 身份、权限过滤和相关性标注；BM25 的确切质量阈值在数据集冻结时给出，不补造已获批准的召回百分比。
使用可控时钟、事件同步点及受控 Server 制造分钟级等待、重试和取消，避免用长时间真实 sleep 证明状态逻辑。

工程验收至少包括核心闭环、边界与故障、集成与回归三组。一个真实 Server 不必覆盖全部能力；受控故障证据与真实互操作证据相互补充。
使用真实认证、付费 Provider 或会产生外部业务影响的场景前，继续遵守项目已有授权边界。已有版本的失败项和学习出口不因本规格而关闭。
R1 保留 US-01–64 和 AC-01–23 编号；衔接设计的 R07-01–12 将新增边界具体映射到这些验收项。
后续实现与测试结果由验收映射追踪，不改变这些要求。

## Out of Scope

- 并行工具调度、多前台 Turn、多 Agent、通用 Planner／依赖图编排，以及任务提交后让模型继续做其他业务工作。
- 后台自动续跑、守护进程、自动恢复原 Agent 流程、自动重提已登记任务或保证远端业务状态存活。
- LangChain 直接接管 MCP、另一套主循环、持久图 checkpointer 或图节点自动重试。
- OAuth 登录／刷新／追加授权、多账号热切换、旧 HTTP+SSE 与 2025 实验 Tasks。
- 向量检索、额外重排模型、RAG 接入或自动知识导入。
- 资源订阅、后台目录定时刷新、MCP Apps、图像／音频／二进制的模型消费与渲染。
- Server 发起的 elicitation、sampling 等未实现交互，以及复杂任务输入工作流。
- 外接写操作、自动风险分类、参数级权限、复杂审批和完整 guardrail；这些属于后续版本范围。
- 管理 GUI、插件安装市场、未经确认的依赖自动安装或跨 Session 共享客户端／缓存。
- 由本规格自动获得产品实现、Git 提交／推送、付费 Live 或既有工程与学习门禁的豁免。

## Further Notes

### 术语与事实归属

| 术语 | 本规格含义 |
| --- | --- |
| JDAgent Session | 保存对话、执行及恢复事实的会话；不是 MCP 旧协议的 Session |
| Turn | 一次用户输入到本轮结束；首版同一时刻只有一个前台 Turn |
| 逻辑工具调用 | 模型发起并经 ToolRuntime 执行的一项操作，内部可有多个 RPC、轮询或重试 |
| RPC 响应／尝试 | 一次协议请求的响应或发送尝试；接收硬限与重试证据在这一层计量 |
| MCP 能力目录 | 外部能力的可重建元数据与完整性状态，不是知识库 Catalog |
| 已加载工具 | 当前可投影进模型请求的完整定义集合；跨 Turn 缓存不改变请求快照 |
| 完整结果／模型预览 | 持久原文与有界上下文投影；保存原文不代表每次完整发送 |
| Task | Server 持有的任务状态，由远端句柄识别；与 Python 异步任务和后台 Memory 作业分别管理 |

本文记录用户已确认的规格。设计时未冻结的 SDK、接口类型、会话兼容、数值校准与固定 Eval 场景，
后续已在[实施记录](../plans/v0.7-implementation.md)细化，实际证据由验收映射追踪。
后续 Issue 和设计文档引用本规格；修改产品范围时先更新批准依据，不以 Issue 讨论默默覆盖仓库合同。

### 访谈收敛与被替代方案

| 决策来源 | 最终有效结论 |
| --- | --- |
| 最初批注、Q1–Q7 | 三类能力、官方 SDK、自建适配、两种传输；只读首版、MCP 与 RAG 分离 |
| Q8–Q18 及修订 | Prompt 两种触发；BM25；跨轮两层缓存；完整结果读回；软限改为 12,000 token |
| Q19–Q26 及修订 | 容量边界与配额；连接 15 秒、执行可配置；最终总共 3 次尝试，而非 3 次额外重试 |
| 用户撤回并行范围 | 多线程／并行编排留到后续版本；未作答的 Q27–Q31 提议不构成批准 |
| Q32–Q34 | 新版 Tasks 串行等待；中断后仅查询、取结果和取消，不自动续跑 |
| Q35–Q37 | 已有 Task 只重试查询；最小 CLI；三组验收 |
| Q38 与后续确认 | 整体规格确认，包括每 RPC 1 MiB、Session 100 MiB、5 秒本地清理初始值；随后授权 to-spec 文档与 Issue 发布 |

已被替代的讨论包括：只做 Tools、强制用户手动选 Prompt、每 Turn 清空工具、结果超限一律失败、所有工具统一 60 秒、
任务提交后让模型继续、并行调度和 4 次总尝试。后续实现不能从这些早期建议恢复已取消范围。

### 与有效 ADR、现状和交付工作流的关系

遵循 ADR-0002 的 SDK 隔离、ADR-0003 的领域无关 Runtime、ADR-0004 的 CLI 应用用例与事实归属，以及 ADR-0008 的顺序执行与共享 Runner 合同。
Tasks 只是远端操作状态查询恢复，不等于恢复整个图执行位置；不因此开启持久图 checkpointer。
新增远程执行边界应在实施设计中显式核对 ADR-0008 的复审条件；本规格不把旧 ADR 的 v0.6 非目标追认为已实现能力。
R1 已在衔接设计中回应该条件：v0.7 需要持久任务关联和显式状态查询，不需要恢复图执行位置，继续不启用持久图 checkpointer 或跨进程审批。

### R1 提出的工程细化清单

以下是 R1 当时的 Proposed 细化清单。后续用户已授权实施，各项落点见实施记录及验收映射；
ready-for-agent 标签本身不构成批准，也不替代这些工作：

1. 锁定官方 SDK 与依赖版本，验证 Tasks 公开扩展接口、旧／新版核心协商和接收阶段硬限的实际可实现路径。
2. 按 R1 衔接设计固定动态定义、来源、预览／原文引用、协议尝试及 Task 记录的具体类型和编码；确定事件 Schema 与兼容读取策略，不擅自清理或迁移旧数据。
3. 用固定样例校准两层缓存容量、BM25 分词及质量阈值、分页与最小轮询间隔；公开具体计量方式和默认值。
4. 细化结果配额预留／释放、分段读取完整性和敏感句柄保存；按 R1 已确定的执行事实及有界取消合同选择具体实现，并证明发送／登记／崩溃各窗口的行为。
5. 固定 CLI 语法、Headless 字段和受支持 Server 超时错误的识别方式；未识别错误继续保持不自动重试。
6. 形成分阶段实施计划、需求到测试映射、固定互操作 Server revision 和模块学习检查表；按项目工作流处理实施授权与既有门禁。

这些内容应复用当前最高公共测试边界，不以未证明的未来变化点新增框架、空壳 Port 或第二事实源。
