# v0.5 上下文、跨会话检索与长期记忆规格

状态：`Approved`（访谈已确认的产品范围与行为）

批准依据：2026-10-21 用户确认访谈收敛方案并要求形成文档。下述需求与已确认决策据此记录；
[架构细化](../architecture/v0.5-context-memory.md)、[实施计划](../plans/v0.5-context-memory-implementation.md)
及其新增参数仍为 `Proposed`。本次批准不等于实现授权，也不关闭既有工程或学习门禁。

2026-10-22 按用户授权修订设计并补评审处置。批准范围保持为访谈确认的行为；新增加的协议字段、
输入语法、退出等待时间、维护入口和实验数值属于架构/Eval 的 `Proposed` 细化。具体“至少三次压缩”
是 AI 建议的 E01 测试参数，已从本规格的已确认 AC 中移出，不能追认成用户当时批准的数字。

## Problem Statement

用户希望 Agent 在一个长任务中连续工作，并在新会话中接续相关经验。当前滑动窗口会移除旧轮次，
但不能缩小当前长 Turn；既可能丢掉早期约束，也可能在当前任务尚未结束时达到窗口上限。
原始事件虽已落盘，Agent 仍缺少有范围限制的历史查询、长期记忆、动态项目指令和可解释的占用统计。

v0.5 的核心结果是：Agent 能在明确预算下多次压缩并继续同一任务，保持约束、执行状态和来源可追溯；
新会话能够检索相关历史并利用经过整理的记忆。跨会话和长期记忆属于本版完整范围。

## Solution

每次调用模型前，Runtime 用当前指令、用户输入、工具定义、相关记忆、历史摘要、近期原文与必要证据
构造 Context。完整原文保存在本地，Context 只是模型本次看到的有限投影。

默认占用达到可用输入预算的 **90%** 时自动压缩，目标降到 **40% 以下**。40% 是目标，不是丢弃重要
内容的理由。用户可随时使用 `/compact` 提前请求压缩；使用 `/context-window` 查看窗口上限、当前
估算、分类占用与上次真实 Usage。长任务中的压缩在最早的完整工具结果边界进行。

会话历史与长期记忆默认限制在同一 workspace。用户通用偏好有独立用户作用域；项目事实不得自动
进入用户作用域。记忆可通过自然语言修正、停用与重新启用；停用不删除历史，也不得被后台再次提取
为有效记忆。新 Session 第一轮完整 Turn 结束后，后台整理其他符合条件的历史会话。

## User Stories

下列编号是稳定的需求追踪标识；“作为……我希望……以便……”对应技能要求的用户故事格式。

1. **US-01** 作为用户，我希望同一长任务能经过多次压缩继续执行，以便完成超过单次窗口容量的工作。
2. **US-02** 作为用户，我希望长对话保留早期仍有效的要求，以便不用反复重述目标和禁止事项。
3. **US-03** 作为用户，我希望压缩优先保留语义与状态，即使增加合理模型开销，以便减少错误续做。
4. **US-04** 作为用户，我希望完整会话原文保存在本地，以便从摘要回查原始证据。
5. **US-05** 作为维护者，我希望能重建模型请求的逻辑输入，以便判断错误来自选择、压缩还是模型回答。
6. **US-06** 作为用户，我希望明确区分原文存档与进入模型的原文保护区，以便理解存盘不等于每次重发。
7. **US-07** 作为用户，我希望系统指令、Role、消息、工具定义、知识、记忆和摘要都有明确归属，以便排查行为。
8. **US-08** 作为用户，我希望读取全局、workspace 和嵌套目录的 AGENTS.md，以便 Agent 遵守目标目录规则。
9. **US-09** 作为用户，我希望每个 Turn 使用稳定的已加载指令版本，以便执行中不会因文件变化前后矛盾。
10. **US-10** 作为用户，我希望首次访问新目录先发现适用规则，以便写入前能调整计划。
11. **US-11** 作为用户，我希望修改过的配置和指令在后续 Turn 生效，以便无须重建会话。
12. **US-12** 作为用户，我希望子目录规则只作用于其路径，以便一个目录的要求不污染兄弟目录。
13. **US-13** 作为用户，我希望当前明确要求优先于历史记忆，以便可以修正先前偏好。
14. **US-14** 作为维护者，我希望模型容量来自 Provider 与 model 配置或能力声明，以便不误用通用窗口数字。
15. **US-15** 作为用户，我希望输入预算预留输出与安全空间，以便请求看似未满却被 Provider 拒绝的情况减少。
16. **US-16** 作为用户，我希望默认在 90% 阈值触发压缩，以便尚有空间完成压缩和必要收尾。
17. **US-17** 作为用户，我希望压缩目标低于 40%，但重要内容可阻止达到该目标，以便不为比例牺牲约束。
18. **US-18** 作为用户，我希望 `/compact` 在空闲时立即执行，以便主动为后续任务释放窗口。
19. **US-19** 作为用户，我希望执行中的 `/compact` 排队到最近安全边界，以便不拆散工具调用和结果。
20. **US-20** 作为用户，我希望重复压缩请求合并，以便不会产生重复维护调用。
21. **US-21** 作为用户，我希望 `/context-window` 展示分类与计数依据，以便判断什么占用了窗口。
22. **US-22** 作为用户，我希望区分本地估算、上次 Provider 实测和累计费用，以便不会把账单当成当前占用。
23. **US-23** 作为维护者，我希望压缩后重新估算完整新请求，以便旧 Usage 不会错误叠加到新摘要。
24. **US-24** 作为用户，我希望重要禁止事项、路径、标识符与必要代码原文受到保护，以便摘要不改变精确含义。
25. **US-25** 作为用户，我希望摘要区分已完成、计划中、失败、待确认与副作用未知，以便 Agent 不把计划当完成。
26. **US-26** 作为用户，我希望摘要带原始事件范围与来源，以便能找回被省略的细节。
27. **US-27** 作为用户，我希望反复压缩复用历史分段而非不断改写唯一摘要，以便控制信息退化。
28. **US-28** 作为用户，我希望摘要生成失败时仍保留原上下文，以便不会因一次故障丢失工作状态。
29. **US-29** 作为用户，我希望重启恢复到已提交的压缩状态，以便不重复有副作用的工具操作。
30. **US-30** 作为用户，我希望无法容纳必要内容时明确停止并说明原因，以便系统不静默丢弃历史继续猜测。
31. **US-31** 作为用户，我希望默认使用当前模型压缩，也能显式配置另一模型，以便选择成本和质量。
32. **US-32** 作为用户，我希望压缩模型不能执行任务工具或擅自切换 Provider，以便维护行为可预测。
33. **US-33** 作为用户，我希望查询本会话及其他会话的原始历史，以便找回摘要没有保留的细节。
34. **US-34** 作为用户，我希望历史查询同时支持关键词和语义匹配，以便既能查标识符也能查相近表达。
35. **US-35** 作为用户，我希望先过滤 workspace 和记录状态再排名，以便不会检索到其他项目内容。
36. **US-36** 作为用户，我希望每个 Turn 召回相关有效记忆，没有相关项就不注入，以便不被无关经验干扰。
37. **US-37** 作为用户，我希望一般历史只在需要时查询，以便不会每轮重发所有旧会话。
38. **US-38** 作为用户，我希望记忆包含稳定偏好、项目事实与决定、验证过的可复用经验，以便新会话继承有用信息。
39. **US-39** 作为用户，我希望临时任务进度留在会话中，以便一次性请求不会变成永久偏好。
40. **US-40** 作为用户，我希望每条记忆有作用域、理由和来源，以便能检查它为何存在。
41. **US-41** 作为用户，我希望新会话首轮完成后后台整理其他历史会话，以便整理不阻塞第一轮回答。
42. **US-42** 作为维护者，我希望按来源版本去重并记录空提取结果，以便没有新内容时不会重复付费调用。
43. **US-43** 作为用户，我希望明确要求“记住”时及时落盘，以便无需等下一次会话整理。
44. **US-44** 作为用户，我希望明确更正生成新版本并停用旧版本，以便后续不再沿用旧结论。
45. **US-45** 作为用户，我希望含糊冲突保留证据并标记待核实，以便模型不会凭猜测裁定事实。
46. **US-46** 作为用户，我希望“忘记”表示停止自动使用且抑制旧来源再次提取，以便保留历史同时尊重当前意愿。
47. **US-47** 作为用户，我希望只有明确重新启用才能恢复停用记忆，以便后台整理不会使它复活。
48. **US-48** 作为用户，我希望稳定记忆不因长期未用而过期，以便低频但重要的信息仍然有效。
49. **US-49** 作为用户，我希望有明确期限的记忆到期停用、来源变化时待核实，以便不把过时内容当现状。
50. **US-50** 作为维护者，我希望维护调用与任务调用分别受预算约束，并统计总开销，以便长任务成本可控。
51. **US-51** 作为用户，我希望后台任务失败或程序退出后可恢复，以便旧记忆继续可用且整理不会重复提交。
52. **US-52** 作为用户，我希望 v0.5 不兼容旧会话，并在设计完成后清理已确认的旧会话，以便从统一新格式开始。

## Implementation Decisions

以下是已确认的行为决策；具体类型名、落盘布局与数值限额由配套架构提案细化。

1. **四类事实分开。** Session Event 是追加保存的运行事实；Knowledge 属于来源管理；Memory 是带版本和
   作用域的持久陈述；Context 是单次调用投影。压缩不改写历史事件，不把记忆或摘要升级为新授权。
2. **指令按 Turn 固定版本。** Turn 开始加载全局与 root→cwd 链；首次进入新路径时补充发现，已发现版本
   固定到 Turn 结束。发现新规则的写操作先返回规则，由模型重新发起写入；程序权限约束始终执行。
3. **配置有明确来源。** 容量、输出预留、阈值和维护限额按 Provider/model 解析并记录快照。未知容量
   必须配置，不默认使用 272K、500K 或 1M。影响请求的配置在 Turn 边界更新。
4. **预算面向真实请求。** 计入工具 Schema、角色封装、系统指令、所有消息及注入内容；缓存命中仍占窗口。
   各分类互斥，总和对应同一请求估算。90% 与 40% 都以扣除必要预留后的可用输入预算为分母。
5. **三层保留。** 原始档案完整落盘；仍有效的关键原文进入保护区；结构化分段摘要和近期完整消息形成
   剩余投影。长 Turn 中已完成的工具批次允许压缩，不能以“当前 Turn”之名永久保护全部内容。
6. **压缩是有界事务。** 选择完整事件边界，生成候选，核对来源和状态，重建请求验证预算，先持久提交，
   后替换内存投影。失败保留旧状态；只在旧请求仍可容纳时继续，否则清晰停止。
7. **90% 是默认触发、40% 是软目标。** 未到 40% 但确有缩小、低于触发线且预留足够时可继续，并报告
   目标未达。没有缩小或必要内容仍超限时不无穷重试，不退回静默删除最老 Turn。
8. **压缩模型不执行任务。** 默认复用当前 ModelPort 配置，可单独指定模型；只接受摘要输出，无任务
   工具。每个维护请求仍检查自己的模型容量、重试、超时与费用。
9. **检索先限定范围。** 跨会话查询和 Memory Recall 包含关键词与语义路径，先做 workspace、作用域、
   状态过滤再排名。索引可重建，权威记录不能由向量库独立持有。
10. **记忆分两阶段整理。** 新 Session 首个完整用户 Turn 完成后启动一次后台作业，先提取其他符合条件
    的历史 Session，再合并与更新记忆；排除当前会话及活跃会话。来源没有新增有效内容则不调用模型。
11. **记忆更新可追踪。** 明确更正替代旧版本；含糊冲突待核实。停用保留记录并阻止旧来源重建，明确
    重新启用才恢复。稳定记忆不按闲置天数失效，期限与来源变化各有独立处理。
12. **用户入口收敛。** 新增 `/compact` 和 `/context-window`，不提供 `/context`、`/memory`；记忆查看、
    更正与停用通过自然语言和受控工具完成。只读窗口统计不调用模型。
13. **恢复不能重复副作用。** 压缩检查点与执行恢复记录职责分开，工具调用及结果保持配对，已确认完成
    的副作用不因摘要、取消或重启再执行。结果未知时沿用现有恢复约束，不能猜测成功。
14. **新版无迁移。** v0.5 使用新会话格式；本次已确认旧会话做一次性清理。新格式原文继续保留，产品
    不新增日常物理删除 Session 或 Memory 的功能。

## Testing Decisions

主测试入口选现有 AgentLoop 的一次真实 Turn：输入消息、注入 Fake Model/Tool/Session，观察发给
模型的请求、持久事件、工具副作用与最终输出。CLI 命令使用既有 CLI 集成入口；持久恢复使用实际
存储 Adapter 与子进程故障测试。只为路径发现、模型计数差异和存储故障补充必要的边界测试。

测试不锁定内部函数次数、私有列表或目录分层；稳定断言包括早期禁令是否仍在、计划是否被误写成
完成、调用结果是否成对、恢复是否重复写文件、不同 workspace 是否串读、停用记忆是否复活。
既有 Loop、ContextBuilder、Session 恢复、CLI 子进程和 v0.4 工具端到端测试是扩展基础。

## Out of Scope

- Skill 执行系统、MCP、子 Agent 编排、OS sandbox、多模态上下文。
- 跨 workspace 自动共享项目事实；自动生成全局偏好；将 KB 改名为 Memory。
- 旧会话迁移与兼容读取；日常物理删除 Session/Memory；`/context` 和 `/memory`。
- 运行中热换已使用的指令版本；保证发现任意 shell 脚本内部的全部路径。
- 自动选择其他 Provider、无限维护预算、承诺压缩没有任何信息损失。
- 以设计完成替代实现、Live Eval 或人工学习出口；本轮不修改产品代码。
