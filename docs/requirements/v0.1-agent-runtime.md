# v0.1 Agent Runtime 需求

状态：`Approved`

批准日期：2026-08-09

## 目标

v0.1 验证一个最小但完整的 Agent 闭环：模型无关的 Agent Core 通过 `ModelPort` 调用模型，处理 Tool Call，经过参数校验和权限判断执行工具，保存可恢复的会话事件，并输出可检查的执行 Trace。

v0.1 是机制学习和架构验证版本，不追求 Claude Code 的功能数量，也不包含求职领域能力。

## 用户场景

1. 用户从文本 CLI 创建新会话并输入自然语言任务。
2. 用户实时看到模型文本输出和工具调用状态。
3. 有副作用的工具执行前，用户可以批准或拒绝。
4. 用户退出进程后，可使用 Session ID 恢复历史会话。
5. 开发者可在不访问真实 API 的情况下，用 Fake Model 重现正常和失败路径。
6. 学习者可根据结构化 Trace 解释一次完整 Agent Turn 的每个阶段。

## 功能需求

### FR-001 文本 CLI

- 支持创建会话、发送消息、结束当前轮次和按 Session ID 恢复会话。
- CLI 只负责输入输出和组装依赖，不承载 Agent 业务规则。
- v0.1 不实现复杂 TUI。

### FR-002 模型边界

- Agent Core 只依赖 `ModelPort` 和项目定义的模型领域类型。
- 提供可编程的 `FakeModelPort`，支持文本、工具调用、Provider 错误、超时和失控循环场景。
- 提供首个真实 `DeepSeekModelPort`，支持流式文本和 Tool Calls。
- Provider SDK 类型、请求对象和异常不得越过 Adapter 边界。

### FR-003 Agent Loop

- 流程为：接收用户消息、持久化事件、构造上下文、调用模型、处理文本或 Tool Call、执行工具、追加结果并继续循环，直到模型正常结束或触发终止条件。
- 支持一次响应中的多个 Tool Call，但 v0.1 按稳定顺序串行执行。
- 配置最大模型调用次数、最大工具调用次数、单工具超时和整轮取消。

### FR-004 工具运行时

- 工具通过统一的 `ToolDefinition` 注册，包含英文名称、说明、JSON Schema、风险等级和 Handler。
- Handler 执行前必须完成工具查找、参数解析和 Schema 校验。
- 工具输出统一转换为 `ToolResult`，包括状态、文本输出、错误、耗时和最小元数据。
- v0.1 固定提供：无副作用的 `calculator`、workspace 限定的 `read_text_file`、必须审批的 `write_text_file`。

### FR-005 权限

- `PermissionDecision` 只有 `ALLOW`、`ASK` 和 `DENY`。
- 纯计算允许；workspace 内读取允许；workspace 内写入询问；workspace 外路径和未知工具拒绝。
- 审批请求及结果必须进入 Session Event Store。

### FR-006 会话和历史

- Session 的事实来源是 append-only 事件流；模型消息由事件投影生成。
- 首个存储 Adapter 使用可读的 JSONL，但 Agent Core 不依赖文件格式或路径。
- v0.1 支持新建和恢复，不支持 fork、merge、跨 Agent 共享或事件修改。
- 持久化只发生在本机运行目录，不进入 Git。

### FR-007 上下文

- `ContextBuilder` 从 Session 投影生成模型请求，组装 System Prompt 和工具定义，并估算上下文大小。
- 超出已知硬限制时明确失败，不静默丢弃历史。
- v0.1 不实现自动摘要、压缩、长期记忆或 RAG，但 Agent Loop 不得直接拼接 Provider 请求。

### FR-008 可观察性

- 每轮记录 Session ID、Turn ID、Provider、Model、调用次数、工具状态、权限决定、耗时、Token Usage、停止原因和分类错误。
- Trace 由结构化事件产生；v0.1 不引入 Langfuse 或 OpenTelemetry。

### FR-009 配置与秘密

- API Key 只从显式配置或用户批准的开发期文件读取，不由程序生成或保存；CLI 中环境变量
  优先，缺省回退到产品仓库之外的 `../tmp/keys/deepseek-api-key.txt`。
- 日志、事件和异常不得包含 API Key、认证 Header 或未经筛选的敏感请求。
- Model、Base URL 和超时可配置；自动测试默认只使用 Fake Model。

## 失败行为

- 未知工具、无效 JSON、Schema 不匹配和越界路径在 Handler 执行前失败。
- 工具异常转换为结构化失败结果并返回模型，不导致事件历史缺失。
- 认证、限流、超时、上下文过长、无效请求和 Provider 内部错误使用稳定错误类别。
- 达到调用上限时以明确的 `limit_reached` 停止原因结束，不继续递归调用。
- 进程异常退出后，已完成写入的事件必须可用于恢复；损坏的尾部事件不得被静默接受。

## 非目标

- Shell、网络工具、浏览器、爬虫和求职领域工具
- MCP、Skills、RAG、长期记忆和上下文压缩
- Subagent、多 Agent、Task DAG、后台任务、Cron 和 Worktree
- Web UI、多用户服务、插件市场和分布式执行
- 完整 Provider 功能对齐和模型自动回退

## 验收标准

1. Fake Model 覆盖普通回答、一次工具调用、多个工具调用、Provider 错误、超时和失控循环。
2. DeepSeek 完成一次流式普通回答和一次真实 Tool Call 闭环。
3. 未批准的写工具不会执行，越出 workspace 的读写请求始终拒绝。
4. 无效工具参数、未知工具和 Handler 异常产生稳定、可追踪的失败结果。
5. CLI 重启后可按 Session ID 恢复，并保留消息、工具、权限和停止原因。
6. Agent Core 不导入 DeepSeek 或 OpenAI SDK 类型；替换 Fake Model 不修改 Agent Loop。
7. 日志和持久化事件不包含 API Key。
8. 学习者可以不看代码解释 `ModelPort`、Tool Call、Tool Result、Session Event 和 Agent Loop 的关系。
