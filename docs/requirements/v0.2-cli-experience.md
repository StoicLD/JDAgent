# v0.2 CLI 体验需求

状态：`Approved`

批准日期：2026-08-20

## 目标

v0.2 把 JDAgent 从“可由命令调用的 Agent Runtime”提升为“可安装、可在任意项目目录中
日常使用的持久交互式 Agent CLI”。本版本聚焦输入、输出、会话、审批、取消、恢复和测试
体验，只增加完成这条 CLI 纵向切片所必需的 Runtime 与 Session 能力。

成功不以复刻 Claude Code 的功能数量衡量，而以以下主循环是否清晰、可靠且可解释衡量：

```text
输入任务 → 看见流式执行 → 审批副作用 → 随时取消 → 保存并退出 → 恢复现场 → 可脚本化验证
```

## 用户场景

1. 用户安装一次 JDAgent 后，可在任意 workspace 目录运行 `jdagent` 并进入 DeepSeek 交互会话。
2. 用户可使用多行输入、历史、搜索、命令补全和持续状态提示完成多轮任务。
3. 用户可在同一个 workspace 下创建、命名、列出和恢复多个 Session。
4. 用户批准写操作前能看到工具、规范化目标、参数摘要、风险和允许范围。
5. 用户在模型生成或工具等待期间可取消当前 Turn，而不丢失已持久化 Session。
6. 终端正常退出或异常关闭后，用户能恢复到最后一个可证明安全的状态。
7. 开发者可用 Fake Model 和稳定的 text/json 输出重复验证指定路径，而不调用真实 API。
8. 学习者能解释 CLI 应用层、Runtime、Session、Terminal Adapter 与 Presenter 的职责和数据流。

## 术语

- **Workspace / Project**：用户显式选择的工作目录，也是文件工具的安全范围。默认是当前工作
  目录；只有 `--workspace` 可以覆盖，不自动向上搜索 Git 根目录。
- **Session**：属于一个 workspace 的持久对话与运行历史；同一 workspace 可以有多个 Session。
- **Turn**：从一次用户 Prompt 开始，到完成、失败或取消结束的一次 Agent 运行。
- **安全 Turn**：具有完整终止事实，且不存在未决副作用的 Turn。
- **交互模式**：无一次性 Prompt 时进入的持续 REPL。
- **Headless 模式**：一次性 Prompt 的 text/json 输出模式。

## 功能需求

### FR-201 可安装入口与默认 Provider

- `jdagent` 安装后可从任意 workspace 运行；`python -m jdagent` 保持等价入口。
- 提供 `--version`，使安装、问题报告和子进程测试可以确认实际运行版本。
- 无一次性 Prompt 时默认进入交互模式；显式一次性 Prompt 保留 Headless 用法。
- 默认真实 Provider 为 DeepSeek；Fake Provider 只在测试或显式 `--provider fake` 时使用。
- 未找到可用 DeepSeek Key 时不得静默回退 Fake，必须给出可执行配置提示并以稳定退出码退出。
- v0.2 不增加第二个真实 Provider。

### FR-202 分层配置与秘密

- 配置优先级固定为：`CLI 覆盖 > 项目配置 > 用户配置 > 内置默认值`。
- 用户配置遵循操作系统用户配置目录；项目配置位于 workspace 的 `.jdagent/config.toml`。
- 项目配置可设置模型、预算、超时和 UI 偏好，但不得设置 API Key、Key 文件、Provider URL，
  也不得放宽用户级权限上限。
- DeepSeek Key 优先级固定为：显式 `DEEPSEEK_API_KEY`、用户配置指定的 `api_key_file`、源码
  开发布局中的 `../tmp/keys/deepseek-api-key.txt`。
- Key 不进入项目配置、Session、输入历史、Trace、异常正文或测试快照。
- 配置错误必须指出来源层、字段和修复方法；不得显示秘密值。

### FR-203 交互输入

- 使用增强型行式 REPL，不构建全屏 TUI。
- `Enter` 提交，`Alt+Enter` 插入换行；多行粘贴保持为一个 Prompt。
- 支持上下键历史、`Ctrl+R` 搜索、斜杠命令补全和集中定义的快捷键帮助。
- 输入历史保存到本机用户数据目录并按 workspace 分区，不进入目标项目 Git。
- 空输入不创建 Turn；EOF 与 `/exit` 都执行正常退出。

### FR-204 内建斜杠命令

v0.2 固定提供以下内建命令：

- `/help`：命令、参数和快捷键帮助。
- `/status`：Provider、模型、Session、workspace、预算、权限模式和最近停止原因。
- `/new`：保留旧 Session 并创建新 Session。
- `/sessions`：列出当前 workspace 可恢复的 Session。
- `/resume`：按名称、短 ID、完整 ID 或交互选择器恢复 Session。
- `/rename`：命名当前 Session。
- `/permissions`：查看或调整当前 Session 的权限状态。
- `/trace`：显示上一 Turn 的安全 Trace 投影。
- `/exit`：完成必要收尾、恢复终端并退出；Session 保持可恢复。

命令必须被解析为有类型的用户动作，不发送给模型。v0.2 不提供 `/clear`，不加载自定义命令、
Skills、Hooks 或 Plugins。

### FR-205 Session 发现与生命周期

- 默认创建新 Session，不自动恢复最近 Session。
- `/sessions` 至少展示名称、短 ID、更新时间、workspace 和最近状态；默认只列当前 workspace。
- 名称不要求全局唯一；歧义时必须让用户选择，不得静默猜测。
- Session、输入历史和本机 UI 状态存放在操作系统用户数据目录，并按规范化 workspace 身份分区。
- Session 名称等生命周期事实必须可持久恢复；Catalog 索引只能是可删除、可从事实重建的投影。
- v0.1 workspace 内 `.jdagent/sessions` 的已有 Session 不得被静默删除；升级方案必须提供可验证
  的发现或非破坏性导入路径。
- v0.2 不提供删除、通用 branch、merge、export、checkpoint、undo 或自动 compact。

### FR-206 增量持久化与异常恢复

- 每个 Runtime Event 成功追加、flush 和 `fsync` 后才视为已保存；`/exit` 不是第一次保存。
- `Ctrl+C` 和操作系统提供的关闭信号执行尽力取消与收尾；强杀和断电不承诺执行清理代码。
- 如果此前所有事件有效、只有最后一条物理记录残缺，恢复流程必须保留原文件备份、截去残缺
  尾部、显示警告，并恢复到最后一个完整事件。
- 中间损坏、Schema 不支持或 sequence 冲突继续 fail closed，不得猜测修复。
- 物理合法但未正常结束的 Turn 必须分类：尚未越过副作用边界时，可追加明确的进程中断失败
  事实后继续；写工具可能已执行但结果未记录时，必须阻止自动继续并显示副作用状态不确定。
- 副作用不确定的原 Session 必须原样保留；用户可从最后一个安全 Turn 建立异常恢复 Session，
  但该机制不扩展为通用 Session Branch 功能，也不声称回滚 workspace。
- v0.1 的单进程单 writer 约束继续成立，除非独立设计另行批准。

### FR-207 取消与退出

- 运行中第一次 `Ctrl+C` 取消当前 Turn，保存可证明的终止事实并返回输入状态。
- 空闲输入状态的退出语义必须与运行中取消区分，并由 `/help` 明确说明。
- 取消不得触发尚未开始的额外工具副作用；已经开始的外部副作用不承诺回滚。
- `/exit` 不永久关闭 Session；退出后仍可通过 `/resume` 恢复。
- Turn 级模型错误、工具错误和用户拒绝在给出可执行提示后返回输入状态；配置无效、Session
  中间损坏和 Runtime 初始化失败才终止进程。

### FR-208 审批与 Session 级允许

- 审批至少显示工具名、规范化目标、参数摘要、风险和调用标识，不显示不必要的文件正文或秘密。
- 用户可以选择拒绝、本次允许或当前 Session 内窄范围允许。
- Session 级允许按工具与规范化目标形成最小范围规则，例如具体文件或目录；不得把一次写批准
  扩大为当前 Session 内该工具的全部调用。
- 规则由 Permission 模块表达和判断；Terminal Adapter 只展示选择，不维护旁路白名单。
- 项目配置只能收紧用户级权限上限，不能放宽。

### FR-209 交互呈现与可观察性

- 输入区附近持续显示紧凑状态：Session 名称、模型、权限模式和 `idle/generating/
  waiting_approval/running_tool/cancelling` 等运行状态。
- `/status` 提供详细 workspace、预算、调用统计和最近停止原因。
- 交互模式区分用户、模型、工具、审批、警告和错误，并提供流式回答与最终可读 Markdown。
- 工具状态不得与模型文本或输入缓冲区拼接；终端退出后必须恢复光标和样式。
- `/trace` 继续使用同源 Runtime Event 的安全投影，不输出消息正文、完整工具参数、文件内容或 Key。

### FR-210 Headless 输出合同

- `--output text` 的 stdout 只包含最终回答；诊断写 stderr；不得包含 ANSI 控制符。
- `--output json` 的 stdout 是稳定 JSON 对象，至少包含 Session ID、Stop Reason、最终回答和
  经过筛选的运行元数据；诊断写 stderr；不得包含 ANSI 控制符。
- text/json 的稳定退出码区分成功、使用或配置错误、Session 错误和 Runtime 失败。
- v0.2 不承诺 `stream-json` 或原始 Runtime Event 的公共兼容格式。

### FR-211 模块与依赖约束

- CLI Entry Point 只解析启动参数、选择交互/Headless 模式并映射退出码。
- Interactive Application 管理 REPL 生命周期和短暂 UI 状态；不拥有对话历史事实。
- Command Router、Terminal、Presentation、Configuration Resolver 和 Session Catalog 具有明确职责。
- Prompt Toolkit 和 Rich 只能出现在 Terminal/Presentation Adapter；Agent Core、Coordinator、
  Runtime Event 和领域类型不得依赖它们。
- CLI 命令不得直接扫描 JSONL、修改权限内部状态或拼装 Provider 请求。
- 新 seam 必须有真实生产 Adapter 与测试 Adapter，或有明确的本地替身；不为未来插件创建空壳。

## 失败行为

- 未知斜杠命令和非法命令参数不创建 Turn，并给出 `/help` 可发现的修复提示。
- 项目配置试图设置被禁止字段时拒绝该配置，不静默忽略安全问题。
- Session 名称或短 ID 歧义时不恢复任何 Session。
- 恢复修复只处理可证明为最终半行的物理尾部；所有其他结构损坏 fail closed。
- 副作用结果不确定时，不自动重试工具、不伪造成功或失败，也不让模型在错误假设上继续。
- Presentation 失败不得改变 Runtime Event；Headless JSON 序列化失败使用明确非零退出码。

## 验收标准

1. 从 JDAgent 源码仓库之外的真实 workspace 可启动已安装的 `jdagent` 并完成多轮 DeepSeek 会话。
2. 无 Prompt 默认进入交互模式；默认选择 DeepSeek；缺 Key 时不回退 Fake。
3. 多行、历史、`Ctrl+R`、斜杠补全、状态栏和 `/help` 在 Windows Terminal/PowerShell 人工验收通过。
4. 九个内建命令均通过 Scripted Terminal 的完整 REPL 测试，命令文本不会发送给模型。
5. 同一 workspace 可创建、命名、列出和恢复多个 Session；不同 workspace 默认相互隔离。
6. 写审批展示目标和风险；拒绝没有副作用；Session 级允许只匹配批准的规范化范围。
7. 运行中取消返回输入状态并可继续对话；`/exit` 后 Session 可恢复。
8. 强杀测试覆盖完整事件、最终半行、安全未完成 Turn 和副作用不确定 Turn；恢复行为符合 FR-206。
9. text/json 的 stdout、stderr、ANSI、字段和退出码通过子进程合同测试。
10. `jdagent` 与 `python -m jdagent` 的一次性入口行为一致；默认测试只使用 Fake Model。
11. 真实 DeepSeek 流式文本、Tool Call、恢复与取消通过显式 opt-in live test。
12. Core 不导入 Prompt Toolkit、Rich、TOML 路径、JSONL Catalog 或终端类型。
13. 学习者可闭卷解释 CLI 数据流、状态所有权、Session 投影和一次异常恢复分类。

## 非目标

- MCP、RAG、长期记忆、求职领域包和新增真实 Provider
- 全屏 TUI、鼠标交互、Vim 模式和主题系统
- 自定义命令、Skills、Hooks、Plugins、MCP 命令与 shell `!`
- Subagent、多 Agent、后台任务、消息排队、Worktree 和远程控制
- 通用 Session Branch、删除、导出、Checkpoint、文件回滚、Undo 和自动上下文压缩
- `stream-json`、原始事件公共协议和完整自动化 SDK
- 完整 Project Trust 系统、高级沙箱和持久化全局权限规则

## 学习出口

实现完成后，学习者必须完成 [v0.2 学习检查表](../learning/v0.2-learning-checklist.md)。自动测试
不能代替对模块职责、交互状态机、异常恢复和 stdout/stderr 合同的闭卷解释。
