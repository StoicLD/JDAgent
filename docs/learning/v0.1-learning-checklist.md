1. `ToolCallDelta` 如何重建为 `ToolCallCompleted`。
2. Agent Loop 在何时持久化 assistant/tool-call 事件。
3. Tool Runtime 如何依次执行工具查找、JSON Schema 校验、workspace preflight、权限策略和用户审批。

## C. Trace 故障练习

先用 Fake Model 注入一个确定性的模型超时：

```powershell
uv run jdagent --provider fake --fake-delay-seconds 1 `
  --model-timeout-seconds 0.01 --show-trace "diagnose this timeout"
```

只根据输出的 `trace=` JSON 回答：

- [ ] Session ID 与 Turn ID 分别是什么？
- [ ] 最后一个事件为什么是 `turn_failed`？
- [ ] `stop_reason` 为什么是 `model_error`，`error_category` 为什么是 `timeout`？
- [ ] `model_calls` 为什么是 1？超时由 Agent Loop 还是 DeepSeek SDK 分类？
- [ ] 哪些事件已经持久化，可用于 resume？哪些副作用没有发生？
- [ ] 如果去掉 Fake 延迟后使用同一个 Session ID 恢复，ContextBuilder 会从哪里重建消息？

本练习的 Trace 不包含 prompt 正文、工具参数或文件内容。对应自动回归测试为
`test_cli_trace_explains_injected_fake_model_timeout`。

可选对照实验：使用 `--max-context-tokens 1` 注入 Context Limit，比较失败发生在模型调用
前还是模型调用中。不要把这个对照实验代替上面的模型超时必做项。
