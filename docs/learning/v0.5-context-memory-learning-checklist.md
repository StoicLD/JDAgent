## C. 数据流与所有权

闭卷重建五条路径：

1. Turn 开始→指令固定→Recall→预算检查→请求保存→模型/工具→完成。
2. 同一 Turn 到 90%→批次收尾→摘要候选→验证→持久提交→继续。
3. 首次写新目录→发现 AGENTS.md→返回规则且未写→模型重新发起。
4. 新会话首轮结束→筛选历史→提取水位→合并→后续 Turn 召回。
5. 用户停用→有效集合改变→后台遇到旧来源→仍不复活→明确重新启用。

- [ ] 每条路径说明输入、状态变化、事件、输出和停止条件。
- [ ] 指出权威事实、可重建索引、内存投影与 CLI 快照的唯一所有者。
- [ ] 解释执行恢复快照与压缩 checkpoint 的区别。
- [ ] 解释 recovery Session 如何用安全前缀引用续做，为什么不能直接使用父会话最新摘要。
- [ ] 说明 OS Session 独占锁与后台 lease_epoch 分别防止什么，以及源会话重新活跃时怎样处理。
