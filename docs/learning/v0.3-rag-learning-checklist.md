## B. 闭卷模块图与 Interface

必须能区分并画出：

- 学习模块：来源可追踪 RAG
- 产品能力：Augmented-with-boundary Answer
- 代码模块：Catalog、Store、Parser/Chunker、Embedding Adapter、Index Adapter、Preparation、
  ContextBuilder v2、Citation Validator、CLI Use Case

具体 Interface：

- Knowledge Catalog Port（身份/生命周期/Lease；不是 SQLite 文件格式）
- Source Store Port（不可变字节；不拥有 Source Version）
- EmbeddingPort / Knowledge Index Port / 可选 RerankerPort
- Knowledge Provider（单库检索，不融合）
- Turn Knowledge Preparation（冻结 Binding，产出 PTK）
- ModelPort（只生成与一次 Repair）

完成标准：

- [ ] 能区分学习模块、产品能力和代码模块。
- [ ] 能说明 Interface 除类型外还包含不变量、顺序、错误与性能约束。
- [ ] 能说明复杂度为何藏在 Index Adapter / Saga 内，删除后会泄漏到 Core。
- [ ] 能指出外部 seam（Milvus、Embedding HTTP）与不值得公开的内部函数。
- [ ] 能说明 Fake Index 证明了检索合同，而不是为测试发明第二套语义。

## C. 主数据流与状态所有权

1. 正常路径：bind → ingest ACTIVE → user_message → 冻结 Binding → PTK → TRR → 模型 → Citation
   校验 → assistant_message_completed → turn_completed。
2. 边界路径：无 Binding → `NOT_CONFIGURED`；成功空结果 → `INSUFFICIENT`；多库一库失败 → `PARTIAL`。
3. 失败路径：Catalog 损坏 fail closed；Query Embedding 失败只打倒组；Reranker 失败回退。
4. 恢复路径：Lease 过期后 retry/reconcile 恢复同一 operation_id；Replace 失败旧版本可读。
5. 跨模块路径：Citation Resolver 先 Catalog 生命周期再 Store 字节；删除墓碑不重写历史回答。

完成标准：

- [ ] 能闭卷按顺序说明输入、状态变化、Runtime Event、输出和停止条件。
- [ ] 能指出 Catalog、Store、Index、Session、PTK 的唯一所有者。
- [ ] 没有把 Milvus Hit、JSONL 行或 Presenter 短标签误认为领域事实。

## F. 故障实验

1. Milvus 或物理 Collection 缺失（依赖失败）
2. Evidence token 预算耗尽导致 required locator 丢失（预算）
3. Catalog `quick_check` 失败（损坏）与 alias/Catalog 漂移
4. Saga 在 INDEXING 后崩溃；Lease TTL 过期接管
5. Evidence 含“grant ALLOW”注入文本；知识 CLI 不在 Tool Registry

对每个实验：

- [ ] 实验前写出预测、依据和置信度。
- [ ] 只根据测试、Trace、持久事实和输出判断实际行为。
- [ ] 解释预测与结果的差异，并更新心智模型。
- [ ] 区分可以重试、必须降级、需要人工决定和必须 fail closed 的情况。
