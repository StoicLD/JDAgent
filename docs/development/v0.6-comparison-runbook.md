## 实验固定内容

先运行 B1/B2/B3（native/native），再运行 T1/T2/T3（langgraph/langchain）。每个样本使用独立
工作区、会话和产品费用库；六个样本共用一个实验预算库。任务保持同一历史约束、长工具原文、
find_files／search_text／read_file／edit_file／run_command 主线及三个独立算例。
只复制合成夹具的 DATASET.md、notes.txt、prices.py 和 verify.py；只有 prices.py 允许编辑。

模型名必须显式指定；端点只允许固定 DeepSeek 地址。`https://test` 仅供注入假传输的测试使用，
CLI 不会向该地址读取或发送真实 Key。任务配置固定为 64,000 模型窗口、24,000 应用窗口、2,048
最大输出、120 秒模型 timeout、temperature=0、thinking disabled、8 次普通模型／16 次工具额度。
维护关闭，不读取用户全局指令、项目源代码或真实会话。模型仍会收到合成工具文件和请求中出现的
本机 Python／临时工作区路径；这属于应在授权时说明的发送范围。

建议首轮额度为 **96 次外部请求、1,200,000 输入 token、120,000 输出 token，六次合计**。
这是旧 v0.5 三次实验上限的两倍，作为本次待批准上限；并非已获准消费，也不保证每次模型输出都
能在额度内完成。实验发送前按输入估算与最大输出预留，完整 Usage 才结算；未知费用保留预留。
Provider 报告超出预留的实际用量时保留实际值并阻止后续请求，不能撤销已发生的调用。
本次离线标准脚本每个样本 9 个外部请求：6 个任务请求、3 个压缩请求；只产生 1 次压缩提交。

## 准备清单，不调用模型

先提交本阶段代码、测试和文档，确认工作树干净。在产品仓库中执行以下示例；模型名采用当前项目
默认值 `deepseek-v4-flash`，实际实验应在授权时一并确认。prepare 只读取本地版本、依赖与合成夹具，
不读取凭据、不发送 HTTP。

```powershell
.venv/Scripts/python.exe -X utf8 -m tests.v06_comparison prepare tmp/v06-implementation/v06-comparison-live-001 --experiment-id v06-comparison-live-001 --model deepseek-v4-flash --calls 96 --input-tokens 1200000 --output-tokens 120000
```

目录必须不存在；prepare 生成 plan.json、plan.sha256 和 budget.sqlite。plan.json 固定完整 commit、
uv.lock 指纹、Python／平台／可执行文件、已安装包版本及体积、夹具指纹和任务参数。真实调用前
必须核查该文件及授权范围。之后产品 commit、环境、锁文件或夹具变化都会拒绝运行；不能把新
实现的结果混进旧实验。未开始的准备目录也不原地修改，应另建有区别的实验 ID。

## 获准后运行原生基线

只有获得明确付费调用授权后才设置 opt-in。Key 使用 DEEPSEEK_API_KEY 或现有批准的本机开发凭据
路径，不放进命令参数、计划或报告。控制入口要求环境开关和命令行参数同时存在。

```powershell
$env:JDAGENT_RUN_V06_LIVE = '1'
.venv/Scripts/python.exe -X utf8 -m tests.v06_comparison run tmp/v06-implementation/v06-comparison-live-001 B1 --allow-live
.venv/Scripts/python.exe -X utf8 -m tests.v06_comparison run tmp/v06-implementation/v06-comparison-live-001 B2 --allow-live
.venv/Scripts/python.exe -X utf8 -m tests.v06_comparison run tmp/v06-implementation/v06-comparison-live-001 B3 --allow-live
```

每条命令完成后先检查退出码、result.json 和 completion.json。B2 要求 B1 已有可校验的收尾记录，
失败样本也占一次尝试；既有目录不能重跑或覆盖。失败时保留原样本，诊断或新一轮重试另行记录，
不能删除目录或账本恢复额度。基线有任一失败时不能准入目标组。

## 冻结比较判据

三个原生样本全部通过后，依据它们的实际测量填写 criteria-input.json。它是一个对象，必须包含
下列九个键，每个值均为 `{"maximum": 非负有限数值, "basis": "基线数据与上限的理由"}`。
数值不能为空或 NaN；模板中的占位值不能作为真实上限。每个目标样本分别与上限比较，不用平均
成绩掩盖单次遗漏或超限。

| 键 | 单位与测量口径 |
| --- | --- |
| first_text_ms | 从提交任务到第一个可显示 TextDelta；不计压缩输出，包含此前任务处理等待 |
| total_ms | 从提交任务到返回终态；不包含后续收尾和人工检查 |
| startup_ms | CLI 从 Runtime 模块导入前到所选 Runtime 构造完成，包含预检和夹具准备；不含 Python 解释器启动和此前标准库导入 |
| external_calls | 全部实际外部尝试，包含任务、分片压缩、合并和引用修复 |
| input_tokens／output_tokens | 实际 Usage；有未知预留的样本不作为通过的成本基线 |
| tool_calls | Runtime 业务计数，不等同于实际副作用数 |
| tool_execution_starts | 本轮持久化的工具开始事件数；文件变化和命令结果另见 result.json |
| dependency_bytes | 当前环境所有已安装 distribution 清单文件去重后的字节数，不含 pyc／__pycache__ |

两组使用同一个锁定环境，因此 dependency_bytes 通常相同，且包含开发依赖。它不代表新旧版本
安装体积差额，也不能与此前非 editable、无 dev 的安装数字直接比较。`setup_ms` 另记录进程内
准备／构造时间；控制器会拒绝把进程内计时和 CLI 导入计时混用。

```powershell
.venv/Scripts/python.exe -X utf8 -m tests.v06_comparison freeze-criteria tmp/v06-implementation/v06-comparison-live-001 criteria-input.json
```

freeze-criteria 固定计划、三份基线收尾记录的指纹和启动计时口径；生成一次性的 criteria.json。
完成后即不可重新冻结。第一份目标 claim 还会记录该文件指纹，运行目标后修改上限会被拒绝。
收尾测量和 criteria.json 自身均带内容指纹，因此在首个目标出现前修改冻结数值也会被拒绝。
工具只校验记录完整性和数值，不代替维护者对上限依据的判断。

## 目标组与中断

在相同授权总额度内，依次把上述 run 命令中的样本改为 T1、T2、T3。比较失败返回非零退出码；
result.json 保留任务结果，completion.json 记录超出的指标，不能把任务成功直接当作比较通过。
每个样本保留 claim.json、result.json、completion.json、会话／对象／命令输出和工作区结果。
计划或已完成结果被修改、预算库丢失／损坏、尝试乱序、重复尝试、未经授权调用均拒绝准入。

整个执行周期持有进程级 OS 锁；正常取消会写取消结果、保留未知费用并释放锁。如果进程强退在
claim 后、completion 前，可在确认没有运行中的控制进程后记录中断：

```powershell
.venv/Scripts/python.exe -X utf8 -m tests.v06_comparison record-interruption tmp/v06-implementation/v06-comparison-live-001 B1
```

该命令必须取得同一 OS 锁，只补 interrupted 收尾，不再次调用模型、不重置账本、不覆盖已完成记录。
若元数据损坏导致无法核验，保留现场，不能通过手工删除后重跑。后续比较与发布结论仍需独立审查
和[学习清单](../learning/v0.6-langchain-langgraph-learning-checklist.md)要求的本人判断。
