## 安装与回退演练

1. 用 `uv build --wheel --offline` 构建 wheel。在独立虚拟环境用 `uv sync --locked --no-dev --no-install-project` 安装锁定依赖，再用 `uv pip install --no-deps` 安装 wheel。检查包只含产品模块与发行元数据。包中有图执行器和模型响应模块，已移除 `jdagent/core/loop.py`。
2. 从独立环境的 `site-packages` 导入两个模型适配器。该环境无 pytest，验证进程使用独立的配置、数据与工作目录。用安装后的 console script 启动 Fake；其后同时提供旧 CLI 值与用户 TOML 旧值，恢复原会话。命令均返回 0、JSON schema 2、`completed`，第二个进程的 stderr 只提示一次。
3. 复制整个会话目录（含 5 个内容对象及 SQLite 数据）。验证旧进程实际从基准源码导入，在同一工作区打开副本并追加一轮。前两轮共 11 条 schema 4 事件，旧版恢复后共 16 条；原 11 条的字节前缀一致，会话 ID 一致，创建会话一次，完成三轮。原目录逐字节保留原事件日志。此样本覆盖普通文本及请求归档；强退与外部副作用由专门的恢复测试覆盖。

最终安装的 wheel SHA-256 为 `62d96ce297d708bd9860669d90f967ac6a4231effe9f91551072430b4e28fd47`。锁文件 SHA-256 为 `be14a48127c9489382ae632e86334304afb03309eacb6b3d2bce1676868d2516`。额外核对了 wheel 中每个 Python 文件与工作树源码的内容，并用 8 个线程同时首次提交旧配置值，仅收到 1 条迁移提示。

## 回归与耗时

基准完整离线测试为 986 passed、1 failed、3 skipped、11 deselected。失败为 v0.3 的词项 Recall@10，实测 0.8125，门槛 0.85。三个跳过项需要显式启用存储规模测量，排除的测试标记为 integration。
最终完整离线回归为 **759 passed、1 failed、3 skipped、11 deselected**（246.91 秒）。唯一失败为与基准相同的 `test_offline_child_and_ptk_eval_meet_gates`，实测仍为 0.8125。两版都以 `pytest -q -m "not integration"` 运行。去除重复的引擎参数使总例数减少，两个适配器的 MCP 配额与旧会话另有 15 项定向复验通过。Ruff lint、format（380 个文件）及严格 Pyright（0 errors、0 warnings）均通过。

同一主机、同一解释器，分别从原版本与本次源码启动独立进程。使用相同的 FakeModelPort、内存会话和成功的模拟读文件工具。固定脚本发起一次工具调用，然后返回最终文本；模型分别在结束事件之后报告 16/4 和 8/2 个输入／输出 token。每组预热 5 轮，再计 30 轮中位数。时间从进入 Runner 到返回结果，排除解释器和依赖导入。图调度列从每轮总耗时扣除全部节点函数的执行时间，包含构图、编译与节点间调度。

| 运行方式 | 模型调用／工具执行 | 输入／输出 token | Turn 中位耗时 | 图节点以外耗时 |
