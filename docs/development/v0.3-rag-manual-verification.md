# v0.3 RAG 手动验证报告与操作指南

状态：`Proposed`

编写日期：2026-09-13。核对版本：`657ecf53df3254041d17a66e1b130ea2d71c8075`，包版本 `0.3.0`。
本文提供可执行的验证流程，不表示学习者已完成验收，也不代填学习检查表。

命令注释更新：2026-09-16。每条命令上方说明用途及主要副作用；`#` 开头的注释可一起复制执行。
路径变量赋值通常只改当前窗口内存；环境变量还会传给后续子进程。普通对话即便使用 Fake，也会
保存 Session；不带 `--answer` 的诊断脚本只查看检索证据，不生成模型回答。

下文的“查看/不改变资料”指不改变业务内容；程序启动仍可能打开或初始化 Catalog、产生 Python
缓存。这里不会把“没有外部模型请求”等同于“完全没有磁盘写入”。

## 1. 先明确目前能验证到哪一层

建议先花 30–45 分钟完成第 2–5 节，再选做真实模型与故障验证。判断 RAG 成功需要同时看
“检索到了什么、答案用了什么、引用指向哪里”，不能仅看命令退出码或回答是否流畅。

| 层次 | 当前验证入口 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| CLI 管理 | `knowledge connection/kb/source/binding/operation` | 摄取、状态、绑定与来源生命周期 | add/bind 成功不代表默认对话已使用知识 |
| 本地检索证据 | 本文附带诊断脚本，不调用模型 | File Index + HashEmbedding 的检索、父段扩展、来源与 Revision | 真实语义向量质量、Milvus Analyzer |
| 回答与引用 | 同一脚本显式 `--answer` | 本地检索 → 真实 DeepSeek → Citation/Session | 真实 Embedding + Milvus 的完整生产链路 |
| Milvus 接口 | 已有 opt-in Live 测试 | 实际索引写入、可见区间、启停投影 | 测试向量不是语义模型；BM25 仍有 fallback 缺口 |

**当前默认 CLI 的限制**：Connection 不配置 endpoint 时，摄取使用本地索引；默认 Runtime 的
`allow_local_index=False`，因此绑定后普通提问会报告 `unavailable/provider_unavailable`。
`kb create` 目前也没有 Embedding endpoint/model/dimension 参数。不要为这两个缺口反复修改问题或密钥。
本指南显式使用诊断入口观察已实现机制，不把它当作已完成的正式 CLI 能力。

上一轮审查的 `197 passed, 1 failed, 5 skipped` 是 **2026-09-05 的证据**；唯一失败为来源校正后的
词项 Recall `0.8125 < 0.85`。2026-09-13 核对 Git 确认修复已提交为 `657ecf5`，旧快照 129 个文件
在忽略 CRLF/LF 差异后均一致。本文未重跑整个历史验收套件。

## 2. 建立独立实验环境

在一个新的 PowerShell 窗口执行。以下 `$Rag...` 变量要在同一窗口保留。

```powershell
# 切换到产品仓库；仅改变当前终端的工作目录。
Set-Location -LiteralPath 'E:\Projects\Codex_Projects_Overall\JDAgent\JDAgentProject'
# 查看当前提交 ID，记录验证基线；不修改仓库。
git rev-parse HEAD
# 查看未提交变更；不修改文件或提交。
git status --short
# 没有 .venv 或缺少依赖时先执行；已安装可跳过。
# 按锁文件安装依赖；可能联网下载，并创建或调整 .venv，不更新锁文件。
uv sync --frozen
# 记录仓库路径供后续命令使用；只设置当前窗口变量。
$RagRepo = (Get-Location).Path
# 指定仓库虚拟环境中的 Python；只保存路径，不运行程序。
$RagPython = Join-Path $RagRepo '.venv\Scripts\python.exe'
# 指定配套诊断脚本路径；只保存路径，不运行脚本。
$RagProbe = Join-Path $RagRepo 'docs\development\examples\rag_manual_probe.py'
# 生成唯一实验目录路径；此行只计算路径，不创建文件。
$RagLab = Join-Path ([IO.Path]::GetTempPath()) ('JDAgent-RAG-Manual-' + [guid]::NewGuid().ToString('N'))
# 计算实验 workspace 路径；此行不创建目录。
$RagWorkspace = Join-Path $RagLab 'workspace'
# 创建实验 workspace 及所需父目录；会在临时目录写入目录项，隐藏命令输出。
New-Item -ItemType Directory -Path $RagWorkspace | Out-Null
# 将后续子进程的用户配置根目录指向实验区；仅影响当前窗口及其子进程。
$env:APPDATA = Join-Path $RagLab 'config'
# 将后续子进程的知识库和会话数据根目录指向实验区；不迁移原有数据。
$env:LOCALAPPDATA = Join-Path $RagLab 'data'
# 让后续 Python 进程采用 UTF-8 模式；不转换现有文件。
$env:PYTHONUTF8 = '1'
# 设置当前控制台输出编码，方便显示中文；不修改文件。
[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
# 设置 PowerShell 向外部程序传文本的编码；只影响当前窗口。
$OutputEncoding = [Console]::OutputEncoding
# 定义后续使用的命令简写；定义本身不运行 JDAgent、不写业务数据。
function Invoke-RagCli {
    # 转发参数并固定使用实验 workspace；实际副作用由每次传入的子命令决定。
    & $RagPython -m jdagent --workspace $RagWorkspace @args
}
# 打印已安装的 JDAgent 版本；不创建知识库或会话。
& $RagPython -m jdagent --version
```

预期版本为 `jdagent 0.3.0`。所有实验 Catalog、原文对象和 Session 均进入 `$RagLab`。
单独换 `--workspace` 只隔离 Binding/Session；Catalog 是用户级共享的，`--data-dir` 也不单独
隔离知识存储，因此这里同时设置 `APPDATA/LOCALAPPDATA`。关闭该实验窗口即可丢弃环境变量变更。

先做无知识库基线：

```powershell
# 运行一次离线 Fake 对话并解析 JSON；会保存实验 Session，不请求模型服务。
$RagBaseline = Invoke-RagCli --provider fake --output json '你好' | ConvertFrom-Json
# 展开显示基线结果；只输出到终端，不另存文件。
$RagBaseline | ConvertTo-Json -Depth 10
```

通过条件：`schema_version=2`、`status=success`、`knowledge.outcome=not_configured`、`citations=[]`。
`Offline fake model response.` 是固定回答，不理解你的问题，不能用于判断答案正确性。

## 3. 导入、绑定与直接查看检索结果

先只导入一份材料，方便确认来源身份。使用副本，后续替换不修改 Gold 文件。

```powershell
# 记录 Gold 样本目录；只保存路径，不修改样本。
$RagGold = Join-Path $RagRepo 'testdata\v0.3-gold\sources'
# 计算实验政策文件路径；此行不创建文件。
$RagPolicy = Join-Path $RagWorkspace 'zh-leave-policy.md'
# 复制政策到实验区；写入目标副本，同名目标可能被覆盖，Gold 原件不变。
Copy-Item -LiteralPath (Join-Path $RagGold 'zh-leave-policy.md') -Destination $RagPolicy
# 注册无 endpoint 的实验 Connection，保存返回 ID；写入实验 Catalog，不连接外部服务。
$RagConnection = Invoke-RagCli knowledge connection add --name manual-local | ConvertFrom-Json
# 创建实验知识库，保存返回 ID；写入 Catalog 元数据，尚未导入资料。
$RagKb = Invoke-RagCli knowledge kb create --connection $RagConnection.connection_id --name manual-rag | ConvertFrom-Json
# 导入政策并保存 ID；写入原文、解析快照、本地索引和操作记录，激活新的 Revision。
$RagAdded = Invoke-RagCli knowledge source add --kb $RagKb.knowledge_base_id --file $RagPolicy --operation-id manual-add-policy | ConvertFrom-Json
# 授权实验 workspace 使用该知识库；持久写入 Binding，影响后续 Turn 的检索范围。
$RagBinding = Invoke-RagCli knowledge binding add --connection $RagConnection.connection_id --kb $RagKb.knowledge_base_id | ConvertFrom-Json
# 查看知识库当前 Revision、Generation 和绑定数；不改变资料内容或绑定。
Invoke-RagCli knowledge kb status --id $RagKb.knowledge_base_id
# 查看来源身份、状态和当前版本；不执行导入或启停。
Invoke-RagCli knowledge source list --kb $RagKb.knowledge_base_id
# 查看这次导入的阶段与错误码；不执行重试。
Invoke-RagCli knowledge operation status --id $RagAdded.operation_id
```

通过条件：首次 `revision=1`；来源 `lifecycle=active`，`current_version_id` 等于导入返回的
`source_version_id`；operation 的 `saga_stage=active`；KB 的 `binding_count=1`，Generation 非空。
后续 ID 均使用返回值，不复制旧实验的 ID。

验证重复摄取和 retry 的幂等性：

```powershell
# 重导入同一份未改动资料，检查幂等性；本例预期不新增来源、版本或 Revision。
Invoke-RagCli knowledge source add --kb $RagKb.knowledge_base_id --file $RagPolicy
# 重试已成功的导入，检查幂等性；本例预期直接返回原结果，失败操作的 retry 则可能继续写入。
Invoke-RagCli knowledge operation retry --id $RagAdded.operation_id
# 查看知识库当前 Revision、Generation 和绑定数；不改变资料内容或绑定。
Invoke-RagCli knowledge kb status --id $RagKb.knowledge_base_id
```

预期来源/版本与 revision 都不增加。对首次成功的 operation 执行 retry，只证明已完成操作幂等，
不证明任意崩溃都能自动修复。

直接观察实际检索证据：

```powershell
# 执行本地 BM25 诊断并保留结果；读取原文证据，不调用模型，不新增 Session 或来源版本。
$RagBefore = & $RagPython $RagProbe $RagWorkspace '全职员工年假是多少天？' --mode bm25 | ConvertFrom-Json
# 展开显示证据和预算；只输出到终端。
$RagBefore | ConvertTo-Json -Depth 16
# 将检索证据保存为 before.json；写入实验目录，重复执行会覆盖同名证据文件。
$RagBefore | ConvertTo-Json -Depth 16 | Set-Content -LiteralPath (Join-Path $RagLab 'before.json') -Encoding UTF8
```

预期 `outcome=complete`，Evidence 的 `parent_text` 包含“入职满一年”“15 天”；核对：

- `source_name=zh-leave-policy.md`，`source_id/source_version_id` 与导入返回一致；不能只核对 Locator。
- `locator` 为 Markdown 结构定位，`bases[].revision=1`；Reference 属于本次 Turn。
- `budget.evidence_tokens <= budget.evidence_token_limit`，父段数量不超过预算；上限来自当前 Profile。
- `hit_count` 是候选数量，`selected_evidence_count` 是选入上下文的数量，两者不必相等。

脚本的 `--mode bm25/dense/hybrid_rrf` 只覆盖本次诊断的冻结 Profile，不更改 Catalog。可分别运行三次
观察差异；HashEmbedding 不是语义向量，Dense 能返回文本不等于召回正确。

再观察正式 CLI 的当前边界：

```powershell
# 用默认 Runtime 发起 Fake 对话；会保存新 Session，当前预期知识不可用，不请求模型服务。
$RagDefault = Invoke-RagCli --provider fake --output json '全职员工年假是多少天？' | ConvertFrom-Json
# 只显示上一步返回的知识状态；不再发起查询或写文件。
$RagDefault.knowledge | ConvertTo-Json -Depth 10
```

当前预期是 `unavailable`，base 的 `failure_reason=provider_unavailable`。这是已知功能缺口，
在记录表写“按当前实现复现限制”，不要写“正式 RAG 问答通过”。

## 4. 验证多格式、答案来源与无答案问题

```powershell
# 依次处理三份样本；循环内会复制文件并摄取，每个新来源增加一次 Revision。
foreach ($RagName in @('finance-stipend.md', 'mixed-faq.md', 'employees.csv')) {
    # 计算当前样本的目标路径；只更新内存变量。
    $RagFile = Join-Path $RagWorkspace $RagName
    # 复制当前样本到实验区；写入或覆盖目标副本，Gold 原件不变。
    Copy-Item -LiteralPath (Join-Path $RagGold $RagName) -Destination $RagFile
    # 摄取当前样本；写入内容对象、本地索引和 Catalog，新增来源并激活 Revision。
    Invoke-RagCli knowledge source add --kb $RagKb.knowledge_base_id --file $RagFile
}
```

把下列问题替换进 `& $RagPython $RagProbe $RagWorkspace '问题' --mode bm25`，先看原文证据，再在
第 6 节启用模型后人工核对回答。单库多格式便于入门；Gold 的多库切片另见第 7 节。

| 问题 | 预期事实/来源 | 人工判定 |
| --- | --- | --- |
| 全职员工年假是多少天？ | 满一年后 15 天，休假政策 | 保留适用条件，不只回答一个数字 |
| 连续病假超过几天需要医院证明？ | 超过 3 天，休假政策 | 不把年度累计上限 30 天混入 |
| What is the VPN hostname? | `vpn.example.internal`，Mixed FAQ | Hostname 必须来自原文 |
| Who is on call on Tuesday? | Bo，Mixed FAQ 表格 | 已知质量薄弱题；未召回即记失败 |
| Which employees are in Beijing? | Ada Liu、Cara Ng，CSV | 必须覆盖两行，不漏人或混入 Shanghai |
| What does Ada Liu own according to notes? | retrieval and citations，CSV 多行字段 | 换行字段不能截断 |
| Summarize leave days and meal stipend. | 15 天 + 80 CNY，两个来源 | 两项分别有正确来源支持 |
| What is the pet insurance copay? | 材料没有答案 | 回答应承认缺少依据，不能编造费用/引用 |

`complete` 仅表示查询完成并选入 Evidence，不是“这些 Evidence 足以回答问题”。尤其无答案题在
Hybrid 下也可能得到不相关候选；要检查答案是否错误地把候选当作支持。

提示注入可选实验：再导入 Gold 的 `injection.md`，询问
`How many annual leave days do full-time employees get?`。预期模型不服从资料中的指令，事实来自
休假政策；跨语言未召回应单独记“检索失败”，不能只据最终回答推断模型抵抗注入成功。

## 5. 验证替换、停用、重新启用和删除

此节只操作 `$RagPolicy` 副本。完成第 6 节原版问答后再做本节，可保存替换前后的回答作比较。

### 5.1 替换与确认要求

```powershell
# 读取实验政策，在内存中把 15 天改为 18 天；此行尚未修改文件或知识库。
$RagText = [IO.File]::ReadAllText($RagPolicy).Replace('15 天', '18 天')
# 将修改后的文本覆盖写回实验政策文件；知识库仍保持旧版，直到显式替换。
[IO.File]::WriteAllText($RagPolicy, $RagText, [Text.UTF8Encoding]::new($false))
# 尝试未带 --yes 的替换；预期拒绝并报错，不激活新版本。
Invoke-RagCli knowledge source replace --kb $RagKb.knowledge_base_id --file $RagPolicy
# 显示刚才外部命令的退出码；预期为 2，只读取状态。
$LASTEXITCODE
```

预期退出码 `2`，stderr 包含 `confirmation_required`；重跑诊断仍为 15 天，revision 不变。
不能因为原始文件内容已经修改，就认为已摄取内容也自动改变。

```powershell
# 确认替换并保存返回 ID；写入新版本与索引，切换当前版本，Revision 增加 1。
$RagReplaced = Invoke-RagCli knowledge source replace --kb $RagKb.knowledge_base_id --file $RagPolicy --yes | ConvertFrom-Json
# 查看当前可见的本地原文证据；不调用模型，不新增 Session，也不改变来源版本。
& $RagPython $RagProbe $RagWorkspace '全职员工年假是多少天？' --mode bm25
```

通过条件：`source_id` 不变、Version 改变、revision 增加 1；当前政策证据为 18 天，不混入旧版本。
替换按文件名定位来源，改名后传给 replace 会找不到原来源。

### 5.2 停用与重新启用

```powershell
# 停用实验来源；关闭当前可见区间、更新 Catalog/Revision，保留已有内容对象。
Invoke-RagCli knowledge source deactivate --kb $RagKb.knowledge_base_id --id $RagAdded.source_id
# 查看来源身份、状态和当前版本；不执行导入或启停。
Invoke-RagCli knowledge source list --kb $RagKb.knowledge_base_id
# 查看当前可见的本地原文证据；不调用模型，不新增 Session，也不改变来源版本。
& $RagPython $RagProbe $RagWorkspace '全职员工年假是多少天？' --mode bm25
# 尝试重新启用来源；停用状态下会写入索引投影并增加 Revision，已删除时预期拒绝。
Invoke-RagCli knowledge source reactivate --kb $RagKb.knowledge_base_id --id $RagAdded.source_id
# 查看当前可见的本地原文证据；不调用模型，不新增 Session，也不改变来源版本。
& $RagPython $RagProbe $RagWorkspace '全职员工年假是多少天？' --mode bm25
```

停用后 Evidence 中不得出现该 `source_id`；其他资料可能仍命中，因此不要硬性要求 outcome 必为
`insufficient`。启用后只恢复当前的 18 天版本，不能同时恢复 15 天旧版。可再重复一轮。

新诊断总是读取当前 Revision；旧 Turn 的历史区间不变需要第 7 节专项回归证明。
保存的 `before.json` 可比较原始 Version，但它本身不是历史 Citation 打开功能的证明。

### 5.3 删除最后做

```powershell
# 尝试未带 --yes 的删除；预期拒绝，不删除内容或改变来源状态。
Invoke-RagCli knowledge source delete --kb $RagKb.knowledge_base_id --id $RagAdded.source_id

Invoke-RagCli knowledge source delete --kb $RagKb.knowledge_base_id --id $RagAdded.source_id --yes
# 尝试重新启用来源；停用状态下会写入索引投影并增加 Revision，已删除时预期拒绝。
Invoke-RagCli knowledge source reactivate --kb $RagKb.knowledge_base_id --id $RagAdded.source_id
```

预期删除返回 `lifecycle=deleted`；reactivate 报 `not_found`；新检索不含该来源。
**这只能验收检索排除和墓碑**：当前索引尚无来源级物理 purge，旧索引文本/向量可能保留。
历史 Citation Resolver 尚未贯通到真实来源打开界面，不能把此处通过算成“物理删除/历史引用全部通过”。

解除 Binding 后再用普通 CLI 提问，应该恢复 `not_configured`：

```powershell
# 解除实验 workspace 的授权关系；持久删除 Binding，不删除知识库和资料。
Invoke-RagCli knowledge binding remove --id $RagBinding.binding_id --yes
# 运行解绑后的离线 Fake 对话；保存新 Session，预期 not_configured，不请求模型服务。
Invoke-RagCli --provider fake --output json '你好'
```

## 6. 选做：真实回答和 Citation（在删除/解绑前执行）

只设置 DeepSeek Key 即可运行这一层；本地摄取/检索仍使用 HashEmbedding + File Index。
不需要为这一步安装 Milvus。先在实验窗口配置 `DEEPSEEK_API_KEY`，不要把值放进报告。
脚本沿用 Configuration 的 model/base URL；如需更改，在实验 workspace 的 `.jdagent/config.toml`
配置 `model` 和 `base_url`。下面 Live 测试专用的环境变量不等于普通配置入口。

```powershell
# 检索并请求真实 DeepSeek 回答；发送问题和选中证据、消耗 Token，并保存新 Session。
$RagAnswer = & $RagPython $RagProbe $RagWorkspace '全职员工年假是多少天？请说明适用条件并引用资料。' --answer | ConvertFrom-Json
# 显示已取得的答案与引用；不再次调用模型、不另存文件。
$RagAnswer | ConvertTo-Json -Depth 20
# 将答案、引用和证据保存为 answer.json；写入实验目录，重复执行会覆盖同名文件。
$RagAnswer | ConvertTo-Json -Depth 20 | Set-Content -LiteralPath (Join-Path $RagLab 'answer.json') -Encoding UTF8
```

这条命令会调用真实服务并产生 Token 用量；脚本关闭了工具，只走检索—生成—引用路径。
`diagnostic_ptk` 是诊断额外字段，含 Evidence 原文和预算；不是新增的正式 Headless 合同。

通过条件：

1. `status=success`，`stop_reason=completed`，`knowledge` 显示成功 base，`citations` 非空。
2. `answer` 中事实与 `diagnostic_ptk.evidence[].parent_text` 一致；执行替换前应为 15 天，替换后为 18 天。
3. 回答中的引用序号能映射到 `citations[].ordinal`；Citation 的 Source/Version/Locator 与本次 Evidence 对应。
4. `model_supplement` 如有内容，应与有来源的答案分开判断；不能把无依据补充视为资料事实。
5. 无答案题不编造有来源的结论。建议对关键题运行三次，保存三次结果，分别记正确/错误，不能只保留最好一次。

验证同一 Session 新 Turn 重新准备知识：

```powershell
# 继续已有 Session 提问；重新检索、发送本轮输入给 DeepSeek、消耗 Token，并追加会话事件。
& $RagPython $RagProbe $RagWorkspace '连续病假超过几天需要医院证明？请引用资料。' --answer --session-id $RagAnswer.session_id
```

预期沿用 Session ID、生成新 Turn ID；不要复用上次机器 Reference。也可以保存同一 Session 的
替换前后回答，核对当前 Turn 使用新 Version。仅凭历史会话文字仍出现旧数字不能认定索引泄漏，
要对照本次 PTK 与 Citation。

## 7. 故障、Eval 与 Live 的补充验证

### 7.1 可直接用 CLI 验证的失败

在删除/解绑前，用下列场景补充记录；每次失败后重查 KB revision 和原版检索。

| 操作 | 预期 | 不应发生 |
| --- | --- | --- |
| 将 `source add --file` 指向不存在的实验文件 | `not_found`、退出码 2，revision 不变 | 原有来源消失 |
| 先改副本内容，再对同名文件执行 add 而非 replace | `name_conflict` | 默默覆盖旧版本 |
| 新建第二个 KB，用其 ID 停用第一个 KB 的 Source ID | `not_found`，两库状态保持原状 | 跨库变更来源 |
| 同一个成功 operation 连续 retry 两次 | 同一 Source/Revision | 重复生成新版本 |

运行 `operation status --id ...` 可观察失败阶段；不要在真实数据上主动篡改 SQLite 或中断写入来模拟
崩溃。索引写一半、旧 retry 回退、Embedding 失败使用已有确定性故障测试观察，避免不可控实验。

后一命令当前预期仍有一个 Recall 门禁失败。标准 Gold 使用 32 维 HashEmbedding，而上面的 CLI

需要逐题数据时运行下列代码；文件保存到新的实验子目录：

```powershell
# 把下面的 Python 文本交给解释器运行；会在实验区新建 Gold 评测数据与 scores.json，不调用模型。
@'
# 加载异步、JSON 和参数处理模块；为后续评测准备工具。
import asyncio, json, sys
# 加载数据类转换工具；将评分记录转成可保存的字典。
from dataclasses import asdict
# 加载路径工具；此行不创建目录。
from pathlib import Path
# 加载项目的离线评测入口；此行尚未运行评测。
from jdagent.knowledge.eval_gold import run_retrieval_eval
# 计算实验目录下的 gold-eval 路径；此行不写文件。
root = Path(sys.argv[1]) / 'gold-eval'
# 新建评测目录；已存在时直接报错，避免复用旧评测数据。
root.mkdir(exist_ok=False)
# 运行完整离线 Gold 检索；写入新评测目录中的 Catalog、对象和备份，索引在内存中。
child, ptk = asyncio.run(run_retrieval_eval(root))
# 将逐题分数整理成字典；只改变内存数据。
payload = {'child': [asdict(x) for x in child], 'ptk': [asdict(x) for x in ptk]}
# 保存逐题评分 JSON；写入 scores.json，同名文件会被覆盖。
(root / 'scores.json').write_text(json.dumps(payload, ensure_ascii=False, indent=2), encoding='utf-8')
# 依次计算每类 Child 指标；只处理本次内存评分。
for metric in sorted({x.metric for x in child}):
    # 选出当前指标的各题得分；不发起检索或修改文件。
    rows = [x.actual for x in child if x.metric == metric]
    # 打印当前指标的平均分；仅输出到终端。
    print(metric, sum(rows) / len(rows))
# 打印最终证据覆盖的平均分；仅输出到终端。
print('ptk', sum(x.actual for x in ptk) / len(ptk))
# 打印评分文件路径，方便打开查看；不再次写入文件。
print(root / 'scores.json')
'@ | & $RagPython - $RagLab
```

重点检查 Q021、Q060、Q070、Q080 的失败来源和 Locator；当前完整 Gold 的 Hybrid/PTK 分数高于
词项分数，不能据此替代失败门槛。Citation Eval 仍是目标覆盖代理，不是回答主张的完整语义判定。
