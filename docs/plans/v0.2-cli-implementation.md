状态：`Approved`

## 当前状态

- v0.1 工程、真实 DeepSeek 和人工学习出口已完成。
- v0.2 需求、CLI 架构和 ADR-0004 已批准。
- M0 文档基线与 v0.1 收尾已于 2026-08-20 完成。
- 尚未开始 v0.2 产品代码；当前 CLI 行为仍是 v0.1 基线。

## 实施原则

- 每个里程碑先固定可观察合同和失败测试，再实现最小行为。
- 复用现有 Turn Coordinator、Agent Loop、Runtime Event、Fake Model 和权限边界，不建立第二套循环。
- 先完成无真实终端依赖的应用 seam，再接入 Prompt Toolkit 与 Rich。
- 默认测试不调用 DeepSeek；真实 Provider 测试保持显式 opt-in。
- 强杀与 I/O 窗口使用确定性故障注入，不依赖随机时序证明正确性。
- 事实与投影分离：Runtime Event 和 Session 生命周期事实可重建 Catalog，UI 状态不进入事实流。
- 迁移不删除 v0.1 Session；任何自动修复保留原始证据。
- 每个里程碑都包含学习说明：接口、状态所有权、失败模式和最小实验。

## 里程碑

### M0 文档基线与 v0.1 收尾

- 正式记录 v0.1 M10b 完成与最终验收。
- 批准 v0.2 需求、CLI 架构、ADR、实施计划和学习检查表。
- 更新当前状态、README、Agent 地图和文档索引。
- 退出条件：权威文档对 v0.1 最终完成与 v0.2 已批准、未实现的状态描述一致；链接检查通过。

### M1 CLI 合同、配置与 Headless 基础

- 定义启动模式、`UserAction`、`ExitStatus`、`--version`、稳定退出码和 text/json 输出 Schema。
- 实现 Configuration Resolver：用户/项目 TOML、优先级、来源定位、未知字段与安全字段限制。
- 默认 Provider 切换为 DeepSeek；保留显式 Fake。
- 实现 Key 优先级：环境变量、用户级 `api_key_file`、源码开发文件回退。
- 将入口收敛为薄 Composition Root；不接入 Prompt Toolkit/Rich。
- 命名测试：`test_configuration_precedence_is_cli_project_user_default`、
  `test_project_config_cannot_set_provider_url_or_key_file`、
  `test_missing_deepseek_key_never_falls_back_to_fake`、
  `test_headless_json_stdout_is_machine_parseable`。
- 退出条件：从源码树外可运行已安装入口；配置和 Headless 合同完全离线可验证。

### M2 Session 生命周期事实与 Catalog

- 定义 Session 名称、workspace 身份、创建/更新时间和状态投影。
- 扩展规范事件或明确等价的生命周期事实，使名称不依赖文件名或不可重建索引。
- 实现 Session Catalog 用例：list、resolve、rename、current status。
- 处理名称/短 ID 歧义，不静默选择。
- 将 Session 用户数据按规范化 workspace 身份分区；处理 Windows 路径语义。
- 设计并实现 v0.1 `.jdagent/sessions` 的只读发现或非破坏性导入，迁移前后均保留原文件。
- 命名测试：`test_catalog_rebuilds_from_session_facts`、
  `test_session_selector_reports_ambiguous_name`、
  `test_workspaces_do_not_share_default_session_listing`、
  `test_legacy_session_import_never_deletes_source`。
- 退出条件：删除 Catalog 索引后可重建相同 Session 列表和名称；Runtime `SessionPort` 保持窄接口。

### M3 物理与逻辑异常恢复

- 将恢复判断实现为可独立测试的分类逻辑，不散落在 CLI 条件分支。
- 支持“完整前缀 + 最终半行”的备份、截尾和警告；中间损坏继续 fail closed。
- 识别无终止事件的逻辑未完成 Turn。
- 未越过副作用边界时，记录明确的进程中断失败事实并允许继续。
- 写副作用可能已发生但结果缺失时，阻止自动继续并提供从最后安全 Turn 建立恢复 Session 的出口。
- 在实现恢复 Session 持久表示前，比较父引用、事件复制与显式恢复快照，固定 provenance 和
  ContextBuilder 行为；不得把该出口扩展为通用 branch。
- 命名测试：`test_recovery_backs_up_and_truncates_only_partial_tail`、
  `test_recovery_rejects_corruption_before_final_line`、
  `test_incomplete_turn_before_side_effect_is_closed_as_interrupted`、
  `test_uncertain_write_side_effect_blocks_automatic_resume`。
- 退出条件：恢复分类对每种故障给出唯一、可解释结果；原始损坏或不确定 Session 均保留。

### M4 Permission Session Rule 与审批视图

- 定义具体文件/目录的规范化 Session Rule，受用户级权限上限约束。
- 审批请求增加安全目标摘要、风险和允许范围；不输出完整文件正文或秘密。
- 实现拒绝、本次允许、当前 Session 窄范围允许。
- Session Rule 随 Session 生命周期结束，不成为永久项目配置。
- 命名测试：`test_session_rule_matches_only_normalized_approved_target`、
  `test_project_config_cannot_relax_user_permission_ceiling`、
  `test_approval_view_redacts_file_content_and_secrets`、
  `test_session_rule_does_not_leak_to_another_session`。
- 退出条件：批准范围外的写操作仍然 ASK/DENY，Terminal 不持有旁路白名单。

### M5 Interactive Application 与 Scripted Terminal

- 实现 `STARTING/IDLE/RUNNING_TURN/WAITING_APPROVAL/RUNNING_TOOL/CANCELLING/EXITING`
  交互状态机。
- 实现有类型的 Prompt、Command、Cancel、EOF 和 Exit Action。
- 实现 `/help`、`/status`、`/new`、`/sessions`、`/resume`、`/rename`、`/permissions`、
  `/trace`、`/exit` 的 Command Router 和用例分发。
- 先使用 Scripted Terminal 与 Capture Presenter 驱动完整 REPL，不引入真实终端依赖。
- 运行中拒绝不安全的 Session 切换；Turn 级错误返回 `IDLE`。
- 命名测试：`test_repl_routes_commands_without_sending_them_to_model`、
  `test_repl_returns_to_idle_after_turn_error`、
  `test_resume_is_rejected_while_turn_is_running`、
  `test_exit_keeps_session_resumable`。
- 退出条件：Fake Model 加 Scripted Terminal 可重复覆盖完整交互主循环和所有命令。

### M6 Prompt Toolkit Terminal 与 Rich Presentation

- 接入 Prompt Toolkit 的 `PromptSession`、多行、历史、`Ctrl+R`、斜杠补全、快捷键和 bottom toolbar。
- 接入 Rich 的角色、Markdown、工具状态、审批、警告和错误呈现。
- `Enter` 提交、`Alt+Enter` 换行，多行粘贴保持单 Prompt。
- 处理 Runtime Event 与输入缓冲区并发显示，避免流式文本、工具状态和 Prompt 拼接。
- Terminal `close()` 幂等并恢复光标、颜色和输入模式。
- 命名测试：使用 Prompt Toolkit 测试输入/输出替身覆盖按键与重绘；不以截图作为唯一断言。
- 退出条件：Windows Terminal/PowerShell 中完成多轮、审批、取消、历史、补全和正常退出人工验收。

### M7 取消、信号与进程生命周期

- 将运行中 `Ctrl+C` 接入现有 Coordinator/Agent Loop cancellation。
- 区分运行中取消、空闲退出、EOF、`/exit` 和操作系统关闭信号。
- 协作式关闭尽力追加终止事实并恢复终端；强杀只依赖持久化与恢复合同。
- 为子进程加入只在测试启用的确定性同步点，覆盖关键 kill 窗口。
- 命名测试：`test_ctrl_c_cancels_turn_and_repl_remains_usable`、
  `test_forced_kill_after_user_event_recovers_as_interrupted`、
  `test_forced_kill_after_write_effect_marks_session_uncertain`、
  `test_terminal_state_is_restored_on_exit`。
- 退出条件：取消不触发额外工具副作用；四类强杀场景符合需求 FR-206。

### M8 Headless 与真实入口合同

- 完成 `--output text`、`--output json`、stdout/stderr 和退出码合同。
- 验证 `jdagent` 与 `python -m jdagent` 等价；交互 Rich 输出不污染 Headless。
- 添加真实安装后的源码树外 workspace 子进程测试。
- 明确 v0.2 JSON 字段版本和兼容范围；不暴露 raw Runtime Event。
- 命名测试：`test_console_script_and_module_entrypoint_are_equivalent`、
  `test_text_stdout_contains_only_final_answer`、
  `test_json_output_has_no_ansi_or_secret`、
  `test_cli_runs_outside_source_checkout`。
- 退出条件：测试和脚本可稳定消费输出，诊断不会破坏 stdout。

### M9 工程门禁、Live 验收与独立评审

- 运行 Ruff format/check、Pyright strict、默认离线全量测试。
- 显式 opt-in 运行 DeepSeek 流式文本、Tool Call、恢复与取消测试。
- 在 Windows Terminal/PowerShell 按人工验收矩阵完成真实 workspace 主循环。
- 固定待评审 revision 或显式工作树快照，请求独立 Standards/Spec 评审。
- 修复并验证阻塞 finding；记录无法覆盖的真实终端和 OS 信号风险。
- 退出条件：全部需求验收标准有可复现证据，正式评审无未处理 blocker/high。

### M10 人工学习出口

- 学习者闭卷画出 CLI Entry、Configuration、Interactive Application、Terminal、Presentation、
  Coordinator、Runtime、Session Catalog 与 Store 的依赖方向。
- 口述 Prompt、斜杠命令、Tool Approval、取消和 Headless 的五条数据流。
- 使用 Trace 与 Session 事实区分物理尾部损坏、逻辑未完成 Turn 和副作用不确定 Turn。
- 解释为什么 Prompt Toolkit/Rich 类型不能进入 Core，以及 Catalog 索引为何不是事实源。
- 退出条件：完成 [v0.2 学习检查表](../learning/v0.2-learning-checklist.md)，未知项诚实进入后续版本。

## 测试矩阵

| 层次 | 主要对象 | 正常路径 | 失败与中断 |
| --- | --- | --- | --- |
| 纯逻辑 | Command、Config、Selector、Recovery、Permission | 解析、合并、匹配 | 未知、歧义、禁止字段、不确定副作用 |
| 本地 Adapter | JSONL、Catalog、历史、TOML | 写入、重建、迁移 | 短写、fsync、半行、中间损坏、索引丢失 |
| 应用 | Scripted Terminal + Fake Model | 多轮、命令、审批 | 模型/工具错误、拒绝、取消、非法状态切换 |
| 真实 CLI | console script、`python -m` | text/json、源码树外启动 | stderr、退出码、缺 Key、坏配置 |
| 真实终端 | Prompt Toolkit + Rich | 多行、历史、补全、状态 | Ctrl+C、EOF、重绘、终端恢复 |
| 进程 | 子进程故障同步点 | 正常退出/恢复 | 强杀、物理半行、逻辑半 Turn、不确定写 |
| Provider | DeepSeek opt-in | 流式文本、Tool Call | 取消、超时、认证与分类错误 |

## 人工验收路径

1. 从非 JDAgent 源码项目目录运行已安装的 `jdagent`。
2. 创建多轮 Session，使用多行、历史、补全和 `/status`。
3. 审批一次文件写入，并验证 Session 级范围不会扩大。
4. 运行中取消一次模型生成，再继续同一 Session。
5. `/exit` 后使用 `/sessions` 和 `/resume` 恢复。
6. 在安全点和写副作用不确定点分别强制关闭子进程，验证不同恢复行为。
7. 使用 text/json 模式完成可重复脚本测试。
8. 完成 M10 学习出口。
