## 实施原则

- 每个里程碑先固定可观察合同和失败测试，再实现最小行为。
- 复用现有 Turn Coordinator、Agent Loop、Runtime Event、Fake Model 和权限边界，不建立第二套循环。
- 先完成无真实终端依赖的应用 seam，再接入 Prompt Toolkit 与 Rich。
- 默认测试不调用 DeepSeek；真实 Provider 测试保持显式 opt-in。
- 强杀与 I/O 窗口使用确定性故障注入，不依赖随机时序证明正确性。
- 事实与投影分离：Runtime Event 和 Session 生命周期事实可重建 Catalog，UI 状态不进入事实流。
- 迁移不删除 v0.1 Session；任何自动修复保留原始证据。
- 每个里程碑都包含学习说明：接口、状态所有权、失败模式和最小实验。

### M4 Permission Session Rule 与审批视图（完成）

- 前置门禁：冻结 `ApprovalOutcome` 与 `SessionPermissionRule` 的精确 Payload、事件 Schema、撤销语义
  和路径解析失败行为。
- 定义具体文件/目录的规范化 Session Rule，受用户级权限上限约束。
- 审批请求增加安全目标摘要、风险和允许范围；不输出完整文件正文或秘密。
- 实现拒绝、本次允许、当前 Session 窄范围允许。
- 用户权限上限是 `ASK | DENY`，项目配置只能收紧；Session Rule 不得覆盖 `DENY`。
- Session Rule 作为 Session 事实持久化；`/exit` 后恢复同一 Session 时继续有效，可查看、可撤销，
  但不会泄漏到另一 Session，也不成为永久项目配置。
- 命名测试：`test_session_rule_matches_only_normalized_approved_target`、

## 人工验收路径

1. 从非 JDAgent 源码项目目录运行已安装的 `jdagent`。
2. 创建多轮 Session，使用多行、历史、补全和 `/status`。
3. 授予一次窄范围 Session 写规则，验证范围不会扩大；`/exit` 后恢复同一 Session，确认规则仍
   有效并通过 `/permissions` 撤销，再确认新 Session 不继承该规则。
4. 运行中取消一次模型生成，再继续同一 Session。
5. `/exit` 后使用 `/sessions` 和 `/resume` 恢复。
6. 在安全点和写副作用不确定点分别强制关闭子进程，验证不同恢复行为。
7. 使用 text/json 模式完成可重复脚本测试。
8. 完成 M10 学习出口。
