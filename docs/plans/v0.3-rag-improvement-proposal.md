# v0.3 RAG 工程补齐与检索质量改进方案

状态：`Proposed`

日期：2026-09-05

依据：[本轮实现审查与修复](../reviews/REV-20260905-001-v0.3-implementation-audit.md)、
[已批准高层设计](../architecture/v0.3-knowledge-retrieval.md)、[P1/P2 范围](v0.3-rag-p1-p2-appendix.md)。
本方案不改变已有批准状态，不自动授权下一版本、依赖新增或数据迁移。

## 1. 要解决的问题

保留现有 Runtime 与 Port 方向，先让 v0.3 满足三个可实测结果：

1. 用户按文档配置真实 Embedding 和 Milvus 后，可完成 add → bind → ask → 核验历史 Citation。
2. Replace、Deactivate、Reactivate、Delete、崩溃重试不会混入错误版本，且能说明是否已完成物理清理。
3. Eval 按正确来源和支持关系计分，完整报告失败、成本与回归；通过才宣称验收完成。

不建议当前替换整个 Agent Runtime 或直接引入大型 RAG 框架。现有事件、权限、Session 与 Knowledge
边界值得保留；本轮普通 Runtime 离线回归已有证据。主要工作是补齐边界内的正确性和真实运行路径。

## 3. 分阶段方案

### A：先补数据生命周期与恢复（最高优先级）

对应发现 F01–F03、F07–F10。本轮的安全保护是起点，不是全部退出条件。

- 把 Source Version、Parsed Snapshot、Generation、Revision Manifest 分开保存。Snapshot 派生身份含
  Source Version、Parser Profile 和 Locator Schema；兼容性变化生成新 Generation。
- 使用持久 Manifest 记录每个操作固定的输入对象、旧/新版本、预期 Chunk 集及 Profile 指纹。
  重试从 Store 重建缺失写入，不重新读取可能已经变更的用户文件，不创建第二个 Source Version。
- Catalog 在一个事务里激活 Revision、Source current_version、生命周期和操作完成状态；重试必须
  校验期望旧指针或明确处理已激活状态。保持全局单 Writer，不提前引入分布式锁。
- Delete 先排除并墓碑，再幂等删除该来源所有索引投影、零引用 Raw/Snapshot 对象；三者确认后才
  标记 DELETED。共享对象继续保留。删除重试不因已经完成的一部分清理而误报来源损坏。
- Lease 使用不同进程 owner、定时续期与明确接管；Reconciler 按操作的真实 Connection 选择 Index/
  Embedding，不统一写入 File Index。损坏 Catalog 禁止 GC。
- 提供可检查的重建计划，列明受旧 Chunk ID 覆盖影响的来源；验证备份和新 Generation 后再切换。
- 同库多个遗留 pending 要先生成冲突诊断与修复计划；逐条验证索引区间及当前指针后恢复，不能绕过
  现有保护后直接 retry。跨库遗留操作已有串行恢复回归覆盖。

退出条件：六个摄取阶段前后中断、部分批量写入、删除中断、旧操作重试、新写入接力均可确定性复现；
旧 Turn/新 Turn 可见集合符合冻结 Revision；已删除来源没有可恢复的索引文本/向量；原文共享引用不误删。
所有失败实验通过后再执行真实服务实验。原始目录/索引清除属于单独的可审查操作。

### B：补一条用户可配置的真实 RAG 路径

对应 F11/F12。先完成一个 Provider，不扩展更多框架。

- CLI 显式创建并查看 Embedding/Retrieval Profile：endpoint、model、dimension、normalization、
  timeout、batch；用户能确认自己使用真实向量还是离线测试适配器。
- 在 Composition Root 解析 env/file credential_ref，分别交给对应 Provider；缺失凭证为
  ACCESS_DENIED，错误脱敏。普通无 Binding Agent 不读取凭证、不导入/连接 Milvus。
- 固定一组实际通过测试的 Milvus Server/PyMilvus 版本，验证 Analyzer fixtures、BM25 Function、
  HNSW 与 Revision 预过滤；生产路径移除隐式词频替代，显式暴露不兼容/不可用。
- 统一 Adapter 异常、有限重试、超时与连接关闭。同步 SDK I/O 需要可取消的 Adapter 隔离，取消后
  不留下未经等待的后台写入。
- 基础 wheel 与 rag extra 分别在源码树外安装，执行创建、摄取、提问、恢复流程；不要让测试专用
  `allow_local_index=True` 成为用户真实配置的替代品。

退出条件：clean-env 按文档一次走通真实 Embedding + Milvus + DeepSeek；没有 RAG extra、服务断开、
错误凭证、单库失败时仍能普通对话，并保留逐库稳定错误。Live 显式开启后依赖缺失不能以 skip 冒充通过。

### C：完成历史原文与回答的核验路径

对应 F10/F15。

- Resolver 输入 Citation 的 Source Version、Snapshot、Locator 和 hash，先检查 Source 墓碑，再
  读取并校验对应历史 Artifact；返回可打开、已删除、损坏三种明确状态。
- Parent Evidence 从 Store 校验加载；索引只提供候选和关联 ID。保存 Parent Locator/覆盖范围，
  使“注入整段、只引用某个 Child”的关系可核验，避免仅按 Locator 字符串猜覆盖。
- 为 CLI 增加只读来源查看入口，恢复会话中的 Citation 能打开当时引用的版本。
- Citation Repair 复用标准模型调用的预算、超时、取消、Usage、finish_reason 和错误映射；仍最多
  一次，不重新检索、不启用 Tool。补充无 Evidence、跨 Turn、畸形引用、supplement 引用与中间工具轮次测试。

退出条件：替换后旧引用打开旧内容；删除后墓碑不打开正文；篡改/缺失对象不会显示为可核验来源；
Repair 故障不会破坏 Session 终止事件与调用预算。

### D：修复评测协议，再证明质量达标

对应 F06/F14。本轮已加入来源身份，原门槛保持不变。

- 明确区分 Child 精确命中、Parent 扩展覆盖、Citation 目标合法性与回答主张支持；分别报告。
- Gold 使用允许的 Source Version/Locator 或明确等价来源集合。Q040 的“至少一个近重复来源”需
  机器可执行的 OR 关系，不能因为 required 为空而自动满分。
- unanswerable 错误支持率以无答案子集为分母；多证据题报告全部必需证据保留率；按中文、英文、
  CSV、跨语言、多库、长 Parent 报告，不用总体均值掩盖失败切片。
- 保存三次正式生成的逐题/逐次结果、聚合、配置指纹、模型、时间和 Usage；使用固定中位数协议。
  第一版主张支持用人工固定标注/判据，不默认增加在线 LLM Judge。
- 针对 Q021/Q060/Q070/Q080 做失败分析；在真实 Embedding + BM25 上跑三模式对照。Hash Fake 只
  证明流程与不变量，不能证明跨语言召回。不要为满足测试而给 Fake 塞答案或修改 Gold 含义。

退出条件：既有 0.85/0.75 Recall/PTK、0.90/0.85 Citation、0.05 无答案错误支持率及 Hybrid 回退限制
逐项满足；所有失败样本可审计。若需要重定义哪一个模式承担发布 Recall 门禁，应由正式设计复审决定，
不能在本轮把 BM25 门禁偷偷改成较高的 Hybrid 分数。

### E：通过消融再选检索增强

先落实全局预算与每库 Profile 的独立所有者；保持同一 Turn 冻结、每库一次检索、每 Profile 一次
Query Embedding。Bindings 重排不能改变全局预算。

第一组实验只比较三个变量，分开运行：

| 实验 | 对照 | 收益判据与代价 |
| --- | --- | --- |
| Parent 扩展 | 整 Parent、命中周围结构窗口、按父子命中比例扩展 | 提升长 Parent 和表格的 Final PTK Coverage；记录 Token 与丢弃原因，不破坏原文 Locator。 |
| 全局 Cross-Encoder | Hybrid 与 Hybrid+一次 Rerank | 沿用 nDCG 增益 ≥0.03、Recall 下降 ≤0.02；记录耗时、失败回退与真实模型身份。 |
| Chunk Overlap | 无、固定、仅强制切分 | 比较 Recall、重复率、Evidence 预算占用及索引规模，不只看召回均值。 |

Query Rewrite、Agentic RAG、代码/网页检索 Tool、额外格式、长期记忆和 Compaction 保持原 P2/
后续版本边界。指定 Claude Code 仓库的有界读取与失败提示可借鉴；其 Agent 工具式探索不能直接替代
本项目 v0.3 明确的每 Turn 一次知识准备。

## 4. 交付顺序与回归要求

建议 A → B → C → D → E；D 的确定性计分器和失败样本整理可与 A 同时推进，真实质量验收依赖 B/C。
每个增量固定可审查的工作树或 revision，先给失败用例，再修复，再回归。每阶段至少检查：

- 普通无 Binding 对话、工具/权限、Session 创建/恢复、未知 schema、取消与 Headless v2。
- 旧来源与冻结 Revision、替换/删除失败、单库故障、多 Profile、秘密脱敏、所有客户端关闭。
- Ruff、Pyright、完整离线测试；需要真实服务的变更补对应 Live 和安装验证。

现有失败测试必须显式报告。新方案获得批准不等于工程或学习出口通过；独立复核由未参与对应实现
的人/Agent 对固定产物执行，人工学习检查表仍由学习者本人完成。
