# v0.8 改造规格与实施计划 · LangGraph 作为唯一 Turn 执行引擎

状态为 `Implemented`。实际工程结果与人工学习状态见[验证记录](../development/v0.8-langgraph-verification.md)。下文保留实施前的需求与验收条件。2026-11-19。代码基准为 `9d7cbdc136e2034416b3190fe409f8660bb04202`。项目所有者已选定单引擎方向，并确认以真实 CLI 和 TurnRunner 两个入口验收。旧配置处理、实施顺序及各项具体预期为本次提案。

## 要解决的问题

用户输入一次会触发一个 Turn。当前默认的原生 `AgentLoop` 和可选的 `LangGraphTurnRunner` 都解释模型响应、执行工具、处理取消并保存终态。学习者要读两条主线才能解释同一行为。维护者改一条规则，要同时维护两套调度和两套引擎的组合测试。上一轮架构审视建议共享模型响应规则；所有者现在选择退出原生执行引擎，双引擎之间的共享需求随之消失。

## 目标与使用体验

在 v0.8 中，用户直接运行 JDAgent，每个需要执行的 Turn 都由现有自建 LangGraph StateGraph 调度。正常输入、显式 MCP Prompt、交互 CLI 与 Headless 使用同一条主线。管理知识库、查询原 MCP Task、继续后台维护等本来不启动 Turn 的操作仍各走自己的入口。

模型接入由独立的 `ModelPort` 负责。DeepSeek 继续支持 `model_adapter=native|langchain`，默认值为 `native`；Fake 可用于离线执行。一次执行可以同时使用 LangGraph 调度和原生 DeepSeek 适配器。会话继续使用现有事件和对象保存，无需转换用户数据。新读者从 Coordinator 进入图，能沿节点找到请求、工具和终态。

## 用户故事

1. 作为新用户，我希望直接输入问题就能通过 LangGraph 得到回答，以便省去执行引擎的配置步骤。
2. 作为现有用户，我希望已有 CLI 命令和受支持的用户配置能完成升级，并说明要删去哪一项设置，以便逐步清理脚本。
3. 作为自动化调用方，我希望继续得到单份 Headless JSON、原退出码与字段含义，以便原有解析脚本继续工作。
4. 作为 DeepSeek 用户，我希望能分别选择原生与 LangChain 适配器，以便控制模型如何接入。
5. 作为离线开发者，我希望 Fake 也通过真实图调度，以便在本地重现工具调用和模型失败。
6. 作为工具用户，我希望同批调用按顺序经过已有校验与审批，以便每个外部动作都能与原调用配对。
7. 作为交互用户，我希望取消会等待已开始的清理，并能继续当前会话，以便知道哪些工作确实发生过。
8. 作为恢复会话的用户，我希望旧会话按既有规则继续或隔离未知副作用，以便避免重复执行一次写入或命令。
9. 作为 MCP 用户，我希望进程重开后仍能查询原 Task；直接 Prompt 仍能发起 Turn，以便区分查已有任务和开始新工作。
10. 作为知识与记忆用户，我希望引用修复、请求归档、记忆意图和压缩仍可追溯，以便核对模型看到的材料。
11. 作为预算管理者，我希望模型调用、工具调用、观察到的失败和费用按既有口径记录，以便对照升级前后的执行成本。
12. 作为维护者，我希望 23 类已知响应场景有独立的预期结果，以便删除原生实现后仍能发现行为漂移。
13. 作为学习者，我希望从入口只追踪一种调度实现，并从一份会话解释成功、失败与恢复，以便自行定位问题。

## 实施决策

### 运行时及状态所有权

| 归属 | v0.8 职责 |
| --- | --- |
| 宿主、组合根与 TurnCoordinator | 选择模型适配器、持有资源、取得会话、记录输入、准备本轮知识。需要 TurnRunner 时直接构造 LangGraph 实现；将仍含 AgentLoop 的工厂名、注解和导入改成与职责一致的名称。 |
| TurnRunner 与 StateGraph | 保留项目自己的 Turn 输入、结果、取消令牌和限额合同。图按轮持有状态，负责请求准备、消费模型流、引用修复、保存回答、逐个执行工具、成功或失败收尾。沿用已有普通响应和修复响应的分支。无需为已退出的第二个引擎再引入公共判定框架。 |
| ModelPort、ContextService、ToolRuntime | 模型消息转换、预算与压缩、工具可见性与审批分别由既有模块处理。图节点调用这些模块。前台、压缩、引用修复及维护继续经既有模型调度与计量路径。 |
| EventJournal、SessionRecovery、MCP | 会话事实持久化后才通知观察者；重启后依据已保存事实恢复。图状态只在本次执行中有效。MCP 管理读取原 Task；图不自动重放工具、不重启远端业务。 |

交付形态为一个生产 TurnRunner 实现。删除原生循环、执行引擎选择分支及对旧循环模块的间接导入。保留仍被应用与测试使用的框架无关合同。顺序执行、业务限额、图步数保护、取消后的资源关闭、追踪隔离、无持久图 checkpoint 和无副作用节点自动重试，均属于必须保留的行为。

### 旧配置与入口迁移

以下是建议采用的 v0.8 兼容策略。它把兼容代码限制在输入处，使旧脚本有一个版本的迁移时间。

| 输入或入口 | v0.8 预期行为 |
| --- | --- |
| 省略执行引擎设置 | 使用 LangGraph，无迁移提示；教程和新配置采用此写法。 |
| CLI 或用户 TOML 显式写 `native` 或 `langgraph` | 两个旧值均解析为唯一的 LangGraph。提示删除旧参数或配置；原来显式选 `native` 的提示须说明实际执行引擎发生了变化。只向 stderr 提示，同一进程去重，逐轮重读配置时不刷屏。 |
| 未知值、类型错误或项目级 TOML 写 `runtime_engine` | 继续按使用或配置错误处理。启动时发现则返回退出码 2，无模型调用或工具执行；运行中重读遇到错误仍走现有配置错误路径。 |
| `--model-adapter native`、`--model-adapter langchain` | 均有效。显式 `native` 指模型适配器时不触发引擎迁移提示。模型适配器、Provider、端点的重启要求继续生效。 |
| 管理命令、内嵌调用及重载 | 分开验证 CLI 的全局参数分派、知识子命令、维护入口、直接组合根和 Turn 间重载。只解析 CLI 的命令沿用其原有配置读取范围。进入组合根后无可变的引擎选择，也无引擎切换或失败回退。 |

v0.8 帮助将旧选项标为兼容项。下一次破坏性版本变更时再决定移除解析入口。原生引擎内部 Python 类的直接导入随实现退出；仓库中所有当前调用方一并迁移。固定历史 revision 的复现实验按原版本运行。v0.8 不得把兼容输入下运行的图引擎记作 v0.6 的 native 基线。

## 测试与验收决策

**已确认两个验收入口。主入口为配置解析和真实组装后的 CLI，故障入口为 TurnRunner。** 用临时 workspace 运行交互和 Headless，对照用户可见输出、退出码和保存的 Session。保留现有 `TurnRunner.run` 合同测试作为补充，用 Fake 模型与工具精确注入半截流、取消和故障。适配器验证沿用真实适配器加本机假 HTTP 的方式。只验证公开可观察行为；“产品包中原生实现与选择分支已移除”另做结构检查。

| 编号 | 场景与通过条件 |
| --- | --- |
| A1 唯一执行路径 | 无参数、两个旧值、Fake、交互、Headless 和直接 MCP Prompt 均走图。发布包仅含一套生产执行实现。帮助与升级说明使用单引擎表述。 |
| A2 兼容输入与协议 | 分别验证 CLI、用户及项目配置、非法值、重载和模型适配器选择。旧脚本的 stdout 可直接解析为 schema 2 JSON；提示位于 stderr；退出码、审批与状态命令行为符合原合同。 |
| A3 模型响应 | 将 23 类差分场景转为固定输入和独立预期。逐项核对请求、事件类型与载荷顺序、TurnResult、工具调用次序、显示流。普通流重复结束应失败；引用修复允许既有重复 stop、最多一次且禁用工具；保留结束之后到达的用量记录。 |
| A4 工具、限额与失败 | 覆盖跨轮重复调用 ID、合批顺序、权限拒绝、目录指令触发重规划、业务限额与图步数、未知副作用停止。取消时关闭模型流或等待工具收尾。持久化失败向上报告；终态已保存后观察者报错不得再写第二个终态。 |
| A5 恢复与格式 | 用当前版创建的会话与现有固定历史样本，覆盖正常恢复、压缩后的历史、断电或强退、未知写入隔离与原 MCP Task 查询。会话 schema 4、对象引用与会话目录沿用原合同；同一业务工具不因恢复而重发。另验证上一稳定版本能读取新版本生成的代表性会话副本，作为回退证据。 |
| A6 两个适配器与领域链 | 固定图引擎，分别通过两个真实 DeepSeek 适配器加假 HTTP 驱动组装后的运行时。覆盖成功与错误、流关闭、Token/费用、前后台资源关闭、知识引用及删除、记忆、MCP 配额和会话恢复。Fake 单列。原四组合的每项行为都映射到新用例或有证据的历史档案。 |
| A7 可维护性与发行 | 用户能从默认 CLI 追到唯一图执行实现与一条终态事件。构建并安装 wheel 后在干净环境完成 Fake 首轮、旧配置启动、正常恢复及两个适配器导入。Ruff 检查及格式、严格类型和完整离线套件记录结果；逐项区分已知失败与新增回归。 |

## 分阶段实施计划

| 顺序 | 实施工作 | 本阶段退出条件 |
| --- | --- | --- |
| 0 · 固定基线与决策 | 记录改动前 revision、依赖锁、配置、已有失败与历史兼容夹具。列出缺省入口、直接构造、合同转引、参数化测试、强退子进程和历史实验。准备后续 ADR，说明替代 ADR-0008 的双引擎与四组合条款，并保留其余已批准约束。 | 23 类场景和其他专属原生测试均有归属；确认旧数据样本及回退用版本。计划与 ADR 的批准状态可查。 |
| 1 · 将差分变为合同 | 两套实现还在时，对同一输入核对结果，固定 A3 的五类可观察输出。为时间、随机 ID 等波动值建立可重复的比较规则。补回原先只靠“双实现相等”才能发现的差异。 | 独立预期在改动前两套实现上通过；至少证明改变结束信号或工具顺序会被断言捕获。 |
| 2 · 迁移启动与配置 | 组合根固定构造图执行器；兼容入口规范化旧参数；模型接入保留独立选择。将 CLI 的取消令牌等转引迁回公共合同，梳理配置重载和命令分派。 | A1、A2 的行为检查通过；普通用户已能按新路径启动；模型适配器的 `native` 仍有效。 |
| 3 · 退役原生实现 | 迁移现行测试工厂、故障注入和 MCP 强退子进程，再删除原生循环。将四组合改为图引擎 × 两个适配器，逐项保留特有断言；固定旧代码的夹具生成器和 v0.6 比较实验标明历史入口，阻止新版本生成伪 native 基线。 | 对生产包和当前测试消费者的导入检查通过；旧会话样本的字节与摘要未被重写；A3、A4、A6 通过。 |
| 4 · 验证与发布准备 | 完成 A5、A7；按同一模型适配器、同一脚本、相同设置比较新旧版的逻辑调用、用量和延迟，单列图调度耗时。更新 README、配置参考、架构、模块地图、当前状态、测试索引和迁移说明。 | 有安装、恢复、双适配器、全量离线和回退演练记录；新增差异已处置。记录性能测量条件与结果，历史阈值未通过的项目单列。 |
| 5 · 交付与学习 | 提交独立工程评审。由学习者画出一次“输入 → 工具 → 回答”的图，预测取消时的事件，并用 Trace 解释为什么重启后可以查原任务。随后做闭卷解释与延迟复测。 | 工程验收和人工学习分别记录；状态文档注明版本、证据与尚待处理事项。 |

各批次应能独立评审。若在切换中发现重复副作用、会话不可读、用量丢失、终态重复或模型适配器误选，停止继续推广，保留会话和原始证据。发布前可撤回该批代码；已部署时结束当前进程，保留数据副本，使用已验证可读该格式的上一稳定构建重启并按原会话恢复规则处理。单次失败不在另一引擎上自动重跑。若旧版本读取副本失败，暂停降级并保留现场。

## 范围以外
