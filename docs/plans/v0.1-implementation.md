## 实施原则

- 每个里程碑先编写失败测试或可执行验收，再实现最小行为。
- 默认测试只使用 Fake Model，不访问网络、不消耗真实 API。
- 先建立窄契约和可工作的 Fake/InMemory Adapter，再实现消费这些契约的 Agent Loop。
- v0.1 发布前的内部接口可以通过评审演进；不使用空实现假装契约已经稳定。
- 每个阶段产生可观察事件，并由学习者解释入口、状态变化、失败和退出条件。
- 当前里程碑未通过前，不提前引入后续机制。

## 里程碑

### M0 Python 工程基线

- 确认 package/distribution 命名。
- 建立 `src` layout、测试目录、uv 依赖和 Ruff/Pyright/Pytest 配置。
- 固化 Python 3.11 补丁版本、格式、Lint、严格类型和离线测试命令。
- 只创建后续 M1 必需的最小包入口，不创建未经批准的业务空壳。
- 退出条件：格式、Lint、类型和空测试命令可重复运行，包可被测试环境导入。

### M1 领域类型、全部 Ports 与可工作 Fake

- 实现 `ModelRequest`、`ModelEvent`、`ModelCapabilities`、`ModelErrorCategory` 和 `ModelPort`。
- 实现 `StopReason`、分层 Tool/Session 错误、Runtime Event Schema v1、`SessionPort`、`ToolRuntimePort`、`ApprovalPort` 和 `RuntimeEventSink`。
- 实现脚本化 `FakeModelPort`、`InMemorySession`、Fake Approval 和最小 Fake Tool Runtime；它们必须真的记录输入并返回可配置结果。
- 不在本阶段实现 Agent Loop、文件工具或 JSONL。
- 命名测试：`test_fake_model_replays_scripted_events`、`test_in_memory_session_preserves_event_sequence`、`test_fake_approval_records_request`。
- 退出条件：所有端口可由测试 Adapter 独立驱动，领域/Core 测试不导入真实 Provider SDK、文件系统或 CLI。

### M2 Session 投影与薄 ContextBuilder

- 完成 Runtime Event Schema v1 的 typed payload 和内存追加/读取语义。
- 实现从规范事件投影聊天消息的纯函数。
- 实现薄 `ContextBuilder`：组合 System Prompt、Session 投影和 ToolDefinition，进行确定性排序、能力前置校验和硬上下文限制判断。
- 本阶段不做压缩、摘要、记忆或 RAG；超过硬限制必须明确失败，不得静默丢历史。
- 命名测试：`test_context_builder_builds_request_from_session_projection`、`test_context_builder_rejects_hard_limit_without_dropping_history`。
- 退出条件：相同事件序列总能生成相同 `ModelRequest`，不存在由 Agent Loop 临时拼 Provider 请求的必要性。

### M3 Tool Registry、WorkspacePathResolver 与三个工具

- 实现工具定义、注册、查找、JSON Schema 校验和统一 `ToolResult`。
- 实现集中式 `WorkspacePathResolver`，使用 real path 与操作系统原生包含关系，处理不存在的写目标父目录。
- 实现 `calculator`、workspace 限定的 `read_text_file` 和 `write_text_file` Handler；此时通过 Fake Policy/Approval 驱动。
- 命名测试：`test_workspace_resolver_rejects_parent_escape`、`test_workspace_resolver_rejects_symlink_escape`、`test_tool_runtime_rejects_invalid_arguments_before_handler`。
- 退出条件：未知工具、非法参数、Handler 异常和路径逃逸均形成稳定 `ToolResult`，并在副作用前失败。

### M4 PermissionPolicy 与 ApprovalPort

- 实现纯 `PermissionPolicy`，输出 `ALLOW`、`ASK` 或 `DENY`。
- 将 `ASK` 交给 `ApprovalPort`；先使用 Fake Approval，CLI Adapter 留到 M6。
- 权限请求、决定和拒绝结果使用规范 Runtime Event；拒绝结果可返回模型。
- 命名测试：`test_write_tool_does_not_run_before_approval`、`test_denied_tool_never_calls_handler`、`test_approval_rejection_returns_tool_result`。
- 退出条件：未经批准的写操作没有文件副作用，越界路径不因用户批准而放行。

### M5 Agent Loop

- 在已有 Model、Tool Runtime、Permission、Session 和 Context 契约上实现小型循环。
- 覆盖文本响应、一个及多个串行 Tool Call、重复 call ID、模型调用上限、工具调用上限、取消和稳定停止原因。
- Loop 不执行 Schema 校验、路径解析、审批交互、JSONL 序列化或 Provider 请求拼接。
- 命名测试：`test_agent_loop_completes_text_turn`、`test_agent_loop_completes_serial_tool_round_trip`、`test_agent_loop_stops_when_cancelled`、`test_agent_loop_classifies_model_timeout`、`test_agent_loop_stops_at_call_limit`。
- 退出条件：普通回答、工具闭环、取消、模型超时和失控循环都能从规范事件与 `StopReason` 解释。

### M6 CLI + Fake + InMemorySession 垂直切片

- 建立 Composition Root，只负责配置与依赖组装。
- 实现 Turn Coordinator，负责一次 Turn 的 Session 输入、Loop 调用、最终事件和 `StopReason` 返回；每轮请求构造仍由 Loop 委托 ContextBuilder。
- 实现 CLI 输入输出与交互式 Approval Adapter。
- 接入基础 Trace 投影，但 Trace 只消费规范事件，不创建第二套事实。
- 命名测试：`test_cli_fake_vertical_slice_completes_tool_round_trip`、`test_cli_rejected_write_has_no_side_effect`。
- 退出条件：仅用 Fake Model 和 InMemorySession，从 CLI 输入到工具结果、最终回答和 Trace 的端到端 happy path 可重复运行。

### M7 JSONL Session 与 resume

- 实现 UTF-8、每行一个 Runtime Event 的 append-only JSONL Adapter。
- append 使用进程内锁并在完整行写入、flush、`fsync` 后才成功；v0.1 不支持多进程 writer。
- reader 验证 Schema、Session、sequence 和每一行；损坏尾部返回带偏移的 `corrupt_event`，不得静默截断或自动修复。
- 实现新建、加载、事件重放和 CLI resume。
- 命名测试：`test_jsonl_round_trip_preserves_events`、`test_jsonl_reader_rejects_partial_final_line`、`test_resume_rebuilds_context_from_events`。
- 退出条件：进程重启后恢复消息、工具、权限和停止原因；所有损坏数据 fail closed。

### M8 预算、取消、超时、Usage 与 Trace 强化

- 加强模型调用、工具调用、上下文和时间预算，统一取消传播。
- 为模型调用和工具执行设置明确超时边界；工具超时转换为可返回模型的 `ToolResult`。
- 记录安全的 Usage、耗时、调用次数、审批结果和停止原因。
- 命名测试：`test_tool_runtime_returns_timeout_result`、`test_model_timeout_records_turn_failure`、`test_cancellation_propagates_without_extra_side_effect`、`test_trace_projects_same_runtime_event_ids`。
- 退出条件：取消、模型超时、工具超时和各类上限都有确定结果、无额外副作用且 Trace 可解释。

### M9 DeepSeek opt-in Adapter

- 本阶段开始前确认 DeepSeek model ID、base URL、能力假设和测试预算。
- 接入官方兼容 API，转换请求、流式文本、Tool Call、Usage 和 `ModelErrorCategory`。
- 加入显式 opt-in 集成测试；默认测试仍完全离线。
- 命名测试：离线协议测试覆盖 Chunk 重建和错误映射；真实测试使用单独的 `integration` 标记并默认跳过。
- 退出条件：真实普通回答和真实 Tool Call 闭环通过，不在日志、快照、事件或失败输出中保存凭据。

### M10a 工程验收闸门

- 运行格式、Lint、严格类型、单元测试和默认离线集成测试。
- 显式 opt-in 后运行 DeepSeek 集成测试。
- 验证恢复、取消、上限、模型/工具超时、权限、workspace 边界和秘密清理。
- 固定待评审 revision 后请求 Cursor 独立评审，处理阻塞 finding 后才可将实现状态升级。
- 退出条件：需求验收标准与命名测试均有可复现证据，正式评审无未处理阻塞项。

### M10b 人工学习出口

- 学习者闭卷画出 CLI、Coordinator、ContextBuilder、Agent Loop、ModelPort、Tool Runtime、Permission、Session 和 Trace 的关系。
- 学习者解释一次 Tool Call 从模型流到权限、副作用、Session 和下一轮请求的完整数据流。
- 学习者根据 Trace 定位一次注入的模型超时、工具超时或损坏 Session，并说明恢复边界。
- 退出条件：解释与实际代码/事件一致；记录仍不理解的机制，作为 v0.2 学习输入，而不是用自动测试替代人工理解。

## 测试矩阵

| 边界 | 正常路径 | 失败与中断 |
| --- | --- | --- |
| Model | 文本、单/多 Tool Call、Usage | 无效流、认证、限流、超时、上下文过长、取消 |
| Tool | 三工具成功、串行调用 | 未知、非法参数、异常、超时、重复 call ID |
| Permission | `ALLOW`、批准的 `ASK` | `DENY`、拒绝的 `ASK`、未批准无副作用 |
| Workspace | 根内现有读目标、根内新写目标 | `..`、绝对越界、symlink/junction 逃逸 |
| Session | 新建、追加、恢复、重放 | 部分写入、坏行、坏尾、版本与 sequence 冲突 |
| Loop | 正常停止、工具闭环 | 用户取消、模型/工具上限、模型错误、内部错误 |
| Trace | 同源事件、Usage、耗时、停止原因 | 不得成为恢复源，不得泄漏秘密 |

## 明确延后

MCP、RAG、长期记忆、上下文压缩、Shell、网络、浏览器、爬虫、Subagent、多 Agent、Task DAG、后台任务、Cron、Worktree 和 Web UI 不进入 v0.1。
