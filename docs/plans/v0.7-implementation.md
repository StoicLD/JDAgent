## P1c 容量与关键词检索的工程默认值

以下数值属于本次实现选择，可用 RuntimeOptions 的 MCPDirectoryLimits 注入小容量验证；不是新增用户已批准数字，
也尚未开放为 TOML 配置项。目录原文不进入 RAG 或 Embedding 服务。

| 项目 | 默认值与计量 |
| --- | --- |
| 目录条目 | 每 Session 最多 2,000 项；获准条目和被隔离条目计入装载预算 |
| 目录元数据 | 8 MiB；按获准条目的规范 JSON UTF-8 字节计量，被隔离条目的已检查定义仍保守计费 |
| BM25 索引 | 4 MiB；每条目 128 字节，加每个不同词项的 UTF-8 字节数及 72 字节开销；计量是确定的容量单位，不声称等于解释器实际堆大小 |
| 构建暂存 | 一次只构建一个 Server 的目录，使用同样的条目／元数据／索引上限；确认能容纳后才淘汰其他 Server 的缓存 |
| 分页与目录等待 | 每类最多 20 页；重复 cursor 中止并标 partial；每 Server 整份目录准备至多 30 秒，连接自身仍受 15 秒约束 |
| 检索 | 非空查询最多 512 字符；每页 1–20 条，默认 10 条；支持 Server 和能力类型过滤、offset 分页 |
| 分词与排序 | 英文大小写归一、下划线／camelCase 拆分；汉字单字及相邻二字词项；BM25 k1=1.2、b=0.75，分词结果随目录缓存 |

固定样例来自 tests/fixtures/mcp_stdio_server.py，验收通过 TurnCoordinator 执行：
“搜索 仓库”首位为 search；“repository files”首位为 read；“repository”可分两页返回二者；
“查询工单”无匹配，改写为“read”后命中；Prompt“explain”可单独检索。
未启用的 write 从不进入候选。以上只验证这些固定样例，不据此宣称通用召回率。
小容量验证同时覆盖：整体淘汰／指定 Server 重载、超大单目录不驱逐其他有效目录、元数据和索引拒绝、分页不完整。

## P2a：模型工具调用与原文闭环

- native 与 LangGraph 都通过 `search_tools` 选择能力，完整定义只进入下一次 ModelRequest；同一 Session 下一 Turn 复用。
  第二层默认最多 16 个定义、8,192 个保守估算 token；待装载队列只保留身份，最多 8,192 字节。
  估算沿用未校准时的 UTF-8 字节代理，并计入完整目录定义、模型工具名及固定开销；不是模型实测 token。
  本批次引用仍计入已加载集合，新选择在请求之间替换；单槽测试覆盖同批次猜名拒绝、旧定义继续执行及下一请求淘汰。
- 请求归档保存宿主来源、Server／代次、原名、定义摘要。执行以该请求曝光的 Schema 校验，并再次检查当前配置与连接。
  MCP 的 path／cwd／args 不进入本地目录发现；本地工具仍使用原有规则。过长模型工具名使用稳定摘要，路由保留原名。
- 普通 `tools/call` 使用 SDK 公开 send_request，避开高层隐含发现和无界缓存。
  `mcp_invocation_started` 在可能发送前持久化调用身份、参数摘要及原文预留；`mcp_invocation_finished`
  保存已确认／未确认事实、受限结果与原文引用。两类事件加入当前 schema 4，新读取器仍接受原有 schema 4 事件。
  发现结果也在保存前登记容量预留，其空 Server ID 与 mcp_control 来源表明这是宿主目录投影，不代表远端业务发送。
- 默认每 Session 原文配额 100 MiB；普通调用保守预留 2 MiB + 16 KiB，覆盖规范 JSON 的序列化膨胀与余量。
  接收时每 RPC 的 1 MiB 硬限保持原值。确认保存后按原文字节计量，未确认调用保留预留；本切片未做原文去重计费。
  配额不足在普通业务发送意图之前拒绝。控制记录不依赖剩余原文配额。
- 原文使用现有不可变对象存储；搜索结果与普通工具结果只把来源、原文引用和预览放入模型结果。

## P2b：Resources、Prompts 与内容类型

- 组合根在资源／模板开关启用时提供四个模型工具：list_mcp_resources、read_mcp_resource、
  search_mcp_prompts 和 get_mcp_prompt。两个 Runner 使用相同实现。模板目录、资源目录分页不读取正文；
  Prompt 的 BM25 候选由模型决定是否获取，不把检索命中直接当作采用。
- 必填 Prompt 参数在 prompts/get 发送前检查，缺失项由正常对话澄清；关闭的能力不连接或发送业务请求。
  定向 Server 的首次目录读取也只启动该 Server，修复此前首次读取会启动所有启用 Server 的问题。
  资源 URI 直接交给对应 Server，包括 file: URI，不经过宿主文件路径解释。
- 三类内容共用执行意图、原文预留、不可变对象、预览和结果事实。新增 operation 明确区分业务方法与 discovery；
  旧 P2a 记录缺失该字段时按原有 Server ID 推断。结果来源新增 capability_kind；持久结果仍使用实际模型调用名配对。
- Prompt 消息的 role 只作为外部材料中的字段保留。测试验证展开正文不进入 UserMessage 事实或 SystemPart，
  仅随 TOOL 消息回到模型。直接 Prompt 命令的独立应用事实仍属 P4，没有伪造模型调用替代它。
- 内容投影支持文本、文本嵌入资源、资源链接和协商版本允许的 JSON 值。链接不隐式读取；
  图片、音频和 blob 不进入模型预览，原文仍保存。纯不支持结果报告错误，混合结果提供可用部分并标记不完整。
  received_complete、processing_complete、preview_complete 和 schema_valid 分别记录不同事实。
- 输出 Schema 校验完整数据；成功响应缺少结构化内容也属于校验失败。isError=true 表示业务失败，
