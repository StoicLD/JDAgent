## P0 实施记录

- 已核实官方 SDK 2.3.0 提供公共 Transport 与 ClientExtension／ResultClaim 接口。
- SDK 默认 SSE 限额是单事件限制，JSON 和 stdio 需要宿主适配的接收约束；还必须验证累计解压限额。
- 本地 uv 默认缓存受沙箱权限影响，后续命令使用仓库已有忽略路径 `tmp/uv-cache`，不修改用户配置。
- 已实现 HTTP 解压后累计限制和 stdio 有界分帧；后者复用现有 Windows Job，在启动业务子进程前取得整个进程树所有权。
- SDK 通过公开 Transport／ClientExtension 接入；新版 Task 句柄显式返回宿主，不启动隐式查询或业务重试。
- 接入实验已通过，具体版本、测试边界、真实本地 HTTP／stdio 互通及剩余范围见 P0 验证。尚未把这些适配接入产品主循环。
- Windows 沙箱中创建 asyncio 自管道会阻塞；异步离线测试在获准的沙箱外执行。没有外部服务或付费模型调用。
- 类型检查固定使用 `.venv/Scripts/python.exe -m pyright --pythonpath .venv/Scripts/python.exe`；默认解释器解析不能稳定找到既有 LangChain 依赖。
- 提交前定向测试及相关命令／组合根／资源所有权回归为 `76 passed in 11.97s`，全仓 Pyright 为 0 errors，Ruff 与锁文件检查通过。
