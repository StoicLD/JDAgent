# v0.4 工具执行层设计提案

状态：`Proposed`

更新日期：2026-09-23

依据：[Q1–Q23 设计讨论](../plans/v0.4-tool-execution-design-discussion.md)。访谈中已确认的
取舍以该记录为准；本文把它们组织为可审阅的设计。具体字段、默认限额和实现阶段是 AI 提案，
尚未整体获批，不构成实现授权。Q23 已裁定跨版本工程门禁按实际依赖划分。

## 1. 核心结果与范围

在 Windows 上，用户对受信任本地工作区发出修改任务，Agent 能完成：

**发现文件 → 分段读取与字面搜索 → 基于读取版本精确修改 → 执行验证 → 报告实际结果。**

同时具备创建文件、查看已保存命令输出、审批与撤销 Session 允许规则、预算内修复明确失败的
能力。保留已有计算器；原无保护覆盖工具不向 v0.4 模型开放。

本版面向宿主当前用户权限，不提供操作系统沙箱。工作目录、路径检查、审批和进程清理各自有用，
但均不能据此宣称命令只能影响工作区。受信任项目内的脚本也不是只读操作。

暂缓：其他平台、MCP 接入、动态工具发现、多版本工具治理、多 Agent、长期交互进程、跨文件
事务、正则搜索、unified diff 编辑和整文件覆盖接口。MCP 的复审条件是跨系统互通需求。

不要求旧 v0.3 Session 迁移或继续执行；保留原始历史数据。v0.4 自身必须支持持久化和恢复。

## 2. 现有基础与本版必需变化

静态核对基线：`21a5aa4066dc0ea318f8949b8c0bd8cc4e62c909`，未在访谈中运行产品测试。

- 复用 Registry、通用 ToolRuntimePort、ModelPort、权限审批、Session Event 与 Context 投影。
- 增加本轮可用工具集合，并在模型描述投影和执行入口使用同一份集合；不能只隐藏描述。
- 将字符串 Handler 结果提升为类型化规范结果；模型文本、CLI 和事件从它生成。
- 扩充审批展示与 Session 命令规则，不能继续用字符串字符数代替命令和编辑内容。
- 增加文件版本、精确编辑、命令生命周期和有界输出保存的合同与实现。
- AgentLoop 可以做一次通用控制合同升级以识别停止状态与预算；以后新增工具不增加按名称
  分支，也不把路径、命令解析或进程回收放入 AgentLoop。

### v0.3 依赖与回归范围

Q23 已确认：只将影响上述共用基础或本版能力的遗留缺口作为相关实现的前置阻塞；无关 RAG
收尾独立推进。当前没有 v0.4 实现或破坏性回归的运行证据，下表识别验证范围，不宣称已有故障。

| 共用路径 | 本版变化可能触及的合同 | 必须保持或明确更新的行为 |
| --- | --- | --- |
| ContextBuilder / ModelPort | 字符串工具结果改为结构化投影、描述集合过滤 | 工具调用与结果关联、上下文硬限制、RAG 证据与引用投影；受限修复请求不得重新开放工具 |
| Session 编解码与恢复 | 新结果、命令许可、停止状态与日志引用 | 同一 v0.4 Session 可保存恢复；未闭合副作用不重放；旧格式按 Q21 明确处置 |
| AgentLoop / Runtime | 可用性门禁、取消清理、未知结果停止、预算 | 已确定失败可有限继续；未知结果/主动取消停止；不影响普通问答和既有 RAG 流程控制 |
| Composition / CLI | 默认工具从三种扩大，替换无保护写入 | 知识管理 CLI 仍不注册为模型工具；无 Binding 的普通对话仍不依赖 Milvus |

例如 `tests/test_knowledge_cli.py` 的现有测试同时断言“知识管理命令不是模型工具”和“工具集合
恰好为三个旧工具”。工具集合变化后应更新后者，保留前者；这种预期调整不同于破坏知识管理
功能。测试是否通过需要实测，当前只读过代码。

实现前固定已有失败清单与 revision，实施后比较失败身份、原因和行为。RAG Recall 未达标及
Milvus Live 未验证不单独阻塞不依赖它们的工具工作；一旦发现真实依赖或新回归，处理受影响
范围，不能据 Q23 跳过全部 RAG 测试。v0.3 既有工程状态保持原记录。

## 3. 模块 Interface 与状态所有权

以下是职责分配，不要求逐行对应新包或新 Port；先扩展已有模块，只在真实变化点设置 seam。

| Module | 调用方需要知道的 Interface | 拥有的事实与复杂度 |
| --- | --- | --- |
| ToolRegistry | 注册定义、按标识查找、列举描述；重复标识失败 | 已接入工具的定义；不决定具体调用是否获准 |
| 本轮能力选择 | 从宿主配置冻结 Analyze / Edit / Execute 及可用集合 | 本轮可用工具；默认 Execute，模型不能自行升级 |
| ToolRuntime | 执行调用与宿主上下文，返回规范结果 | 校验、可用性、审批、事件顺序、统一限额与停止判定 |
| Permission / Approval | 判断调用；询问一次允许或 Session 规则；撤销规则 | DENY 上限、规则匹配和用户许可；规则的持久事实仍归 Session |
| 文件工具 Module | 发现、读取、搜索、创建、精确编辑 | 路径约束、读取版本、匹配、提交及文件失败事实 |
| 命令执行 Module | 执行程序和参数，返回有界输出与进程结果 | Windows 启动、执行环境、进程生命周期、取消和清理 |
| 输出日志 Module | 按 Session 和日志 ID 保存、分段读取、清理 | 命令输出字节及容量；ID 不授予跨 Session 或任意路径读取权限 |
| Session / Context / Presenter | 保存规范事件；投影模型消息及用户显示 | 事件是调用和许可的持久事实；日志存输出正文，投影不是第二事实源 |

Core 不依赖具体 Provider SDK 或 Windows 进程细节。Provider Adapter 只处理该模型的工具
描述、参数及结果消息格式，不承担权限判断。纯函数测试与真实 Windows Adapter 共同验证
同一 Interface，不为未来平台预先搭建框架。

## 4. 注册、可用与许可

工具定义建议包含 `name`、用途与限制描述、`input_schema`、结果数据 Schema、能力类别、
风险类别、Handler，以及确有需要的调用准备逻辑。风险类别扩展为能明确表示命令执行，不能
因为程序名看似是测试工具就当作只读调用。

描述必须说清适用场景、参数单位、前提、结果含义和重要失败；例如精确编辑需要读取版本，
搜索忽略不等于拒绝访问，命令非零退出不等于启动失败。所有参数都有类型与大小上限。

执行顺序建议：查找注册项 → 检查本轮可用性 → 参数校验 → 解析路径/程序并准备审批信息 →
检查 DENY 与 Session 规则 → 必要时审批 → 重新验证会变化的前提 → 记录执行开始 → Handler →
校验及保存规范结果 → 投影或停止。

- 不存在、不可用、参数错误和拒绝审批都不得调用 Handler。
- 宿主设置 Session、Turn、工作区、执行环境与限额；这些不是模型可伪造的参数。
- 审批等待期间不持有长期文件写锁；批准后前提改变时返回冲突，不能写入另一份内容。
- 持久记录失败时，不再开始新的副作用调用。已执行但结果记录失败属于需要人工判断的状态。
- 同一调用 ID 的重复请求不得成为重复副作用执行的理由；未完成调用不能在恢复时自动重放。

默认能力映射：Analyze 含计算器、发现、读取、搜索、读取本 Session 输出；Edit 再含创建与
精确编辑；Execute 再含命令。能力范围本轮固定，宿主改变范围从下一轮生效。

文件许可建议沿用既有默认：纯计算和只读调用可允许，创建与编辑默认 ASK，用户/项目 DENY
始终优先。文件 Session 规则仍绑定具体工具与文件/目录范围，不因选择 Edit 或 Execute 自动
产生。创建审批展示目标与待写内容，编辑审批展示读取版本及具体差异；有界预览可展开查看，
不能把未展示的内容默认为已审阅。普通 Trace 保持结构化元数据合同，不加入参数或内容正文。

## 5. 工具参数与专属结果提案

工具名称和字段名为建议标识；实现前的详细 Schema 必须与本表同义，不暗中增加能力。

| 工具 | 核心输入 | 专属结果 |
| --- | --- | --- |
| `find_files` | 相对目录、路径模式、是否包含被忽略文件、数量上限 | 相对路径列表、扫描范围与截断说明 |
| `read_file` | 路径、起始行、行数 | 原文片段、行号、完整文件读取版本、编码、下一读取位置 |
| `search_text` | 字面查询、相对目录/路径模式、是否包含被忽略文件、上下文行数、结果上限 | 路径、行号、匹配及上下文、跳过/失败统计、截断说明 |
| `create_file` | 路径、内容 | 新文件版本、写入字节数；已存在时无覆盖 |
| `edit_file` | 路径、读取版本、`[{old_text,new_text}]` | 修改前后版本、替换数、有界变更摘要 |
| `run_command` | 程序、参数数组、工作目录、可选超时 | 实际程序与工作目录、退出码、结束原因、清理状态、输出日志引用 |
| `read_command_output` | 本 Session 日志 ID、流、位置、长度 | 已保存输出片段、下一位置、保存范围与丢失说明 |

首版文件工具建议仅处理 UTF-8 文本，可读取 BOM 并在编辑时保留；不猜测其他编码，拒绝已识别
的二进制文件。不改写未涉及内容的换行字节；CRLF 与 LF 的处理必须有测试。创建父目录须已
存在，暂不引入目录管理工具。上述文本与目录约定属于待评审默认项。

发现与搜索默认遵循 `.gitignore` 并跳过 `.git`、依赖和构建产物。扩大搜索是显式参数，结果
显示实际范围；直接已知路径读取仍由路径和权限合同控制。无匹配、文件无法读取和扫描被截断
必须可区分。v0.4 不承诺整个目录树的快照一致性，搜索结果不是精确修改凭据。

## 6. 文件路径、版本与提交

文件工具仅访问工作区内可证明的目标；验证真实路径与既有祖先，不能用字符串前缀比较。
工作区内绝对路径可规范化处理，工作区外路径拒绝。命令可执行文件可位于系统或虚拟环境目录，
不能把文件工具的工作区约束误套为只能运行工作区内的程序。

普通文件路径与日志 ID 分开处理。设备路径、特殊文件、链接和 Windows reparse point 的支持
策略在详细合同中列明；初始建议不遍历链接目录，不修改链接目标，对不能证明目标身份和位置
的访问拒绝处理。符号链接、硬链接和目录联接不能仅靠正常文件测试推定正确。

读取版本建议以完整原始字节摘要表示，和规范目标绑定；分段读取也返回同一完整内容版本。
受单文件体积上限约束，不能为“分段”而无限扫描大文件。版本是修改前提，不是授权凭据。

编辑先检查完整版本，再将所有 `old_text` 在原始内容上定位；每项必须非空且唯一匹配，区间
不能重叠，全部通过才生成新内容。全部替换基于同一原文，不以顺序替换后的内容匹配下一项。
任一前提失败均不修改原文件；创建若遇到同名目标则失败，包括审批期间新增的文件。

**目标保证与待验证机制分开：**本版要求无匹配、歧义、版本冲突时零写入，成功时完整提交一个
编辑批次；不允许报告成功后留下半个批次。仅“先算 hash，再写文件”不足以证明不存在并发
窗口，仅更名提交也不证明不会覆盖检查之后的外部修改。实现前必须用 Windows 实验确定锁、
目标身份、暂存与替换的组合，并明确支持的文件系统条件。机制无法满足承诺时阻塞该能力，
不能默默退化为无保护覆盖或宣称能抵御任意宿主进程竞争。

取消和崩溃要区分未提交、已提交与无法判断；不承诺跨文件回滚或断电持久性。可判定的结果写入
事件，无法判定时保留已知版本/目标和停止原因；恢复不得盲目重试。

## 7. 命令审批、运行与输出

直接启动解析后的程序和参数数组；模型不提供 Shell 字符串或环境变量覆盖。初始建议支持
明确的可执行程序，脚本通过显式解释器及参数运行；不对脚本文件暗中添加 Shell 解释。
命令的 stdin 关闭，不提供终端交互和后台进程句柄。

工作目录建议限制为工作区内已存在且通过路径检查的目录，缺省使用工作区根目录；这是启动
位置约束，不能据此推断程序运行后无法访问外部路径。程序位置与工作目录分开解析。

宿主在调用准备时固定实际程序、工作目录和执行环境；审批显示它们及完整参数边界。参数多到
无法完整展示时提供展开查看或拒绝，不能仅展示字符数就取得宽泛授权。

命令默认 ASK。用户可选择仅本次允许，或授予“固定实际程序 + 参数数组前缀 + 工作目录 +
宿主执行环境标识”的 Session 规则；前缀由用户看见并确认，不由模型按相似程度猜测。
Session 规则可以撤销，恢复同一 v0.4 Session 时有效，但不能覆盖 DENY 或本轮能力范围。
环境标识不能包含可恢复的秘密正文；规则不宣称程序或项目脚本内容永不变化。

进程管理必须覆盖根进程及其后代：正常结束、非零退出、超时、主动取消、启动失败、输出读取
失败与进程清理失败。启动前不能建立所需管理能力时不执行；不得仅因等待协程取消就宣称
进程已经终止。根进程退出而子进程仍活动时也未完成清理。

超时和取消进入有界清理阶段，记录可证实的终止状态；不支持长期进程交互。无法确认清理或
中断后的执行结果时停止本轮。用户主动取消无论清理结果如何都结束本轮。强制结束宿主时不能
依赖 Python finally 必然执行；启动、清理与恢复场景必须有真实 Windows 证据。

模型只收到有界 stdout/stderr 预览，正文保存到本机 Session 关联日志，以日志 ID 读取。
日志保留到用户主动清理；不因容量紧张静默删除旧日志。总额度已无可保存空间时，建议在启动
新命令前返回容量错误；运行中达到预留/单份上限则继续排空输出并显式记录未保存部分，不能
因为不再保存而阻塞进程。容量约束作用于原始字节，解码方式及替代字符情况另行报告。

清理是用户或宿主管理入口，不由模型自动删除历史输出；清理后事件仍保留调用和日志曾存在的
事实，后续读取返回已清理状态。日志落盘失败、Session 写入失败与达到预期容量上限须区分。

## 8. 统一结果与停止合同提案

工具结果是可序列化为 JSON 的领域数据，不规定为 JSON-RPC 2.0。Provider Adapter 按目标
API 包装工具消息；不得反过来让 Core 依赖某个 Provider 的响应字段。

| 字段组 | 建议内容与意义 |
| --- | --- |
| 身份 | `call_id`、`tool_name`、`duration_ms` |
| 结果 | `status`：success / error / cancelled / uncertain；稳定 `error_code` 与可解释信息 |
| 执行事实 | 是否开始、是否完成；命令另带退出码、结束原因、清理状态 |
| 修改事实 | 未执行、已提交及版本、未知；任意命令对宿主的全部影响不作穷举证明 |
| 数据 | 经过工具专属 Schema 校验的 `data`；文件结果与命令结果各有明确形状 |
| 输出 | 有界预览、日志引用、模型预览截断与持久日志丢失两个独立标识 |
| 控制 | Runtime 生成 continue / stop_turn 及原因；Handler 不能自行绕过停止规则 |

非零退出是已经观测到的命令结果，退出码必须原样报告；它不同于程序无法启动。进程正常结束
并不证明没有副作用。这里的“副作用不确定”针对中断、提交或清理的完成状态无法判定，不能
把任意命令未被全面审计的宿主影响都误归为需要停止的同一种状态。

| 情形 | 是否执行/修改 | 本轮处置 |
| --- | --- | --- |
| 未注册、不可用、参数错误、DENY、拒绝审批 | 不执行 | 可报告原因；不得原样反复询问审批 |
| 未找到、无匹配、读取版本冲突、目标已存在 | 不提交修改 | 可重新发现/读取并重新决定，仍受预算与许可约束 |
| 验证明确非零退出，进程已完成清理 | 保留实际执行结果，不假设无副作用 | 允许预算内修复与再次验证 |
| 只读操作超时且已确认结束 | 没有写入提交 | 返回明确失败，继续仍受调用预算约束 |
| 写入/命令中断、提交结果或清理无法确认 | 保存已知事实和未知项 | 停止本轮，不再调用模型或工具 |
| 用户取消 | 先完成有界清理并保存可得事实 | 停止本轮 |
| 预算耗尽 | 不开始下一个超预算操作 | 宿主报告已完成、未完成和未验证项，不伪造成功 |

默认不在 ToolRuntime 中自动重试副作用调用。Agent 在得到明确失败后作出的新调用，与底层
偷偷重试同一调用是不同的行为。Session 恢复发现未闭合的副作用调用时交还用户判断。

## 9. 默认限额建议（尚未批准）

限额由宿主管理；模型只可在上限内请求更小值。以下是初始实验值，需在固定 Eval 中检验，
不能把它们写成用户已经选定的参数。

| 项目 | 初始建议 |
| --- | --- |
| 文本文件处理上限 | 单文件 2 MiB；超限明确拒绝，不部分执行编辑 |
| 单次读取/搜索返回 | 最多 200 行 / 100 个匹配，并受 32 KiB 字节上限约束 |
| 单次创建/编辑请求内容 | 512 KiB；输入与生成后的文件均另受体积上限约束 |
| 发现/搜索工作量 | 最多扫描 10,000 项、10 秒；提前停止必须报告范围不完整 |
| 命令耗时 | 默认 120 秒，宿主上限 600 秒；清理另给最多 5 秒 |
| 模型命令输出预览 | stdout 与 stderr 合计最多 16 KiB，保留流标识 |
| 持久日志容量 | 单调用 10 MiB；每工作区全部 Session 合计 100 MiB |
| 单轮调用预算 | 建议模型 16 次、工具 32 次；现有代码默认分别为 8 与 16 |
| 验证失败修复预算 | 一轮最多两轮修复后再验证，并同时受总调用预算约束 |

“两轮修复”不是 Handler 根据代码改动猜测的值。建议用宿主的失败恢复计数：一次命令明确非零
退出后，接下来的修改及再次命令执行占一个恢复轮次；再次非零再开启下一次，达到上限停止。
这种保守规则可能把探测命令非零也计入预算，必须在 Eval 中覆盖。若需要更细的验证任务标识，
应先修订合同，不能依靠模型自报无限豁免。输出预算仍受现有总上下文硬限制约束。

## 10. 最小 Eval 与验收主线

固定一个小型本地项目：包含待定位函数、跨文件同名文本、UTF-8 中文、CRLF 文件、被忽略产物、
一个可确定失败再通过的验证入口，以及生成大输出/等待/启动子进程的测试夹具。
实现前冻结夹具与预期 diff，不在本次设计访谈中运行它。

| 编号 | 场景 | 必须观察的证据 |
| --- | --- | --- |
| E01 | 未新增能力的现有基线 | 实际可调用工具与未完成步骤；已有代码缺能力的判断不冒充运行分数 |
| E02 | 发现、读搜、同文件多处修改、验证通过 | 预期文件字节、读取版本、调用顺序、进程退出码、最终报告全部对应 |
| E03 | 验证失败后修复再通过 | 第一轮真实失败证据、有限修复计数、第二次验证结果，无虚报首次通过 |
| E04 | 未注册/不可用/非法参数/拒绝/DENY | Handler 未启动，目录与进程状态无对应副作用 |
| E05 | 同名创建、歧义/重叠/缺失匹配、版本变化 | 原文件字节不变；失败原因可区分 |
| E06 | 审批期间变化、提交临界区竞争与中断 | 不覆盖已检测的新内容；提交状态正确，未知则停止，不虚报原子保证 |
| E07 | 路径逃逸、链接、目录联接及特殊路径 | 不访问不支持或越界目标；拒绝原因明确 |
| E08 | 命令前缀规则与恢复 | 尾参可变；程序/cwd/环境变化失配；撤销、DENY、新 Session 均正确 |
| E09 | 大输出、容量耗尽、清理后再读取 | 模型与保存上限独立，未保存内容有标记，命令不因管道未排空而卡死 |
| E10 | 超时、Ctrl+C、子进程存活、清理失败 | 实际进程状态及有界结束时间；不确定后无后续模型或工具调用 |
| E11 | Session/日志写入失败与宿主异常结束 | 未记录的副作用不自动重放；恢复能指出不确定性 |
| E12 | 注册一个测试工具 | 通过相同 Runtime 调用与结果投影，无 AgentLoop 工具名分支修改 |
| E13 | 真实 DeepSeek 主线 | 真实工具参数、实际 diff/验证结果与模型报告一致；模型/配置/用量可追溯 |

自动化分三层：纯合同与确定性 Fake；真实 Windows 文件和进程集成；真实 DeepSeek 主线。
Fake 不能替代 OS 清理证据，Live 不能替代故障注入。建议 Live 固定主线连续运行 3 次并保存
全部结果；门槛初案为 3 次均完成，不挑选最好的一次。网络故障与工具/模型失败分别记录，
不得静默重跑覆盖原始失败。

门禁指标：确定性关键不变量用例全部通过；越权副作用和虚报验证成功均为 0；输出、时间、
调用次数遵守限额；失败样本有可追溯原因。性能数值由上述初始值和实测共同确定，不宣称已达标。
保留基础 CLI、Session、取消、ModelPort 及共用 RAG 路径的回归；按 Q23 区分既有且无关的
RAG 失败与本版新回归，不能以旧失败清单为由降低新改动的门禁。

## 11. 分阶段计划与退出条件提案

1. **设计冻结与依赖核对**：按 Q23 核对实际依赖，形成详细 Schema、事件/恢复变化、验收夹具和实现前
   基线；验证 Windows 文件提交和进程管理的关键机制。无可验证机制不进入相关能力实现。
2. **执行合同纵向切片**：先以现有纯工具打通注册、可用性、校验、规范结果、事件与 Provider
   投影；新增测试工具无需修改 AgentLoop。schema 变更不得静默污染旧记录。
3. **文件闭环**：发现、分段读、字面搜索、创建与精确编辑；完成路径、冲突、审批及中断用例。
4. **命令闭环**：进程管理、Session 前缀规则、输出日志、超时取消与清理；完成真实 Windows
   故障实验，再接入预算内失败修复。
5. **验收与学习出口**：固定 Eval、真实 DeepSeek、基础回归、安装与相称独立评审；学习者完成
   [专属学习清单](../learning/v0.4-tools-learning-checklist.md)。工程与学习分别记状态。

本文不直接创建 GitHub Issues，不执行代码实现、commit 或发布。设计共识形成后再按已配置的
任务跟踪约定拆分任务。无需为此次常规模块扩展增加一份重复既有模型无关 ADR 的新 ADR。
