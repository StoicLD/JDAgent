## C02 执行、截止时间与取消

MCP 工具沿 ToolRuntime 的公共执行入口运行，并使用已有 `manages_timeout` 机制，由适配层管理逻辑调用期限。
内置工具的默认 10 秒等待保持原范围，不成为 MCP 的隐含期限。连接准备为 15 秒，逻辑工具等待默认为 10 分钟，
工具覆盖优先于 Server 覆盖；重试、退避和 Task 轮询共用同一逻辑期限。进度只用于展示。

必须同时处理 ToolRuntime 的异常分支和 `_settle`：后者当前可无限等待子任务结束，不能作为 MCP 的无界收尾路径。
本地取消收尾有独立的 5 秒上限，可发生于执行期限耗尽之后。适配层在该窗口内尝试取消协议操作、关闭连接及清理所拥有的进程。
到期仍未完成时，前台结束等待，相关 Server 标为不可用并保留清理责任；残留资源不能被新调用复用，也不能被静默遗弃。
具体进程终止与传输释放方法需在实现中证明；客户端返回、取消请求被接受与远端工作停止是三种不同事实。
资源收尾不构成后台业务续跑。对取消或未知结果不得发起新的业务尝试。

### 必须分开的事实

| 事实 | 含义与使用方式 |
| --- | --- |
| 是否可能已发送 | 决定能否声称未执行；依据发送前持久意图和后续证据，不能只看 READ／WRITE 风险 |
| 结果是否确认 | 区分已取得最终结果与尚无结果；没有结果不证明没有执行 |
| effect | 依据已确认的操作语义和证据描述业务副作用；不能用来代替发送或重试状态 |
| 停止要求 | 未确认的调用停止当前执行，可使用现有 `requires_stop`；不必伪造 `effect=unknown` |
| 重试资格及次数 | 宿主检查已识别的服务端超时、安全重复配置、尝试额度与剩余时间 |

已确认只读语义且无写副作用证据时，结果未确认仍可保留 `effect=none`，同时明确未完成、停止和禁止自动重放。
真正副作用未知的操作继续遵守已有恢复隔离规则。SDK 超时、传输断线或 HTTP 错误不自动等于服务端业务超时。
总共 3 次尝试为首次加最多 2 次重试；同 Turn 更换 call_id 不刷新额度。保护在执行入口生效，不依赖模型阅读错误说明。

## C03 来源、参数语义与定义快照

来源由宿主注册的能力身份确定，包括内置工具／MCP、Server ID、原始能力名及配置身份代次。
不能以模型参数或 Server 返回的 `source` 字段作为宿主判定依据。MCP 调用仍需参数 Schema 和启用范围检查，
但不进入 TurnInstructions 对 path、directory、cwd 和 args 的宿主路径扫描；MCP 专用 preflight 不调用本地路径解析器。
内置八工具的工作区限制、AGENTS.md 发现和审批保持原行为。外部资源 `file://` 也不构成读取宿主文件的授权。

一次模型请求的快照至少表达：请求身份、实际曝光的工具集合、每个工具的完整定义及摘要、Server／认证配置代次和内部路由。
这些是语义字段，具体类型名称尚未冻结。Runner 将快照关联传给 ToolRuntime，后者只执行该请求实际曝光且仍被配置允许的工具。
不能仅凭名称从“最新注册表”重新取得 Schema；失效身份不得静默重新绑定到其他账号、连接代次或工具。

定义在本批次内保持固定；搜索加载的新定义仅供下一请求使用。批次引用的定义在容量核算内保留，
空间不足时缩小或拒绝新加载，不能把正在使用的定义从计量中排除。刷新与重连只在空闲时进行。
持久记录保存核验所需的请求／定义身份和摘要，内存中的处理器绑定只服务当前执行，恢复时不据此重跑旧批次。

当前 ToolRegistry 只有构造、查询和枚举接口。R1 不把尚不存在的动态增删当作既有缺陷；新增动态加载时必须实现上述快照合同。

## C04 原文、预览、压缩与记忆

外部结果的公共表示需要区分来源、完整性、Schema 校验结果、有界预览和完整原文引用。原文持久化使用现有会话对象能力，
不能把全文塞进普通 ToolOutcome，再期望投影层自动知道哪些字段应省略。引用包含所属 Session、对象身份和完整性核验信息；
敏感远端句柄使用另一类受控引用，不复用普通原文展示入口。

| 入口 | 必须使用的内容 |
| --- | --- |
| 下一次模型请求 | 预览、来源、完整性说明与读回引用；服从 12,000 估算 token 软限和剩余窗口 |
| 压缩输入 | 同一有界投影；摘要保留外部来源，不把模板写成受保护的用户约束 |
| 历史／恢复投影 | 继续使用预览；从磁盘加载原文不能自动触发全文注入 |
| 显式分段读回 | 有界页面、来源、范围和是否读完；不会改变原对象完整性 |
| 自动长期记忆 | 把事件交给提取模型之前排除 MCP 来源及其派生候选 |

直接 Prompt 命令中用户亲自输入的语句是用户消息；Server 展开的模板正文是外部材料，另存应用事实。
模型发起的 Prompt 获取维持工具调用／结果配对；直接命令不伪造模型调用。两种入口共用外部内容投影规则。
原文、读回页面和派生摘要均携带来源；无法分离来源的混合候选不参与自动记忆提取，用户的独立原始陈述仍可参与。
显式记忆请求仍由既有独立机制判断。任何路径都不调用 MCP 到 RAG 的摄取、索引或知识检索接口。

结果配额仍为默认 100 MiB／Session，发送新业务操作之前检查并预留；既有原文不按缓存策略淘汰。
预留失败阻止新增需要保存结果的业务操作，不应使取消和必要的控制状态记录失效。元数据预留、释放与去重的数值合同仍待细化。

## C05 调用事实与 Task 恢复

事实写入仍通过 EventJournal／Session 链完成，不能在 MCP 管理器内另建一套互相竞争的完成记录。
调用身份关联原 Session、Turn、逻辑调用、工具／参数指纹、Server／认证配置代次和已用尝试次数；普通日志不保存秘密。

| 崩溃时可见的持久证据 | 恢复判断 | 允许行为 |
| --- | --- | --- |
| 确定尚未进入发送阶段 | 未执行 | 为配对补 NOT_EXECUTED，不自动继续旧 Agent 流程 |
| 已有发送意图，无最终结果／无持久句柄 | 可能已发送，结果未确认 | 说明无法保证查回；禁止自动重提，不能补成 NOT_EXECUTED |
| 已持久登记 Task 关联，无最终结果 | 任务待查明 | 按原身份显式查询、读结果或取消；不重新 tools/call |
| 已完整持久保存最终结果 | 完成事实可核验 | 读回结果；任务 completed 仍须检查业务 isError |

发送意图必须在可能发出网络请求之前持久化，失败则不发送。意图已写但实际上还未发送的崩溃窗口也保守归为“可能已发送”，
不能承诺跨进程恰好一次。工具执行开始事件本身不证明请求已经到达 Server。
收到 Task 句柄后先持久登记再继续轮询；若在收到与登记之间崩溃，只能按无持久句柄处理，不伪造可恢复保证。

`classify_logical_recovery` 与 `close_pending_calls` 必须联合识别 MCP 发送证据，不能仅因风险为 READ 就补“未执行”。
补全旧 Turn 的协议配对与记录远端业务结束分别处理：结束本地等待不会把仍待查明的 Task 写成 completed／cancelled。
后续 Task 查询产生关联到原调用的管理事实，不覆盖旧结果，也不重复写同一个模型 call_id 的终结结果。

只有 MCP 结果未确认时，原 Session 可以保留任务管理入口，不因这个事实强制新建恢复 Session，也不自动恢复旧 Agent 流程。
若同一历史另有本地写副作用未知，普通 Agent 恢复继续按现有规则隔离；任务管理显式选择原 Session 及受控引用，
在工作区、Server 和认证身份核验后查询，不借此开放对原会话的任意续写或跨账号查回。
所有查询、取消及结果保存仍串行进入应用用例；未实现并行 Agent、后台轮询或图状态恢复。

用户的新明确请求与自动重放分别判断，但恢复流程和模型自行换 call_id 不能绕过已有禁止重放状态。
已取得句柄后只允许重试符合条件的同任务查询；正常轮询不消耗“重新执行业务”的次数，仍受总等待预算限制。
身份不匹配、Task 过期、Server 遗失状态或 stdio 重启后句柄失效均明确报告，不重新提交替代工作。

## C06 会话编码与兼容

当前解析器只接受 schema 4，SessionCatalog 遇到单个不可恢复会话会中断整个列表。R1 要求按会话隔离失败：
可解析会话正常列出；不支持版本或损坏会话显示 ID 和明确状态，不能伪造其业务摘要、更新时间或完成状态。
不支持与损坏原因应尽可能区分。选择不可读会话时拒绝继续 Agent 执行，其他会话仍可选择。

新的序列化与读取能力必须一起交付。本次兼容基准是当前可读的 schema 4 会话，不扩大对更早、已有独立隔离规则的历史格式的支持承诺。
这些旧会话保持可读取，写入新事件前先确定兼容策略；具体是保持版本还是升级版本尚未冻结。
若升级，新读取器的旧格式路径与写入限制必须写入工程方案，并验证未授权迁移不会发生。
老程序不能读新格式不等于新版本兼容性必然失败，但不能让目录因单条记录不可读而整体失效。
不得静默跳过未知执行事件并恢复业务，因为该事件可能包含发送、Task 或结果证据。

## C07 CLI 与凭据

| 状态 | 允许 | 不允许／处理方式 |
| --- | --- | --- |
| 空闲 | 能力发现、刷新／重连、Prompt 触发、显式远端 Task 查询／结果／取消及既有命令 | 按各自权限和预算处理 |
| 前台 Turn 或工具运行中 | 只读 /context-window、MCP 本地状态、取消；退出先取消并收尾 | /compact、刷新、配置切换、远端管理操作提示空闲后重发，不在当前 Turn 排队 |
| 等待审批 | 审批回答与取消；只读状态保持可用 | 不暂停整个命令消费；状态输出重绘提示或延迟显示，不能当作审批答案 |

终端继续使用一个读取入口，将审批回答与斜杠命令分流。状态查看读取本地快照，不因查看而隐式连接 Server 或获取新状态。
取消必须在审批和长等待期间可达。Headless 不启动交互登录或未知输入等待；错误只报告必要引用标识，不含凭据值。
本次调整 /compact 的忙时行为是对 R0“运行中只查看和取消”的落实，旧批次边界排队逻辑不再用于当前 Turn 的这条命令。

用户配置只保存凭据引用。最小实现解析环境变量引用，将 Bearer 本体或明确指定的环境值直接交给对应连接。
没有引用、引用不存在或为空时返回可理解的配置错误，不打印完整配置／环境／请求头。
身份缓存键使用非秘密标识及连接代次；凭据变化后通过空闲时显式重连使旧连接与目录失效。
v0.7 不依赖凭据文件、系统秘密存储、OAuth 或多账号热切换；这些后端以后可扩展，但不能改成用户 TOML 内嵌 Token。

## C08 接收硬限与 SDK 验证

SDK 负责协议处理，适配层负责传输接入、预算与资源生命周期，优先复用 SDK 传输实现。
允许通过 SDK 的公开接入点包装字节流／传输；包装只负责计量、拒绝和清理，不复制 JSON-RPC 协议栈。
1 MiB 约束发生在整条响应解析前；HTTP 对解压后、属于该 RPC 响应的数据累计，stdio 对消息计量。
包装与解析器之间不得先有一个无界的整消息缓冲。超限拒绝整条消息并按需关闭对应连接，不把截断 JSON 当正常输入。
既有的进度、轮询频率、总期限和目录分页限额仍须生效，不能借 SSE 事件边界反复重置同一响应的计量。

F08 当前为 `deferred`：尚无锁版实验结果，不能声明已证实 SDK 支持或不支持该包装。
实施前的最小实验必须固定 SDK／依赖版本并留下以下证据：

1. 对 stdio 与 HTTP 分别注明使用的公开接入点、完整消息解析的位置，以及限额在何处执行。
2. 用受控服务验证小于、等于、超过 1 MiB 的响应，覆盖分块、压缩后的膨胀、多段 SSE 和 stdio 不完整消息。
3. 观察接收与解析边界：超过上限的数据没有作为完整成功结果交给协议层；缓冲增长受已声明的分块／限额约束。
4. 验证超限后错误、连接清理与其他 Server 可用性；取消不遗留未归属的接收任务。
5. 在同一固定依赖上另验新版 Tasks 扩展的公开接入，不以模拟 SDK 返回值代替协议互通。

如果任一传输无法满足硬限，阻止宣称其 AC-11 通过，提供实际限制及替代方案，再修订设计。
不得自动放宽到解析后检查、私有 API 猴子补丁或重新实现完整协议栈。实验不需要付费模型或真实业务数据；本轮文档修订未执行该实验。

## C09 ADR-0008 复审回应

远程执行触发了 ADR-0008 的复审条件。v0.7 所需恢复是保存远端任务关联并允许显式查询，
不要求在某个图节点恢复 Agent、不要求后台自动续跑，也不要求跨进程审批。因此继续采用会话事实链和应用任务管理入口，
不启用持久图 checkpointer／interrupt，不让图节点重试外部操作。只读配置范围与现有审批继续由宿主负责。
这项结论仅适用于 v0.7；若未来批准并行编排、跨进程续跑或持久审批，应再次复审，不沿用本次结论作默认许可。
