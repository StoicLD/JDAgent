## 已证明的接入方式

固定运行环境为 Windows、Python 3.11.15；依赖见 `pyproject.toml` 与 `uv.lock`：
MCP／mcp-types 2.3.0、httpx2 2.16.0、AnyIO 4.14.2、Pydantic 2.14.2。
官方 SDK 负责协商、JSON-RPC、消息类型和方法分派；适配不使用私有猴子补丁，不复制协议栈。

| 范围 | 公开接入点和接收边界 | 证据 |
| --- | --- | --- |
| HTTP | `streamable_http_client(http_client=...)` 接收由宿主持有的 httpx2 Client；`AsyncBaseTransport` 包装原始流，单个 HTTP 响应累计解压后字节，再交 SDK 解析 | [HTTP 包装](../../src/jdagent/adapters/mcp_transport.py)、[边界测试](../../tests/test_v07_mcp_transport.py) |
| stdio | SDK `Transport` 接受标准消息流；宿主在读取 stdout 时按字节分帧，单消息有界后调用 SDK 的 `jsonrpc_message_adapter` | [stdio 适配](../../src/jdagent/adapters/mcp_stdio.py)、[真实进程测试](../../tests/test_v07_mcp_stdio.py) |
| Tasks | `ClientExtension`／`ResultClaim` 注册现代 task 结果；`session.call_tool(allow_claimed=True)` 交还句柄，`send_request` 发送显式 get／cancel | [扩展适配](../../src/jdagent/adapters/mcp_tasks.py)、[Tasks 测试](../../tests/test_v07_mcp_tasks.py) |
| 核心协商 | 同一 SDK 分别与 2026-07-28、2025-11-25 的独立 stdlib 服务通信；现代 Tasks 不向旧连接提供查询能力 | [stdio peer](../../tests/fixtures/mcp_stdio_server.py)、[HTTP socket peer](../../tests/test_v07_mcp_http.py) |

HTTP 包装支持 identity、gzip 和 zlib deflate，拒绝其他编码。解压使用剩余预算加一个字节的输出上限；
上限触发后不消费后续分块，也不把截断 JSON 交给 SDK。SSE 的注释、事件与消息均计入同一请求响应的累计预算，
不会因事件边界清零。受控 8 MiB 输入在第 17 个 64 KiB 分块触发默认 1 MiB 限额，余下分块不再读取。

stdio 每次最多读 64 KiB，并按消息剩余预算进一步缩小读取。接收缓冲最多为限额加一个判定字节，
解析前只复制限额内的完整消息；多条消息分别计量。超限未结束消息关闭消息流，等待请求收到连接失败，不能被当成完成结果。
stderr 只被有界排空，不进入模型、事件或普通输出。

Windows stdio 复用现有 `WindowsCommand` 的 Job 所有权，新增保留 stdin 的模式。可信 bootstrap 逐字节读取启动描述，
防止提前消费后续协议数据；进入 Job 后才启动 Server。正常关闭和调用方取消均经过真实 Server＋子进程退出检查。
现有命令执行的默认 stdin 行为保留。POSIX 分支使用独立进程组；本次 Windows 环境没有运行 POSIX 分支。

## Tasks 和 SDK 错误的边界

Tasks 测试证明：收到句柄时尚未轮询；get／cancel 请求携带原 taskId，HTTP 包含 `Mcp-Name` 与 `Mcp-Method`；
completed 的 `isError=true` 仍保留业务错误；cancel 只是确认收到请求，后续 get 可以仍为 working。
没有隐式第二次 tools/call，没有使用旧实验 Tasks。宿主持久登记、逻辑期限、状态恢复尚属 P3。

SDK 的 HTTP JSON 接收错误可能经 TaskGroup 形成异常组，SSE 错误通常成为 MCPError。
连接所有者必须统一收束这两种失败，不能只在单次 call 内捕获 MCPError。P0 直接在 SDK 连接边界验证两种形式均拒绝超限结果并释放响应流；
最终应用错误转换将在 P1 的连接所有者中实现。SDK 高层 call_tool 还可能自动重新列目录或处理 header mismatch；
产品适配必须使用宿主管理的显式会话操作，避免这些动作绕过快照与重试合同。

## 验证与复现

命令从产品仓库运行，不需要外部网络、凭据或付费模型：

```text
.venv/Scripts/python.exe -m pytest tests/test_v07_mcp_transport.py tests/test_v07_mcp_stdio.py tests/test_v07_mcp_tasks.py tests/test_v07_mcp_http.py tests/test_v04_commands.py tests/test_v06_composition.py tests/test_v06_owned_resources.py -q
.venv/Scripts/python.exe -m pyright --pythonpath .venv/Scripts/python.exe
uv --cache-dir tmp/uv-cache lock --check --offline
```

定向验证覆盖：大小在 1 MiB 以下／等于／超过、分块与提前停止读取、gzip／deflate 膨胀、压缩损坏和截断、
多个 SSE 段的累计预算、stdio 不完整大消息、单 Server 失败隔离、进程树关闭／取消、两种核心协商、Tasks 两种传输。
HTTP peer 为本机回环套接字的独立 stdlib 实现，stdio peer 为独立子进程；部分更细的分块故障使用 HTTP 边界 MockTransport，SDK 本身未被模拟。

上述定向测试为 `76 passed in 11.97s`。全仓显式解释器 Pyright 为 0 errors；
变更 Python 文件的 Ruff format／check 通过；锁文件一致。
默认 Pyright 曾报告既有 LangChain 导入缺失，固定项目解释器后消失；没有据此删除类型检查或修改既有适配器。
Windows 沙箱的 asyncio socket-pair 限制使异步测试需要获准在沙箱外运行，测试仍为本地离线测试。
完整测试套件与实现后 code-review 留到 P5；本记录不是完整验收声明。
