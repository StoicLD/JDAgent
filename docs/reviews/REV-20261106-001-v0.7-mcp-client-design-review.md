## 总体判断

产品边界清楚。官方 SDK 留在适配层、两类 Runner 共用接入链、只读启用、MCP 与 RAG 分开、
Tasks 在当前调用内顺序等待、中断后只查询不重提，这些选择和现有 Runtime 的职责划分一致。
规格也明确把 SDK 锁版、事件合同、容量校准和实施计划留在工程细化，没有把它们写成已批准数字。

问题在于 D02 要求复用的几条现有路径，会在接入后直接改写已经确认的行为。工具外层超时、
同名字段的目录发现、中断恢复和全文投影都没有在规格中指定改哪一段合同。Further Notes 列出了
截止时间、事件 Schema 和配额，但没有点名这些现有入口。按现有代码实现，10 分钟等待、
“参数同名不触发本地规则”、中断后查回任务，以及 12,000 token 预览都会在第一条相关路径上失效。
共 4 项 High、4 项 Medium、1 项 Low。

## 需要实验验证的疑点

- 锁定官方 SDK 后，stdio 与 Streamable HTTP 能否在应用看到完整消息之前统计解压后字节（F08）。
- 新版 Tasks 的公开扩展在该 SDK 版本中实际能注册哪些请求；规格已声明不能把安装 SDK 当成 Tasks 可用。
- 模型侧工具名的长度和字符限制，确认 Server ID 与原始工具名的可逆编码何时必须改为局部隔离。
- DeepSeek 对同一次请求中动态增减工具定义的接受情况，以及前缀缓存是否因此失效。

## 剩余风险

手工启用并标成 READ 的 MCP 工具会沿现有权限策略直接 ALLOW，调用时不再审批。
规格把自动风险判断和参数级权限放在版本范围之外，因此启用名单本身就是权限边界；
名单放宽后，远程写操作不会再经过现有写入审批。

ADR-0008 把远程执行列为图持久化和审批的复审条件。规格已经选择不启用持久图 checkpointer，
这个选择应在实施设计里作为对该复审条件的回答保留，避免实现时重新引入图恢复。

## 批准条件判断

规格中的产品范围可以保持已确认状态。它还不能作为实现合同。进入实现前，工程细化需要写明
F01–F04 对 ToolRuntime、目录发现、Session 恢复、投影和记忆抽取的具体改动，以及 F05 的定义快照。
F06–F08 应在 CLI 与事件合同中一起定下。F09 可随凭据配置一并处理。
