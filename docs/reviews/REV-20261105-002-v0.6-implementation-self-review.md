## F01：完成计时与首次目标前的冻结判据缺少内容校验

- **finding_id**：`REV-20261105-002-F01`；**severity**：`medium`。
- **location**：[实验控制器](../../tests/v06_comparison.py)的 `_completed`、`freeze_criteria` 与 `_criteria`。
- **claim**：原始 result.json 的指纹受核验，但 completion.json 自身的 metrics 没有校验；判据文件
  在首个目标 claim 写入前也没有独立内容校验。人工误改记录可能改变后续比较所依据的数据。
- **evidence**：在固定 revision 上完成 B1 后，把 completion.json 的 total_ms 改为 0，再运行 B2。
  新回归用例预期 ValueError，却进入被设置为拒绝的任务执行器，实际抛出
  `AssertionError: Edited measurement must be rejected before task execution`；失败发生在任何 B2 HTTP 前。
- **impact**：实验可能沿用被改写的基线测量或冻结判据，不能据此支持性能判断或默认切换。
  这是测试／实验基础设施问题，未改变产品运行时数据；本次没有真实消费。
- **disposition**：`accepted`。
- **resolution**：为 completion.json 和 criteria.json 保存规范化 JSON 内容的 SHA-256，并在下一次
  准入前验证；首个目标前后均拒绝判据修改。回归同时覆盖空值、负数、布尔和 NaN 上限。保留原始
  结果、失败与账本，不通过删除重建解决问题。修复提交标题为
  `fix: seal comparison measurements and frozen criteria`，具体 revision 见分段提交记录。
- **validation**：[控制器回归](../../tests/test_v06_comparison_controller.py)修复前 1 failed，修复后
  15 passed，9.87 秒，见[证据](evidence/v0.6-20261105/implementation-self-review/README.md)。内容指纹
  用于发现记录变化，不是对能同时改写文件和指纹的本机攻击者作防篡改认证。
