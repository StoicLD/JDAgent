## Standards 轴

初轮结论为 fail，包含四项 High：

1. JSONL append 与恢复没有共享同一排他锁，存在恢复替换覆盖并发 append 的风险。
2. 物理恢复备份使用 `.jsonl` 后缀，会被 Session discovery 误认为可恢复 Session。
3. 交互层只取消父任务，缺少可测试的 active turn/cancellation seam；审批仍可能占用阻塞输入。
4. `ResolvedConfiguration` 与 `RuntimeConfiguration` 重复声明和校验同一组 host 配置，违反配置
   单一事实原则。

处置：

- JSONL append/recovery 现在通过同一个按路径锁串行化；确定性并发测试固定不丢事件合同。
- 备份改为 `.bak`，Session discovery 只接受合法 Session ID 的 `*.jsonl`。
- Interactive Application 持有 active task 与 `CancellationToken`，公开应用级取消 seam；审批改为
  Prompt Toolkit 异步输入，Headless 使用明确拒绝策略。
- 删除 `RuntimeConfiguration`；Composition Root 直接消费唯一的 `ResolvedConfiguration`。
  `RuntimeOptions` 只保留 model/tool call 上限与 provider options，不重复 host 配置。

复核结论：四项 High 全部关闭，0 Blocker、0 High；未发现新的硬违规。

## Spec 轴

初轮结论包含三项 High 和一项 Medium：

1. `.jsonl` 恢复备份会污染 Session Catalog。
2. 用户/项目 `write_permission` 在比较权限上限前没有统一去除首尾空白，可能绕过项目不得放宽
   用户 `DENY` 的合同。
3. `waiting_approval/running_tool` 没有完整的事件驱动状态与持续可见底栏。
4. 包版本测试仍断言开发版本，与最终 `0.2.0` 合同不一致。

处置：

- 备份 discovery 问题按 Standards 轴相同修复并增加回归测试。
- 权限上限比较先规范化字符串；空白变体测试固定 `DENY` 不可被项目放宽。
- `PermissionRequested/ToolExecutionStarted` 等 Runtime Event 驱动交互状态。空闲与审批输入由
  Prompt Toolkit bottom toolbar 持续显示状态；生成、工具执行和取消由 Rich Live footer 接管。
- 包元数据、`--version` 和测试统一为最终 `0.2.0`。

复核结论：全部 finding 关闭，0 Blocker、0 High；定向终端/交互复核通过。

## 残余环境风险

- 自动化和 PowerShell PTY 不能代替用户真实中文 IME、legacy console、不同窗口宽度与关闭窗口
  手势的全部组合。它们保留在 Windows 人工矩阵中持续观察，但当前没有 Blocker/High 证据。
- 关闭窗口、terminate、强杀和断电不能保证 Python `finally` 执行；v0.2 不声称“退出时一定写入
  新事件”，而是依赖逐事件 fsync、物理/逻辑恢复分类和副作用不确定时的显式恢复 Session。
- Session 级允许规则是当前 Session 的持久事实：正常 `/exit` 后恢复同一 Session 继续有效；新建
  Session 不继承，规则也不能覆盖用户或项目 `DENY`。
