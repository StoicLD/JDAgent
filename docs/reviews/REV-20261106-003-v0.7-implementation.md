## Spec

评审者：`/root/v07_spec_review`。原结论：`fail`，2 项行为不符；没有已证实的范围扩张或其他独立缺项。

**F01／high：悬空本地 Schema 引用会终止整个 Turn。**
规格 D05 要求“不合法……局部隔离该工具并报告原因”。原 `mcp_service.py:769` 仅检查引用以 # 开头，
check_schema 不验证目标；指向不存在的 $defs 的定义进入模型。真实协调器调用时，ToolRuntime 仅捕获
ValidationError，native 抛出引用异常，LangGraph 返回 INTERNAL_ERROR。应在发现阶段隔离并将验证异常转成局部工具错误。

**F02／medium：单个畸形工具导致同一 Server 的全部能力丢失。**
规格 D05 要求只有无法可靠区分条目的坏响应才使目录获取失败。原 `mcp_connection.py:453` 对整个
ListToolsResult 强类型验证，单项 description:42 即失败。受控 HTTP Server 同时提供正常 read、
畸形工具及 Resources／Prompts，两版核心均得到 failed/protocol/closed 和空目录。应逐项隔离。

实际执行：固定差异检查、ListToolsResult 最小复现、两段内联受控 HTTP 实验；两版目录失败和两个 Runner
的引用失败均已观察。临时会话清理，无仓库修改；未重跑完整套件或执行付费 Live。

初审汇总：Standards 1 项、最高 low（维护性判断）；Spec 2 项、最高 high。
